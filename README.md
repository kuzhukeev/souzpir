# Союз Пир — клиентский кабинет

Первая контрольная точка подготовлена 31.10.2026: база и первые макеты. **Очередь остановлена для просмотра пользователем.** Новые задачи и дальнейшая реализация — только после его команды.

- [Экран входа](http://souzpir.local/preview/login)
- [Очередь](http://tasks.local/)
- [Приватный репозиторий](https://github.com/kuzhukeev/souzpir)

Сверху экранов доступны переключатели темы и состояния. Реализованы вход, неверные данные, блокировка, MFA, загрузка; кабинет с событиями, пустым состоянием, скелетоном и ошибкой. Есть мобильная версия, поиск, фильтры, меню и локальные демонстрационные действия. Вход пока не аутентифицирует, реальные сообщения и бизнес-действия не выполняются.

## Что установлено

Laravel 13 / PHP 8.4, React 19 / TypeScript / Inertia 3 / Tailwind 4 находятся непосредственно в `C:/OSPanel/home/souzpir.local`. Backend — `app`, frontend — `resources/js`, стили — `resources/css`; OSPanel обслуживает только `public`.

PostgreSQL 16: отдельные рабочая и тестовые базы, ограниченные роли. Основные миграции применены; создана одна организация и три демонстрационных бренда. Пользователей и паролей по умолчанию нет. Доступы, ключи и runtime находятся в игнорируемых локальных файлах.

Все 308 исходных изображений учтены в [покрытии](planning/image-coverage.json). Они служат визуальным эталоном; интерфейс, SVG-иконки, логотипы и скелетоны воспроизведены кодом. Три темы и локальный Manrope входят в проект. Отменённый выбор организаций и удаление организации не реализуются.

## Параллельная работа

[План из 81 задачи](planning/QUEUE.md) и [машинный план](planning/tasks.json). На этой точке завершены SP-C-01, SP-T-01, SP-E0-01, SP-E0-02, SP-F-01 и SP-P-01; остальные 75 задач ожидают следующей команды. Статусы и атомарное владение ведёт tasks.local.

Один чат берёт карточку через `scripts/task.py claim`, работает в своей ветке/worktree и отправляет результат в review. Интегратор проверяет, объединяет в main и ставит done по SHA. Зависимости и пересечения scope не позволяют одновременно редактировать общие файлы. Worktree сохраняются для проверки истории; новые чаты автоматически не создаются.

Перед продолжением читать [AGENTS.md](AGENTS.md), [workflow](docs/parallel-workflow.md), [решения](docs/preparation/decisions.md) и [обязательные уточнения будущих задач](docs/contracts/integration-followups.md). Остановка зафиксирована в [первом checkpoint](docs/checkpoints/first-preview.md).
