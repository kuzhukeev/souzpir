# SP-E1-06 — первая независимая часть

Подготовлен испытательный bootstrap разделения владельца PostgreSQL и runtime-роли и описан порядок отдельно проверяемого перехода существующего окружения. Это не реализация карточки команды и приглашений целиком; задача остаётся в работе у исполнителя и не передана на итоговую приёмку.

## Что проверено

- В отдельном кластере PostgreSQL 16 внутри worktree на отдельном loopback-порту созданы неповышенные разные роли миграций и runtime и база `souzpir_test_e106_roles`. Перед миграциями проверены собственный `basePath`, `inferBasePath`, `APP_ENV=testing`, действительные база/роль и отличие от preview. Администраторское соединение подтвердило worktree-local data directory.
- Роль миграций применила реальные миграции приложения, затем тестовый bootstrap назначил права runtime. Роль миграций также создала и изменила тестовую таблицу; новые таблицы и последовательности получили рабочие default privileges.
- Адресные интеграционные проверки `python -m unittest discover -s infra/database/tests -p 'test_*.py' -v`: **8 тестов успешно**. Проверены реальные Eloquent-операции приложения под runtime, SQL CRUD с реальным триггером неизменяемой опубликованной базы знаний, запрет его отключения и защитных изменений, запрет изменения `migrations`, обхода через `session_replication_role`, членства, владения и создания объектов. Ошибочные PUBLIC column grants, повышенные роли, неверная база и смешанное владение отвергаются; ошибка bootstrap откатывает транзакцию. PHP smoke отдельно отвергает сервер с неправильным data directory.
- PHP smoke запускается только с тестовым окружением и защищёнными fake mail/notifications/queue и запретом посторонних HTTP. Тестовые данные откатываются; реальные внешние отправки не выполнялись.

## Границы

Скрипт намеренно предназначен только для свежей изолированной тестовой базы и не переводит рабочую базу. Проверены конкретные пути Laravel, а не все функции кабинета; прежде чем применять разделение к существующему окружению, интегратор должен отдельно проверить права, функции, другие схемы и роли-создатели, подготовить проверенную резервную копию, скрипт перехода и откат. Default privileges относятся только к текущему создателю и схеме `public`; пересоздание `migrations` требует повторной защиты до запуска runtime.

UI, приглашения, матрица ролей, браузерные проверки и скриншоты в эту первую часть не входят и ещё не выполнены.
