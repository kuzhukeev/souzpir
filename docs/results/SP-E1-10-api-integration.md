# SP-E1-10: изолированная проверка связки API-ключей

Статус: частичная интеграционная ветка для проверки, не приёмка SP-E1-10. Основной checkout, main и рабочая БД не изменялись. Основа `cd741ece6ed7c24bef54635beb00cb276429e28c`; обычными merge включены проверочная ветка `codex/sp-e1-10-api-integration` (`9a195c5`) с API guard `f1b7d67`, затем текущая SP-E1-10 `84af480`. Конфликтов merge не было. Не включалась ветка корпоративной доставки уведомлений.

В тестовом приложении создан настоящий ключ бренда через `/integrations/api/keys`, значение получено единожды через `/integrations/api/secrets`, затем ключ использован для `/api/v1/brand` и отозван. Проверены отказ второго раскрытия, требуемая ability `read`, отсутствие права у ключа `leads`, запрет другого бренда и отказ после отзыва. API и тесты выполнялись через Laravel HTTP kernel на отдельной PostgreSQL, без внешних вызовов. Endpoint продавца `turn` и API лидов не реализованы; они не выдаются за рабочие. Текст на странице уточнён соответственно.

Добавлены две проверки реальной двухпроцессной гонки раскрытия ключа и logout с database-session и database-cache: барьер установлен в транзакции после изменения одноразовой квитанции либо после изменения записи отзыва, другой процесс действительно ждёт PostgreSQL lock. Если раскрытие уже зафиксировало квитанцию, оно заканчивается до logout; если logout первым отзывает сессию, раскрытие отклоняется. После logout повтор со старой cookie не выдаёт секрет. Это проверка срока действия **сессии раскрытия**; logout сам по себе не отзывает ранее созданный API-ключ. Полная строка ключа не печаталась и не сохранялась в отчёте.

Тестовый интеграционный bridge и worker очищены от жёсткой привязки к прежним checkout/порту. Перед доступом проверяются testing environment, фактические cwd/basePath, отдельное имя test-БД, несовпадение с preview, loopback, соответствие порта и ограниченная роль без superuser/createdb/createrole. Composer lock проверен и зависимости физически скопированы в работу при совпадающем SHA lockfile; junction vendor не использовался. Изолированный сервер PostgreSQL и временный Vite останавливаются после проверок.

Проверки:

- API guard вместе с реальным созданием и отзывом ключа: **16 тестов, 115 assertions**; отдельный bridge повторён после форматирования: **1 / 22**.
- Интеграции и конкурентные раскрытия: **44 теста, 317 assertions, 4 намеренных пропуска** тестов доставки выключенных вебхуков. Новые обе гонки logout входят в этот результат.
- Auth/session/invitation regression: **26 тестов, 258 assertions**.
- Playwright UI fixture: **32/32**, три темы и ширины 1440/1024/390, клавиатура и a11y; после изменения сообщения повторены **9/9** экранов API. Это fixture с искусственными данными, не полноценный browser E2E с рабочей БД. Проверенный пример: `.local/screenshots/e1-10/api-pyro-1440.png` в данном worktree; это не реальный ключ и не факт доставки вебхука.
- TypeScript, ESLint, production build, Pint и Composer validate прошли. Vite предупреждает о разрешении URL шрифтов во время исполнения; файлы шрифтов присутствуют в `public/fonts`.

## Блокеры и границы

- Полная задача не готова: корпоративный Telegram/email не подключены, исходящая доставка вебхуков принудительно выключена независимо от config. Нужны проверенный снимок подписок, квитанция тестовой отправки и испытания outbox, после чего отдельный разрешённый операторский этап. Четыре пропущенных теста не считаются проверкой доставки.
- Действующий guard держит транзакцию и блокировки organization/brand/token во время вызова обработчика. Только текущий read-only `/api/v1/brand` проверен в этом контуре: его обработчик выполняет чтение бренда и формирует небольшой JSON, исходящего HTTP в тесте нет. Жёсткий верхний предел длительности ожидания БД и поведения под нагрузкой не доказан. Прямое подключение будущего `turn` с внешним AI внутри такой транзакции несовместимо с `Ai/Gateway`, который запрещает сетевой вызов внутри DB-транзакции, и может удерживать отзыв ключа. До рабочих API диалогов/лидов нужен отдельный безопасный контракт admission/lease/recheck/outbox без сетевого I/O под DB-блокировками и его проверка.
- Разработческие UI-тесты используют fixture; настоящих внешних SMTP, Telegram, webhook, AI и продакшн БД не было. Генерируемые assets, локальные сессии и учётные данные не включены в Git.
