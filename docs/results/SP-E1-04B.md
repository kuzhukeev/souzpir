# SP-E1-04B — проверка доступа к модулям

Причина сбоя CI воспроизведена: тест отправлял веб-сессию на `/api/v1/`, где обязательная API-граница сбрасывает веб-аутентификацию и требует bearer-токен. Поэтому ответ 401 был корректным, а до проверки модуля запрос не доходил.

Тест использует отдельный веб-маршрут с автоматической проверкой модуля и тестовый API-маршрут с фактической цепочкой API, Sanctum, контекстом токена, правом `read` и явной проверкой модуля. Он проверяет 401 без токена и с неверным токеном, 403 при недостаточном праве, 404 для выключенного модуля и чужого бренда, 200 с контекстом выданного токена для разрешённого модуля. Проверены включение и выключение через интерфейсный серверный маршрут, повторная проверка в job-контексте и независимость состояний другого бренда и организации. Токены и данные синтетические; HTTP-запросы заглушены и запрещены наружу.

Проверки выполнены из worktree задачи на отдельном локальном PostgreSQL `souzpir_test_sp_e1_04b`:

- Исходное падение воспроизведено: ожидался 404, получен 401.
- Адресный тест после исправления: 1 тест, 25 проверок — успешно.
- `OrganizationTest.php`: 23 теста, 212 проверок — успешно.
- `pint --test tests/Feature/Shell/Organizations/OrganizationTest.php` — успешно.
- `git diff --check` — успешно.

Ограничения: маршруты проверки зарегистрированы тестом, но используют реальные middleware и хранилище. Полный набор тестов и интеграцию в main выполняет интегратор. Реальные внешние вызовы не выполнялись. Скриншоты не требуются: задача не меняет интерфейс.
