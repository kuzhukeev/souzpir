# SP-UI-04 — результат

- Списки диалогов и лидов возвращают до 50 записей и next_cursor; порядок убывания по created_at и id сохранён.
- Курсор проверяется по существующей записи текущего бренда; повреждённый или чужой отклоняется с 422.
- Проверки: 6 тестов, 58 проверок на отдельной PostgreSQL (54 записи, одинаковые даты, права, чужой бренд и некорректный курсор); Pint, генерация типов без изменений.
- UI не менялся; скриншоты не применимы.

## Техдолг
- Удаление записи-якоря между запросами делает её курсор недействительным; клиенту нужно начать список заново.

## Принято по умолчанию
- При отсутствии следующей страницы next_cursor равен null.

## Нужно от интегратора
- Подключить tests/Feature/SP-UI-04 к CI: phpunit.xml вне scope задачи.
