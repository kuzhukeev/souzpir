# SP-E3-09
- Добавлен контракт ChannelDelivery с командой и квитанцией; завершённый bot-ход передаёт сохранённое сообщение fake-адаптеру.
- Fake проверяет организацию, бренд, диалог и роль сообщения; повтор ключа возвращает квитанцию, конфликт отклоняется. suggest и manager доставку не вызывают.
- `ToolRunner` читает остатки из последнего завершённого импорта своего бренда без цен; прайс возвращает только fake-квитанцию при включённой настройке и сохранённом файле.
- Исправлено поведение неизвестных инструментов для существующего ToolRunnerTest. Для `intro_and_ask` финализатор допускает первый ход; Responder получает настроенное приветствие только канала widget.
- Защищённый первый ход теперь сохраняет отдельные стадии Responder для инструментов и замечаний Guard, повторно использует их при replay и делает не более трёх попыток; затем передаёт диалог на ручную проверку.
- Проверки: ToolRunnerTest, Delivery, FirstSellerTurnHttpTest — 10 тестов / 77 утверждений; повторно Delivery и FirstSellerTurnHttpTest — 10 тестов / 72 утверждения; отдельно тест прежней блокировки некорректного инструмента; Pint. Изолированная БД `souzpir_test_e309`.
- Ограничение: доступен только fake-канал, реальной отправки и экранов нет; скриншоты неприменимы.
## Техдолг
- Fake-дедупликация использует настроенный cache с TTL 30 дней; для реальных адаптеров нужна долговечная идемпотентность транспорта.
- В одном ответе обрабатываются до четырёх вызовов инструмента; некорректный вызов после валидного может быть воспринят как конец списка.
## Принято по умолчанию
- Fake-квитанция имеет статус `fake_sent`; содержимое сообщения в cache не сохраняется.
- После трёх отклонённых Guard ответов включается ручная проверка без новой платной попытки.
