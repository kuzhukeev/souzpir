# SP-E1-05 — карточка бренда

Дата: 31.10.2026. Ветка `codex/sp-e1-05`, база `8ed6f5f5eff6d1e8cbaaae5766b61215375958c3`.

## Реализовано

- S-2.3: основные поля бренда и алиасы, три темы, приватный растровый логотип, подпись и промо-карта с предпросмотром сайдбара/шапки, домены, модули, архивирование через существующие действия E1-04.
- `GET /brands/{brand}/settings` и формы general/theme/domains/website. Выбранный бренд кабинета отделён от редактируемого `targetBrand`; page `moduleItems` не переопределяет общие flags `modules`.
- Серверная валидация, Action, PostgreSQL storage и audit. Повторная проверка активной сессии, роли owner/admin, organization/brand grants под блокировками; аудит в одной транзакции. Чужие ID закрываются 404.
- Логотип PNG/JPEG/WebP до 2 МБ и 2048 × 2048 преобразуется в PNG без активного содержимого. Приватная выдача, rollback нового файла при ошибке, cleanup старого после commit. Путь совместим с существующим списком брендов.
- Domain proof сохраняет протокол R-S-10: `/.well-known/eyon-domain-verification.txt` или TXT `_eyon.<host>`, оба содержат plain server-issued token; состояния pending/verified/failed, время и причина проверки. Ошибка повторной проверки снимает verified; check_version не позволяет устаревшему сетевому результату перезаписать новую проверку.
- HTTP: проверка всех A/AAAA, запрет частных/служебных адресов, cURL pinning, TLS verification, отсутствие proxy/redirect/decompression, пределы ответа и connect/total timeouts. HTTP выполняется вне SQL-транзакций; проверки используют только fake DNS/HTTP.
- Проверка сохранённого сайта и отдельное предупреждение о полном запрете wildcard-робота в robots.txt; недоступность robots не превращается в измеренный успех.
- Квоты и доступность модулей берутся из существующих PlanLimits/UsageReader/ModuleEntitlements; отсутствующие значения не превращаются в выдуманные тарифы или ноль.

## Интеграционные действия и ограничения

1. Общая оболочка и список брендов вне scope. Интегратору добавить ссылку на `/brands/{id}/settings` в существующий список брендов и подключить feature shared prop `brandAppearance` (`logo_url`, `subtitle`, `promo_card`) в общий Sidebar и соответствующий shared DTO/type. Сам пресет темы уже используется существующим runtime; подпись/промо/логотип видны в рабочем предпросмотре карточки, но общая оболочка пока их не потребляет. Точные пути — в `docs/modules/E1-05.md`.
2. `scripts/generate-types/generate.php --check` сообщает stale `translations.ts`. Read-only сравнение подтвердило: lang inputs, generator, FeatureRegistry и generated translations byte-identical базе 8ed6f5f; задача не добавляет переводов. Это исходное расхождение: отсутствует `navigation.seller_digests` (31 ожидаемый ключ против 30 generated), navigation JSON также совпадает с base. Интегратору выполнить штатную генерацию, включая новые именованные routes; shared generated файлы здесь не изменялись.
3. Нативный `dns_get_record` использует таймаут DNS ОС; отдельный deadline DNS/TXT не установлен. Ограничения 3/8 секунд относятся к HTTP connect/total, не к суммарному времени системного DNS. Ошибки DNS закрывают проверку.
4. robots.txt здесь проверяется только на полный запрет `User-agent: *` / `Disallow: /`, это не полноценный SiteAudit/scoring. Верификация доказывает текущий challenge; SSL/CNAME provision и интеграция будущего widget runtime не выполняются этой задачей.
5. Live проверки внешних DNS/HTTP, писем и ИИ не проводились по прямому запрету пользователя. Golden fixtures не менялись.

Задача передаётся только в review. Merge в main и done выполняет интегратор.
