# SP-E5-10D — пометки во входящих и массовая отправка (D-2.5)

- Во входящих базы знаний показываются все шесть типов пометок, исходный ответ бота, комментарий и предложенное исправление; применение и отклонение только ручным действием (прежняя часть, тест ReviewsE510DTest).
- D-2.5 «Пометки» (07.11): массовое действие «Отправить во Входящие базы знаний» для выбранных новых пометок — `POST /seller/reviews/send` (право `seller.dialogues.operate`, текущий бренд, видимость менеджера по своим диалогам). Пометка остаётся «Новая» с отметкой «Куда учтено: Входящие базы знаний»; база знаний и черновик не меняются, внешних вызовов нет.
- Страница по макетам `43/80937148-D-2.5-main`, `43/ba7becf3-D-2.5-states`, `43/5432cfb3-D-2.5-empty`: карточки типов с процентом и полосой, период справа, фильтры, «Выбрано: N», кнопки «Отправить во Входящие базы знаний» и «Отклонить», «Выбрать все», чипы типа и статуса, «Куда учтено», дата «28 окт, 09:15», ссылка на диалог `#…`; skeleton «Загрузка» (столбики + строки таблицы); ошибка «Не удалось загрузить пометки / Код: ERR_LOAD / Повторить»; пустое состояние «Пометок пока нет» с кнопкой «Открыть диалоги».
- Проверено:
  - массовая отправка, чужой бренд (404), отклонённая пометка (404), пустой/неверный список (ошибки валидации), наблюдатель (403), БЗ не меняется, пометка видна во входящих — `tests/Feature/Seller/Reviews/ReviewsSendE510DTest.php`;
  - skeleton, выбор всех с клавиатуры, отправка, отказ сети, наблюдатель без действий, три темы, 1440/1024/390 без горизонтальной прокрутки — `tests/Browser/E5-10D/reviews.spec.ts` (2 теста); прежние E5-10/E5-10B/E5-10C/E5-10D браузерные — зелёные;
  - Feature `tests/Feature/Seller/Dialogs` — зелёные, кроме PendingPageE504HTest: локально падает проверка роли БД слота («isolated test database»), к правке не относится;
  - check frontend (lint, typecheck, test, build), check lint.
- Скриншоты: `.local/screenshots/SP-E5-10D/reviews.png`, `reviews-loading.png`.

## Техдолг
- Входящие БЗ показывают последние 50 новых пометок по дате создания; отправленные старые пометки сверх 50 туда не попадут до разбора более новых.

## Принято по умолчанию
- «Отправить во Входящие» не создаёт новых записей: помечает выбранные новые пометки `applied_to = inbox`; после решения во входящих поле заменяется на место применения (факты, образцы речи…).
- В пустом состоянии оставлена строка «Пометок нет.» в пояснении — на неё опирается существующий тест E5-10.
- Номер диалога в таблице — последние 6 символов ULID (порядкового номера у диалога нет).
