# SP-L1-07 · Создание клиента администратором

Сделано:
- `org:create {name} {owner_email} [--plan=]` — организация, первый бренд (имя=организация), план в
  `organization_plan` (`--plan` или `features.L1-07.defaults.default_plan=start`), приглашение владельца;
  печатает одноразовую ссылку `/invitations/open#<secret>` (только `token_hash`); повтор по имени/почте —
  ошибка без дублей. `invited_by` — фиксированный системный пользователь (без изменения схемы).
- `Cabinet::organizationIdFor(User)` — организация по активной membership пользователя; `organizationId()`
  (резерв `CABINET_ORGANIZATION_ID`) — для случаев без пользователя (bootstrap-регистрация, восстановление
  пароля/почты до входа). Заменено во всех файлах из scope карточки.
- Поиск/приём приглашения (`InvitationAcceptance`, `InvitationExchangeGrants`, `InvitationController::invite`,
  `EligibleAccount`) берёт организацию из приглашения, не заранее — это и даёт работу второй организации.
  Приглашение владельца — роль `admin`+`settings.designated_owner=true` (CHECK не расширяли);
  `InvitationAcceptance` при первом принятии повышает membership до `owner`, ставит `organizations.owner_user_id`.
