# SP-L1-07 · Создание клиента администратором

Сделано:
- `org:create {name} {owner_email} [--plan=]` — организация, первый бренд (имя=организация), план в
  `organization_plan` (код из `--plan` или `features.L1-07.defaults.default_plan=start`), приглашение владельца;
  печатает одноразовую ссылку `/invitations/open#<secret>`, хранит только `token_hash`; повтор по имени
  организации/почте владельца — ошибка без дублей.
- `Cabinet::organizationIdFor(User)` — организация по активной membership пользователя; `organizationId()`
  (резерв `CABINET_ORGANIZATION_ID`) — для случаев без пользователя (bootstrap-регистрация, восстановление
  пароля/почты до входа по email). Заменено во всех файлах из scope карточки.
- Поиск/приём приглашения (`InvitationAcceptance`, `InvitationExchangeGrants`, `InvitationController::invite`,
  `EligibleAccount`) больше не требует знать организацию заранее — берёт её из самого приглашения; это и даёт
  работу второй организации.
- Приглашение владельца — роль `admin`+`settings.designated_owner=true` (CHECK `invitations_role_check` не
  расширяли); при первом принятии `InvitationAcceptance` повышает membership до `owner`, проставляет
  `organizations.owner_user_id`. `invited_by` (FK, не nullable) — фиксированный системный пользователь
  `system.org-create@cabinet.internal`, создаётся один раз и переиспользуется; схему не трогали.
