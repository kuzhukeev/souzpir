# SP-E1-09E — имена объектов журнала и CSV

Сделано: сервер разрешает имена и ссылки контактов и диалогов только в текущем бренде; журнал показывает их вместо ID. Основные действия получают читаемые фразы. CSV содержит те же названия действий и объектов, а также колонку модуля.

Проверки: `JournalNamesTest.php` и `JournalTest.php` — 6 тестов, 160 проверок (сценарий, права, изоляция брендов, ошибки и CSV); `tests/Browser/E1-09E/journal.spec.ts` — 1 тест; `npm run typecheck`; Pint.

Скриншот, светлая тема, 1440: [Журнал](../../.local/screenshots/SP-E1-09E/journal.png).

## Остаток

- Имена/ссылки прочих типов объектов требуют отдельных реестров их владельцев; пока показан технический ID без ссылки.
- Для остальных кодов действий остаётся явная подпись «Действие: код»; полный словарь нужно согласовать по событиям модулей.
- Меню ⋮ и его действия по макету ещё не реализованы; текущая кнопка «Открыть» показывает детали.

## Техдолг

- При удалённом контакте диалог показывает запасное имя с ID.

## Принято по умолчанию

- Чужой объект, даже если его ID попал в событие текущего бренда, не получает имя и ссылку.

## Нужно от интегратора

- Завести продолжение на реестры остальных объектов, словарь действий и меню; согласовать владельцев ссылок модулей.
