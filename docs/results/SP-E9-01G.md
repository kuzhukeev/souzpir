# SP-E9-01G — частичная сквозная приёмка

- В изолированной PostgreSQL и браузере проверены реальные маршруты и состояния 20 экранов, включая созданные через UI черновик, факт, тему, клиента, напоминание, товар, импорт TXT, публикацию и настройки причины передачи. Вопрос для D-4.2 добавлен в тестовую БД; runtime им не проверен.
- Axe на 1440/1024/390: серьёзные нарушения на пустой D-4.11, входящих D-4.1/D-4.2, карточке D-3.2, таблицах D-5.1 и D-10.1. Диалог из виджета не открывается при пустом поиске; при непустом открывается. Подробности и другие расхождения — docs/validation/SP-E9-01G-real.md, скриншоты — .local/screenshots/SP-E9-01G/.
- Единая таблица восьми сценариев docs/validation/acceptance.md синхронизирована с опубликованным main и дополнена результатами. Настройки причины проверены на валидацию, сохранение и изоляцию двух брендов.
- Проверки: TypeScript, ESLint двух тестов и PHP lint двух fixture-файлов прошли. Оба браузерных прогона завершились ошибками из-за обнаруженных дефектов; результаты и скриншоты сохранены до assertions. Повтор пустых состояний подтвердил link-in-text-block на трёх ширинах.

## Остаток
- Сценарий 3: webhook → fake-ответ → перехват и возврат через браузер после готовности runtime; сценарий 5: диалог → задача → fake-уведомление и изоляция; сценарий 7: сообщения виджета → диалог → карточка; сценарий 8: смена бренда в диалогах и очистка кэша и вкладок.
