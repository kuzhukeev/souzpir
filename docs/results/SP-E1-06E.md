# SP-E1-06E — форма одноразового приглашения

Компонент `resources/js/features/Shell/InvitationIssuance/InvitationDialog.tsx` реализует русскоязычное окно: почта, роль, доступные бренды, отдельное подтверждение, настоящий `POST /team/invitations`, однократный показ и копирование ссылки. Срок 7 суток назначает сервер. Письмо не отправляется. Для менеджера передаются роль `member` и `sales_manager=true`; для каждой явной попытки создаётся ключ из 32 случайных байтов через `crypto.getRandomValues`.

При неизвестном результате нет автоматического повтора: окно объясняет, что приглашение могло быть создано, и требует отдельного действия и подтверждения перед новым выпуском. При закрытии во время запроса остаётся только несекретный признак неизвестного результата, который показывается при следующем открытии смонтированного компонента. Секрет не передаётся родителю и хранится только в состоянии/ссылках текущего компонента; при закрытии, смене контекста, навигации, скрытии страницы или отказе доступа отображаемое поле очищается, а поздние ответы игнорируются. Не используются Inertia props, история, localStorage, sessionStorage или журнал для хранения ссылки. Программное копирование выполняется только по нажатию; если Clipboard API недоступен, доступно ручное выделение. Как обычно для JavaScript, управление физической очисткой памяти браузера принадлежит сборщику мусора.

До показа ссылки выполняется `GET /team` и сверяются действующие права, бренд, revision и доступность выбранных брендов. Пока ссылка показана, эта проверка повторяется каждые 5 секунд; зависшая проверка прекращается ещё через 5 секунд и ссылка удаляется. События локальной и межвкладочной смены контекста очищают её сразу. Отзыв только на сервере без события в браузере обнаруживается при следующей проверке; при замороженных браузером таймерах мгновенная проверка не гарантируется. При зависшем выпуске через 15 секунд показывается неизвестный результат, даже если fetch не реагирует на abort.

## Подключение интегратором

Общая `Team/Index` не изменялась. Компонент необходимо держать смонтированным на странице и передавать `open`, `onClose`, актуальные `canIssue`, `brandId`, `revision`, `brands`. На текущей странице: `canIssue={canViewRoles}`, `brandId` — текущий `usePage().props.brand.id`, `revision={teamBrandRevision}`, `brands={filterBrands}`. Кнопку открытия следует показывать только при наличии прав; при изменении контекста передавать новые значения. Не сохранять ссылку в родительском состоянии. Смонтированное окно сохраняет предупреждение о закрытом во время запроса выпуске; после полной перезагрузки страницы такой несекретный признак не сохраняется, а новый выпуск всё равно требует отдельного подтверждения.

## Проверки

Изолированный worktree; PostgreSQL 17 на `127.0.0.1:56443`, отдельная `souzpir_test_sp_e1_06e` с непривилегированным владельцем, отдельные storage/session/cache и synthetic пользователи. `MAIL_MAILER=log`, AI и доставка fake; внешние обращения не выполнялись. Браузерные запросы ограничены тестовыми loopback-серверами. Тестовый PHP router запущен только с `APP_ENV=testing` и явным флагом; он подставляет известный `SERVER_ADDR` для встроенного PHP-сервера, который сам его не сообщает. В тесте `http://souzpir.local:8231` Chromium разрешает домен в loopback, а CORS разрешён только для скриптов отдельного тестового Vite-сервера; это не проверка конфигурации OSPanel или рабочего HTTPS.

- Vitest: 10 адресных тестов, включая закрытие при незавершённом запросе, недоступную буферу обмена среду, неизвестный результат, зависший fetch, очистку DOM и запоздалый ответ.
- Playwright/Chromium: 13 сценариев настоящего HTTP→UI и отдельной БД, включая одноразовый обмен через Auth, потерянный ответ после фиксации, отсутствие автоматического повтора, отказ viewer/чужого бренда, смену бренда в другой вкладке и отзыв реальной сессии. В тесте выключены trace, video и автоматические снимки страницы при ошибках; снимки делаются только до выпуска ссылки.
- Дополнительно проверяются все сочетания трёх тем и ширин 1440/1024/390: выбор роли с клавиатуры, возврат фокуса, отсутствие горизонтального overflow, видимый текст не меньше 13 px, axe без serious/critical нарушений. Скриншоты несекретной формы находятся в `.local/screenshots/e1-06e/form-<ширина>-<тема>.png`; они не коммитятся.
- TypeScript `tsc --noEmit` и адресный ESLint проходят. Полный интеграционный набор не запускался; подключение к общей странице остаётся интегратору.

## Исправление после review

Проверка контекста отправляет текущую версию Inertia и отказывает при несовпадении полученной версии; смена версии также очищает уже показанную ссылку. Два браузерных сценария прошли на настоящем HTTP с production Vite manifest и отдельной тестовой PostgreSQL: POST 201 → GET 200 → показ ссылки; намеренно устаревшая версия → GET 409 → ссылка не показывается, запись в БД одна. Ответ с неожиданной версией при HTTP 200 проверен отдельно unit-тестом. Для проверки страницы команды тест создаёт во временной директории копию ресурсов с подключением компонента; общая страница в Git не менялась, интеграцию выполняет основной чат. Тестовый сервер ограничен loopback, живых отправок нет.

Дополнительно прошли 13 unit-тестов, 19 браузерных регрессионных сценариев (включая темы, размеры экрана и доступность), TypeScript, адресный ESLint и проверка синтаксиса тестового PHP router. Тестовый harness обновлён для настоящего провайдера Inertia.
