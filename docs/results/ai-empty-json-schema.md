# Пустой JSON-объект в схемах AiGateway

В запросах Gateway допустим точный пустой `stdClass` только внутри `tools[*].function.parameters` и `response_format.json_schema.schema`. Он представляет JSON `{}` и сохраняется на wire и в fake-fixture; `[]` остаётся массивом, а их хеши и ключи идемпотентности различаются. Непустые объекты, подклассы, `JsonSerializable` и ресурсы отвергаются до сериализации. Проверяемая копия передаётся существующим SecretBoundary и ContactBoundary без изменения переданных вызывающим данных; ContactMasker сохраняет исходную форму JSON-объектов в строковых аргументах инструмента, продолжая маскировать контакты. Ошибки не раскрывают чувствительные ключи в трассировке.

Общий CanonicalJson используется также отчётами «Видения»: проверен сохранённый хеш payload с 2000 слотами относительно прежнего алгоритма. Ограничение числа узлов проверяющей копии относится только к AI; CanonicalJson сохраняет совместимость по числу узлов и ограничивает глубину значением JSON encoder. Для циклов и произвольных объектов обработка закрывается с ошибкой.

На отдельной PostgreSQL и fake-драйвере прошли 33 теста Gateway / 169 assertions, в том числе фактический fake вызов, повтор с тем же ключом и различие `{}` и `[]`; 155 тестов границ и канонизации / 277 assertions, в том числе при `zend.exception_ignore_args=0`. Живых вызовов не выполняли. Независимая проверка рассмотрела ссылки PHP, трассировки, недопустимые объекты, циклы и большие отчёты.

**Граница для SP-E3-03:** это исправление касается исходящих схем и строковых аргументов в запросе. Ответы провайдера и fake-fixture по существующему контракту `toolCalls[].arguments` декодируются как PHP-массив; поэтому пустой объект из ответа модели неотличим от пустого массива. Изменение этого поведения требует отдельного согласования типа результата, replay, валидатора Gateway и потребителей прототипа. Сквозной round-trip `{}` здесь не заявляется. Прямой вызов ContactMasker не заменяет полный путь Gateway с проверкой SecretBoundary перед обработкой JSON-аргументов.
