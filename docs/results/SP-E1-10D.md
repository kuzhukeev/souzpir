# SP-E1-10D — чтение диалогов по брендовому ключу

- GET `/api/v1/seller/conversations` и GET `/api/v1/seller/conversations/{id}` возвращают ограниченный список и карточку своего бренда без содержимого переписки и приватного состояния.
- Используются существующие bearer, tenant и `read` permission middleware; проверяется доступность Seller.
- 2 feature-теста, 9 проверок на отдельной PostgreSQL: успешный путь, чужой бренд, отсутствие ключа и неверное право; Pint, генерация типов и diff check.
- Изменения серверные; скриншоты не применимы. Создание и ведение диалога остаются вне этого среза.

## Техдолг
- Список ограничен первыми 50 записями; курсорную пагинацию добавить при появлении большого объёма данных.

## Принято по умолчанию
- Право ключа `read` разрешает только метаданные диалога: ID, режим и время создания.
