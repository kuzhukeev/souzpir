# SP-E8-03 — наборы вопросов «Видения»

Ветка `codex/sp-e8-03`, база claim `447b0b4c83c0cc777069e7846ced628846ffc3cb`. Результат предназначен для review, интеграцию в main выполняет интегратор.

## Реализовано

Предложенные вопросы, ручной ввод и явный импорт из сохранённой анкеты, выбор и отключение кандидатов, утверждение, текущий неизменяемый набор и история версий с checksum. Ручные и импортированные данные имеют отдельное происхождение; генерация ИИ не имитируется. Изменение набора после обновления профиля явно копирует подходящие вопросы без изменения предыдущего набора и без дублей. Удаление разрешено только автору собственного ручного вопроса.

Утверждение проверяет активную session lease, права и tenant, доступные модели и настроенные лимиты. `QuestionSets::create` создаёт реальную immutable версию; в той же транзакции сохраняются active pointer и audit. Наборы размером 12, 20 и 30 проверены без жёсткого тарифного значения. Viewer получает утверждённые наборы без приватных кандидатов. Приватный JSON доступен через HTTPS/loopback, не сохраняется в Inertia history; ошибки не раскрывают тексты и исключения.

- Отдельные PostgreSQL `127.0.0.1:55500`, тестовая база `souzpir_test_sp_e8_03`, роль без административных прав, отдельные storage/cache/cookie и порты. AI/delivery fake, mail log; живых внешних отправок и AI вызовов не было.
- Серверные проверки с `zend.exception_ignore_args=0`: **11 passed / 251 assertions** — isolation, roles, limits, 12/20/30, происхождение и перенос, privacy, rollback audit. Утверждённый set передан в существующий `MeasurementRunner::start` с synthetic grant и fake runtime: pending measurement создан, ai_calls=0 и внешних HTTP запросов нет.
- Browser: 37/37 visual/axe для страниц, трёх тем и размеров 1440/1024/390; реальный E2E 1/1 (версии 1/2, viewer, подмена brand ID, межсайтовый CSRF 419). Read-only сверка БД подтвердила checksum, active pointer, audit и отсутствие AI calls. Отдельная regression сравнения истории как multiset — 1/1.
- TypeScript, scoped ESLint, production build, Pint и validator контрактов PASS. Вручную проверены локальные снимки `.local/screenshots/e8-03/active-neutral-390.png`, `approve-neutral-1440.png`, `real-history.png`.

## Запросы интегратору и ограничения

- Владельцу `docs/contracts/registry.json`: зарегистрировать brand-scoped `vision_question_manual_batches` (parent `question_generation_batches`), `vision_question_approvals` (parent `question_sets`) и `vision_question_copy_entries` (parents `question_candidates`, `question_sets`).
- Будущий consumer генерации обязан исключать batches с собственным sidecar origin `manual`, `questionnaire`, `active_set` из AI очереди/rebuild. Настоящая AI-генерация анкеты требует отдельного data class/grant/policy и разрешённого live этапа.
- SP-E8-04 должна выбирать active pointer tenant-qualified и повторно проверять lease, permission и published grant; `MeasurementRunner::start` сам active pointer не проверяет. Автозапуск и расписание в этой задаче не имитируются.
- Пункт «Вопросы» и переход из профиля отсутствуют в существующей общей навигации вне scope. Интегратору: добавить `/vision/questions` в `resources/js/components/navigation/navigation.json` с `vision.report.read` и ссылку из профиля после утверждения анкеты; права изменения остаются `vision.quiz.write` на сервере.
- История ограничена последними 100 версиями; потребуются pagination и согласованное расписание. Полный сценарий E2E №2 зависит от последующих задач отчётов/публикации.

## Исправления интегратора: приватный транспорт и история

В ветку задачи штатно объединён main `6c7e1f6`. Контроллер использует `VerifiedHttps`: недостоверные заголовки и универсальные proxy-сети не признаются HTTPS. Допустимый HTTP — только `APP_ENV=local`, host `souzpir.local`, прямое соединение loopback с обеих сторон без forwarding headers. Интерфейс получает разрешение от сервера, поэтому поддерживает этот локальный адрес. Приватные данные не помещаются в Inertia props: при `pagehide` содержимое скрывается, после BFCache-восстановления страница принудительно перезагружается; при ответе API 401 браузер переходит к входу.

- На отдельной PostgreSQL прошли 12 тестов / 274 assertions, в том числе native HTTPS, явный доверенный proxy, поддельный forwarding, универсальный proxy и local/production.
- Browser E2E проверяет создание, версии, подмену бренда, CSRF, локальный HTTP, смену бренда и back после logout. События `pagehide/pageshow` с признаком BFCache дополнительно возбуждаются явно и проверяются в браузере; фактическое попадание страницы в BFCache конкретным браузером не гарантируется. Тестовый встроенный сервер слушает только loopback; отсутствующий в нём `SERVER_ADDR` задаётся test-only router. Рабочий веб-сервер должен передавать реальный адрес соединения.
- Проверены TypeScript, scoped ESLint, Pint и production build. Тестовые SMTP/AI не отправляли внешних запросов. Снимок истории: `.local/screenshots/e8-03/real-history.png`.
- Регистрация таблиц и правила будущего consumer добавлены в `main` коммитом `e0cfe79`.
