# SP-C-03 · Исходные аргументы действий ИИ

Добавлены отдельные `completeWithRawToolCalls` в Fake и OpenRouter. Каждый
получает результат из одного источника и возвращает нормализованный результат
вместе с исходными строками `arguments_json`; исходные строки не получаются
повторной сериализацией массива. Условие целостности проверяет JSON-объект,
дублирующиеся ключи на любой глубине и в окружающем JSON, идентификаторы вызовов
и отсутствие дубликатов ID. Массив в корне не принимается, `{}` сохраняется как
исходная строка. Публичный `complete` сохраняет прежний формат и поведение.

Для нового fake-пути fixture хранит `result.toolCalls[].arguments` как строку
с исходным JSON, аналогично полю OpenRouter; старые fixtures с уже разобранными
массивами не считаются доказательством исходных аргументов. При ошибке fake
возвращает безопасный `Rejected`, при неопределённом ответе/состоянии OpenRouter
— `Uncertain`; сведения из запросов, ответов и ключей не включаются в ошибки.
Новый результат — только данные: он не является подтверждением стадии или
правом на бизнес-действие. Привязка к защищённой стадии, хранение, учёт,
исполнение и восстановление неизвестного исхода относятся к SP-C-02 и здесь
не подключены. Глубина проверки JSON ограничена существующим инспектором (22).

Проверки в отдельном worktree с отдельным локальным PostgreSQL
`souzpir_test_c03_raw` и непривилегированной ролью: **19 тестов / 79 проверок**
для синтетических fixtures и подменённого HTTP, включая `{}`/`[]`, вложенные и
экранированные дубли, ошибки и отсутствие утечек; существующий набор проверки
прежнего OpenRouter `complete` — **3 теста / 378 проверок**. HTTP в тестах
подменялся, неразрешённые запросы запрещены; живых вызовов ИИ и отправок не было.
Изображения и браузерные скриншоты не применимы.
