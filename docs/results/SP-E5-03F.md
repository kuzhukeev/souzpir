# SP-E5-03F — защищённая симуляция продавца

- Продолжен ранее принятый этап API: исходящий первый ход и последующие ответы API остаются защищёнными.
- В симуляции фиксированный ответ заменён на extractor → Policy → responder → детерминированный Guard через fake Gateway. Вход и результат заново проверяются в пределах организации и бренда; вызовы Gateway происходят вне транзакции.
- Запись входящего сообщения и claim защищены идемпотентной квитанцией; повтор успешного хода возвращает сохранённый результат без дополнительных сообщений и вызовов. Посторонняя беседа и бренд не принимаются.
- PostgreSQL: тесты симуляции и моста — 7 тестов, 41 проверка; API opening/follow-up — 1 тест, 41 проверка. Pint пройден. Тесты используют отдельную БД и локальный fake-драйвер.

## Остаток
- Защищённые вызовы инструментов, повторная генерация после Guard и модельный Guard для последующих ходов; сейчас такие случаи завершаются без отправки.
- Явная повторная попытка после ошибки fake Gateway: успешный ход идемпотентен, но ошибочный вызов требует отдельной попытки.
- `TokenInboundRuntime` сохраняет прежний фиксированный fallback для старого транзакционного маршрута; действующий двухфазный API обрабатывает обычные ходы через Gateway. Удалить fallback после проверки всех его входов.

## Техдолг
- Отсутствующие fixture Gateway приводят к ошибке симуляции; нужно подготовить согласованные fake fixtures под используемые сценарии.

## Принято по умолчанию
- При отказе Guard ответ не записывается и не доставляется.

## Нужно от интегратора
- До приёмки частичной сдачи зарегистрировать продолжение на перечисленный остаток.
