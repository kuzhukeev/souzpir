# SP-E5-03F — повтор fake-вызова

- Повтор того же API-запроса или хода симуляции после подтверждённой ошибки fake Gateway создаёт следующую попытку с ссылкой на предыдущий вызов; исходящий первый ход, extractor и responder поддержаны.
- Успешный повтор возвращает сохранённый результат без дублей сообщений и вызовов. Неопределённый результат не переотправляется; права и бренд повторно проверяются на каждой стадии.
- PostgreSQL: API и защищённая симуляция — 7 тестов, 89 проверок; сценарии ошибок обеих стадий, первый и последующий ход API, повтор, изменённый запрос и чужой бренд. Pint пройден; внешних вызовов нет.

## Остаток
- Защищённые вызовы инструментов, повторная генерация после Guard и модельный Guard для последующих ходов; сейчас такие случаи завершаются без отправки.
- Проверить входы старого транзакционного `TokenInboundRuntime` и заменить фиксированный fallback там, где он применяется в согласованных сценариях.

## Техдолг
- Нет дополнительных замечаний.

## Принято по умолчанию
- Повтором считается повтор исходного запроса с тем же ключом и теми же данными; попытка создаётся только после подтверждённого отказа, неопределённый результат сохраняется без повторной отправки.
