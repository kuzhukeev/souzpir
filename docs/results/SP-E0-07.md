# SP-E0-07 — независимый шаг: read-only состояние очередей

Реализована операторская команда `runtime:queue-status`: агрегаты ожидающих,
зарезервированных и неуспешных заданий для разрешённых очередей текущего
namespace; чужие очереди и недопустимые подключения исключены. При отсутствии
таблиц и неподдерживаемой конфигурации выдаётся безопасная ошибка. Подробное
значение показателей и ограничения — в `docs/modules/E0-07.md`.

**3 feature-теста / 61 проверка**, Pint и `git diff --check`: реальные таблицы
PostgreSQL с синтетическими заданиями, включая чужие очереди и исключения с
приватными маркерами; снимки таблиц до и после совпадают, SQL содержит только
SELECT и не выбирает payload/exception. Команда успешно работает в отдельной
транзакции `READ ONLY`. Проверки выполнены на двух отдельных кластерах этого
worktree с разными тестовыми БД и ролями. Перед миграциями применяется общий
guard `IsolatedAuthDatabase`; рабочая и preview БД не использовались.

Scheduler, worker и внешние отправки не запускались. Полный DoD SP-E0-07 ещё не
выполнен. Незавершённое расписание с воспроизведённым ростом очереди сохранено
в `codex/archive-sp-e0-07-schedule-wip`, старый worker с блокером гонки путей —
в `codex/archive-sp-e0-07-0ce2592`; они не входят в этот коммит. Скриншоты к
этому инфраструктурному шагу не относятся.

## Изолированная одноразовая проверка runtime

- Добавлены команды изолированной тестовой очереди: статус, один проход worker и один проход scheduler с отключённой регистрацией расписаний; внешняя доставка отключена.
- На отдельной PostgreSQL `souzpir_test_e007` на loopback: status показал пустые очереди; один синтетический job записал маркер и worker завершился; scheduler сообщил отсутствие задач; некорректное имя БД отклонено.
- Рабочий worker и реальные отправки не запускались; UI нет, скриншоты не применимы.
- Ограничения: проверен один fake job; настоящие расписания, поведение ошибок и безопасное журналирование их содержимого не проверены. Постоянный режим не предоставлен.

## Техдолг
