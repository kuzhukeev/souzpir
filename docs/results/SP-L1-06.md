# SP-L1-06 · Уведомления менеджеров о сообщениях и черновиках

Сделано: события `seller.conversation.inbound` и `seller.draft.ready` зарегистрированы в `docs/contracts/registry.json` (owner SP-L1-06) и `EventCatalog::TITLES`; `RecipientPolicy` даёт доступ ролям owner/admin/member (менеджеры бренда). Новый модуль `app/Seller/Notifications/`: `QueueInboundNotification` — слушатель `eloquent.created` на `Message` (роль client), ставит `NotifyConversationEvent`; `LiveDraftJob::finish()` ставит тот же job при статусе `suggested` (`turn_id` в данных). `NotifyConversationEvent` — дедуп (не чаще раза в N минут на диалог+тип события, таблица `seller_notification_event_marks`, `config/features/L1-06.php: dedup_minutes=5`), затем `NotificationDispatcher::enqueue` (существующий outbox → `NotificationProcessor` сам создаёт `cabinet_notifications` по каталогу и политике, без правок в этом файле) и — при `NOTIFICATIONS_EXTERNAL_ENABLED` (`features.E0-04.defaults.external_delivery`) — одно сообщение в группу менеджеров через `TelegramSender::managers` (chat бренда `managers_chat_id`), текст = заголовок каталога + ссылка на `/seller/dialogs/{id}`, без прочих персональных данных. `DrainNotificationsSchedule` регистрирует `notifications:drain` каждую минуту (`withoutOverlapping`) через `ScheduleContributor` в `config/features/L1-06.php` — `routes/console.php` не трогали.

Тесты: `tests/Feature/Launch/L1-06/ConversationNotificationsTest.php` — входящее сообщение → кабинет для owner и менеджера бренда, изоляция чужого бренда (нет записи), группа Telegram молчит при выключенном флаге и дедуп-окне, включение флага + истечение окна (`CarbonImmutable::setTestNow`, +10 мин) → ровно одно сообщение в `managers_chat_id` со ссылкой на диалог; `LiveDraftJob` со статусом suggested → уведомление владельцу. `DrainScheduleTest` — расписание регистрирует `notifications:drain` `* * * * *` с `withoutOverlapping`. Проверено: `php artisan test tests/Feature/Launch/L1-06` (3/3, 17 assertions); регрессия — `php artisan test tests/Feature/Shell/Notifications/NotificationCoreTest.php tests/Feature/Launch/L1-01 tests/Feature/Seller/Channels/Planned` (зелёные; падения `OutboxTracePrivacyTest`/`OutboxDeferralTest`/`AfterCommitTest` — известное ограничение слота «dedicated nonprivileged test database owner», см. `docs/results/isolated-test-database.md`, не относится к задаче). `composer lint` (pint) — зелёный.

## Техдолг
- Канал входящего сообщения в данных события берётся из `messages.channel_account_id`; если он не заполнен (например, виджет без привязки) — `channel: unknown`, без блокировки уведомления.

## Принято по умолчанию
- Получателями «менеджеров бренда» взяты активные участники бренда с ролями owner/admin/member (как для существующих `handed_off`/`contact.reminder`), а не только owner/admin — иначе менеджеры не узнавали бы о новых сообщениях.
- Группа в Telegram — существующий `managers_chat_id` Telegram-канала бренда (единственный канал этого типа); если он не настроен, шлётся только уведомление в кабинет.
