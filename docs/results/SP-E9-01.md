# SP-E9-01 — сквозная приёмка, очередной срез

Полная фиксированная матрица восьми сценариев ведётся в `docs/validation/acceptance.md` (единая приёмка по решению владельца 07.11.2026); прошли сценарии 1, 2 и 4, остальные — «не прошёл» с конкретным незакрытым шагом.

## Сделано в этом срезе
- Сценарий 4 доведён до сквозного прохода: `KnowledgeLifecycleE901ETest` теперь дополнительно запускает песочницу (`/seller/knowledge/sandbox/reply`, `simulation=true`) именно на второй, уже опубликованной версии (`secondRelease`) после правки факта — ответ подтверждает `release=secondRelease`, заполняет слот и контрольная сумма снимка отличается от версии до правки; далее идёт откат первой версии с восстановлением текста. Проверено: `php artisan test tests/Browser/Acceptance/KnowledgeLifecycleE901ETest.php` — 1 passed (62 assertions).
- Попытка фактического прогона сценария 6 (`acceptance_e901e`, роль `souzpir_e901e`): роль в общей Postgres уже создана интегратором, но её пароль не совпадает с `ci-only-password` из `.github/workflows/ci.yml`; создать роль/сменить пароль самостоятельно нельзя — у роли исполнителя нет `CREATEROLE`. Остаётся «не прошёл».

## Остаток
- Сценарии 3, 5, 7, 8 не изменились — упираются не в тесты, а в отсутствующую в движке функциональность (см. Техдолг), которая вне scope SP-E9-01 (только `docs/validation/acceptance.md`, `tests/Browser/Acceptance/`, `tests/visual/`).
- Сценарий 6: код проходa уже в main, фактический прогон ручного CI `acceptance_e901e` не выполнен — нужен рабочий пароль роли `souzpir_e901e`.
- Визуальные эталоны 20 экранов × 3 ширины и `tests/visual/` не собраны (каталог пуст) — вне достигнутого в этом срезе.

## Техдолг
- Ни один канал (Telegram, виджет) сейчас не генерирует живой ответ бота синхронно и видимо в диалоге — `WidgetInboundRuntime` явно документирует «no AI stage exists for a public visitor yet» и всегда переводит диалог в режим менеджера; это блокирует честный проход сценариев 3 и 7 (переписка в браузере) без изменения движка, которое вне scope.
- Переключатель бренда на самой странице диалогов намеренно отрисован как «Скоро» (`context-e901c.spec.ts`) — сценарий 8 не может быть пройден с этой страницы, пока переключатель не включён в соответствующей карточке экрана.
- Цепочка «диалог → задача → fake-уведомление» для причины передачи (сценарий 5) не продемонстрирована сквозным браузерным путём по той же причине — нет реального входящего хода с live-движком вне песочницы.

## Принято по умолчанию
- Для сравнения «новая версия ≠ старая» в сценарии 4 используется сравнение контрольных сумм снимка из уже существующего ответа песочницы, а не отдельный вызов репозитория — так тест не завязывается на внутренний bind `TenantContext` в контейнере.

## Нужно от интегратора
- Пароль (или пересоздание) роли `souzpir_e901e` для фактического прогона сценария 6 в ручном CI `acceptance_e901e`.
