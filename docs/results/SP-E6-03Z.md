Доработка по reviewFeedback (reopen): D-5.2 показывает редактируемое «Не более N вопросов подряд» в карточке «Порядок вопросов по типу клиента» — сделано как настройка бренда, а не фиксированный текст.

Правило вопросов: не более одного вопроса в реплике (уже было в DeterministicGuard) и не более N ответов бота подряд, заканчивающихся вопросом (по умолчанию 2, настраивается в `policy.limits.max_consecutive_questions`) — следующий ответ по делу без вопроса. `FirstTurnDeterministicGuard::exceedsConsecutiveQuestionLimit()` принимает лимит параметром (default 2 — старые вызовы без аргумента не меняют поведение); `evaluateLocked` берёт лимит из опубликованной политики бренда. Напоминания (meta.goal_kind / meta.goal.kind = followup_nudge) не считаются и не прерывают цепочку.

Настройка лимита: `SlotOrder.tsx` (карточка «Порядок вопросов», уже умела сохранять порядок слотов в черновике) получила поле «Не более N вопросов подряд» (1–5), сохраняется вместе с порядком через тот же POST `/seller/settings/slot-order` → `policy.limits.max_consecutive_questions` в черновике, публикуется обычным циклом публикации базы знаний. `Funnel.tsx` (только чтение, опубликованная политика) показывает текущее значение вместо фиксированного «двух».

Цели и закрывающие поля (D-5.2 «Воронка», сделано ранее): `policy.client_fields` (required+stage) — единственный источник, сохранённый в настройках бренда.
