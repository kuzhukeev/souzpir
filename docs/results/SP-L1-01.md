# SP-L1-01 · Лимит расходов на ИИ

Сделано: config/features/L1-01.php (AI_BUDGET_DAILY_USD=3/MONTHLY_USD=30, org_monthly_usd=30, reservation_micros/limits для claude-sonnet-5.5 и gemini-2.5-flash). Gateway::reserve() проверяет глобальный дневной/месячный и org-месячный потолок до HTTP, только для живого драйвера (ai_live_reservations — отдельный учёт, не трогает legacy ai_budgets.reserved_micros). 80%: Log::warning + одно событие ai.budget.threshold_reached на org за период (дедуп через ai_budget_threshold_notices); для global-уровней — только лог (нет own organization_id для события). 100%: App\Ai\Budget\BudgetExhausted (LogicException 'AI budget exhausted.'). `ai:budget:set-org {organization} {usd}` — переопределение лимита org; `ai:budget` — отчёт по расходу/резерву/лимиту. LiveDraftJob: при budget_exhausted ход failed + error_code, диалог передаётся менеджеру (mode=manager/stage=handoff/handed_off_at, как в FirstInboundRuntime). MeasurementRunner: текущий слот failed/budget_exhausted, остальные pending того же замера — тоже failed/budget_exhausted, не берёт новые; UI-лейбл «Остановлен лимитом» (errorLabel в Measurements/Index.tsx). OperatorAiRecovery показывает расход/резерв/лимит сегодня/за месяц/по org, % использования.

Тесты: tests/Feature/Launch/L1-01/ — AiGlobalBudgetTest (6: дневной/месячный стоп до HTTP, 80% once per period, uncertain считается по резерву, set-org валидация+override+стоп, вывод ai:budget), LiveDraftBudgetStopTest (хэндофф), VisionMeasurementBudgetStopTest (стоп текущего+соседних слотов). Проверено: `php artisan test tests/Feature/Launch/L1-01` (8/8), регрессия — `tests/Feature/Ai/GatewayTest.php` (35), `tests/Feature/Launch/L1-02` (3), `tests/Feature/Shell/Billing/AiRecoveryPageTest.php` + `tests/Feature/Ai/Recovery` (10) — все зелёные. `check frontend` и `check lint` — зелёные.

## Техдолг
- reservation_micros/reservation_request_limits — технический потолок резерва (не цена для клиента); перед реальным запуском на живом OpenRouter проверить против актуального прайса провайдера.
- Глобальный дневной/месячный учёт считается без блокировок между параллельными резервами (гонка возможна при одновременных живых вызовах) — по правилам MVP не защищено.
- 80% для global_daily/global_monthly только в лог, без DomainEvent: схема ai.budget.threshold_reached в docs/contracts/registry.json требует один organization_id, а глобальный уровень не привязан к одной организации.

## Принято по умолчанию
- Числа лимитов и резервов взяты из текста карточки (30/3 USD) и подобраны как консервативные технические ceiling по умолчанию (не прайс провайдера) — см. Техдолг.
