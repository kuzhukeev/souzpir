# Результат SP-E0-02

Выполнен scoped фундамент tenancy: organizations/brands/memberships/invitations, TenantContext/runner/scopes, ResolveTenant, POST /brand/switch, lazy Inertia projections и контракт inspect/accept приглашения. User расширен memberships relation и MustVerifyEmail. Изменения bootstrap, locks, чужих DTO и audit schema не потребовались.

Explicit local/testing seeder создаёт одну демонстрационную организацию и 3 бренда, без пользователей, паролей и memberships. Повторный запуск идемпотентен, новый installation ID не создаёт вторую компанию. Initial owner assignment остаётся будущему onboarding; до него owner_user_id=null и authenticated кабинет не включается.

Проверено на PHP 8.4.19 / PostgreSQL 16.13, отдельных souzpir_sp_e0_02 и souzpir_test_sp_e0_02. Credentials/runtime/cache/cookies изолированы, .env не коммитится. Установлены зависимости из текущего composer.lock; validate --strict прошёл, manifest/lock не изменялись.

- Основной PHP suite перед добавлением integration regression: **50 passed / 274 assertions** (E0-02: 22 tests / 130 assertions).
- Дополнительный regression implicit model binding выявил отсутствующий middleware priority в E0-01: валидный current-brand ID даёт 404, поскольку SubstituteBindings выполняется до ResolveTenant. Тест сохранён без skip/подмены kernel: **1 ожидаемый pending integration failure**. Root согласовал исправление shared bootstrap сразу после merge; mark-done допустим только после green regression. Остальные 50 tests остаются green.
- Независимый review выявил stale-session mutation fallback; исправлено: read-only fallback либо explicit brand.switch, прочие stale/missing-context writes → 404 без записи в другой brand. Добавлен regression.
- Реальная гонка двух PHP процессов: один accept, второй 404, ровно один membership/consumption.
- Чистая preview DB: migrate прошёл, explicit seed дважды прошёл без дублей.
- Scoped Pint: прошёл.
- Config/route cache: brand.switch action/name/middleware неизменны. Полная semantic parity сравнивается после нормализации Laravel-generated names для ранее unnamed health/Inertia devtools routes; raw JSON из-за этих случайных имён закономерно отличается.
- Реальных внешних отправок и LLM calls нет. Source donor и baseline fixtures не изменены.

Границы: E0-03 владеет action permissions/can, E0-08 production shell/cache reset и generated DTO, E1-01 auth pages/token routes, E1-06 issuance/resend/revoke/delivery, E0-04 audit integration. В этой точке нет authenticated production UI; preview остаётся явно демонстрационным. Guest HTML redirect интегратор направляет на literal /login, который до E1-01 может возвращать 404. JSON unauthenticated boundary проверен как 401; verified и CSRF также проверены.

Screenshots не приложены: задача инфраструктурная, новых экранов не создаёт. Макеты первой контрольной точки принадлежат P-01. Детали использования и реальные ограничения: docs/modules/E0-02.md.
