# Одноразовый обмен приглашений — результат для интегратора

Основа: main `e0cfe7969f6d0a17845e0d1e96d052b887282309`. Работа подготовлена в отдельной ветке `codex/sp-invitation-onetime`; состояние очереди и main не менялись.

Приглашение атомарно расходуется при первом успешном обмене и больше не принимается напрямую через Tenancy API. Полномочие хранится в БД под HMAC ID сессии; epoch документа и номер запроса защищают от запоздавшего обмена. При смене ID сессии grant переносится и epoch меняется, при logout grant удаляется. Сохранены повторные проверки роли, адреса, организации, срока и отзыва при принятии. При откате миграции уже обменённые ссылки отзываются. Контракт и обязанности владельцев: `docs/contracts/invitation-exchange.md`.

Проверки на отдельной PostgreSQL `souzpir_test_sp_invitation_onetime` с ограниченной ролью, без реальных внешних отправок:

- AuthFlow: 19 тестов, 223 проверки; VerificationIntegration: 5 тестов, 61 проверка; Tenancy Invitations: 6 тестов, 28 проверок.
- Два теста с независимыми PHP-процессами и ожиданием блокировок PostgreSQL: 15 проверок. Они проверяют однократный обмен одного токена между сессиями и отклонение документа со старым epoch.
- Chromium Playwright: 7 сценариев, включая регистрацию, вход, повторную ссылку, два быстрых перехода, неверный fragment и потерю ответа. TypeScript, Pint и `docs/contracts/validate.py` прошли.
- Снимок проверенного экрана с синтетическими данными: `.local/screenshots/invitation-show.png` (игнорируется Git).

Ограничения: потерянный ответ может потребовать нового приглашения; автоматический почтовый сканер с исполнением JavaScript способен расходовать одноразовую ссылку. До обмена fragment может остаться в истории, особенно в браузерах без Navigation API; абсолютного отсутствия в истории нет. Очерёдность разрешается по зарегистрированным сервером запросам. При простое очистку записей обеспечивает работающий штатный scheduler; просроченный grant независимо от очистки недействителен. Сценарии браузера выполнялись в Chromium; отдельные реальные сетевые SMTP-вызовы не проверялись. Team-ветку и общую интеграцию необходимо проверить отдельно.
