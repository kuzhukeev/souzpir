# Частичная защита трасс outbox

Кандидат от `8d8c4b3`, без snapshot E1-10. Не является полной защитой трасс и не должен приниматься как решение caller-closure leak, описанного ниже.

`OutboxDispatcher` скрывает аргумент `DomainEvent` и отделяет запись от постановки job. Ошибки сериализации и БД заменяются безопасными без исходной exception chain; SQL/bindings и сообщение драйвера не передаются наружу. `QueryException`/`UniqueConstraintViolationException`, допустимый SQLSTATE и `DeadlockException` сохраняют значимые для PostgreSQL/Laravel сигналы повтора; вместо исходного PDO previous прикладывается новый очищенный. Два постоянных сообщения существующей проверки оставлены, прочие сообщения и исключения — общие. Ошибки постановки job вне границы не преобразуются; это не доказательство приватности их вызывающих кадров. Для иных драйверов и произвольных пользовательских подклассов сохранение типов не заявляется.

На отдельной PostgreSQL `souzpir_test_sp_outbox`, после проверки фактических `basePath` и `current_database`, полный каталог `tests/Feature/Shell/Notifications`: **26 тестов, 257 проверок** с `zend.exception_ignore_args=0`, включая реальный отказ JSONB на NUL, проверку ошибки JSON от невалидного UTF-8, отсутствие исходных SQL/bindings и предыдущего исключения с данными, настоящий commit/rollback, идемпотентную запись и повтор Laravel-транзакции с синтетическим `40001`. После повтора в БД остаётся одна запись. SQL deadlock и внешний transport настоящими не вызывались, очереди и сетевые отправки — fake.

## Оставшийся блокер: вызывающий closure попадает в trace

В реальном `DB::transaction(fn () => enqueue($event))` сама closure содержит захваченный `DomainEvent`. При `zend.exception_ignore_args=0` новый очищенный exception всё равно содержит внешний кадр Laravel transaction с этой closure в `getTrace()['args']`. Через `ReflectionFunction::getStaticVariables()` или трассировщик с аналогичным доступом можно увидеть данные event, хотя они отсутствуют в тексте исключения и во внутренней оригинальной цепочке. `SensitiveParameter` на `enqueue` не скрывает аргументы методов Laravel или захваты вышестоящего кода.

Это же воспроизведено на ранее интегрированном `ConversationRepository::claimTurn`/`PrivateOperation`: внешний `DB::transaction` closure хранит `TurnCommand` и его текст. Скрипт `tools/diagnostics/outbox-trace/probe.php` выполняет оба сценария на synthetic input и изолированной test DB, не печатает содержимое и не делает внешних вызовов; результат `true` подтверждает **сохраняющийся дефект, а не приёмку**.

Для полного решения нужна согласованная граница всех вызывающих бизнес-транзакций, ограничение захватываемых данных и/или проверенная fail-closed конфигурация PHP/runtime и обработчиков логов для HTTP и долгоживущих workers. Временное изменение process-global `zend.exception_ignore_args` внутри приложения не используется: оно может влиять на другие fibers и быть недоступным. Нельзя утверждать полную приватность `getTrace`, пока внешний caller и возможность повторного оборачивания исключения не проверены.
