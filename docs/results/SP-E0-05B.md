# SP-E0-05B — восстановление учёта ИИ

- Сохранён ранее сданный изолированный список `reserved`/`uncertain` вызовов.
- Новая миграция сохраняет ID генерации OpenRouter, в том числе при неполном ответе. Провайдерская сверка проверяет ID, финальность и стоимость через fake HTTP.
- Операторское действие переносит подтверждённую стоимость из резерва в расходы, обновляет `object_costs`, отмечает превышение и пишет аудит. Нулевая стоимость освобождает резерв. Без доказательства учёт не меняется; автоматического повтора нет.
- Тесты: RecoverCallTest 4, OpenRouterFinishReasonTest 3, UnresolvedCallsTest 6; 13/13, 489 assertions. Только fake HTTP, отдельная БД. Pint пройден.
- Ограничения: POST-контроллер не подключён к маршруту и UI отсутствует, потому что маршруты/клиент вне scope. Старые вызовы без ID остаются заблокированными. Скриншотов нет: добавлен серверный сценарий без экрана.

## Техдолг
- При сверке не отправляется существующее уведомление о пороге бюджета; баланс и аудит сохраняются.

## Принято по умолчанию
- `reserved` допускается к проверке после 10 минут; положительная стоимость без пригодного ответа записывается как оплаченный неуспешный вызов.

## Нужно от интегратора
- Зарегистрировать POST-маршрут по контракту `docs/modules/E0-05B.md` и открыть задачу на русский операторский экран с действиями и состояниями.
- Проверить доступность провайдерских ID для старых неопределённых вызовов; без ID не освобождать их автоматически.
