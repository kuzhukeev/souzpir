# SP-E1-08C · Восстановление смены контекста

Выход и смена бренда сохраняют receipt и позволяют получить исходный результат после отзыва сессии без доступа к приватным данным. Повтор после reload сохраняет исходный ключ и цель переключения. Обновлены типы маршрутов. Перед повторной сдачей влит актуальный origin/main.

Проверки: E1-08/context-recovery Chromium — 2/2; LogoutReceiptTest и BrandSwitchReceiptTest — 4/4; два адресных SessionIdempotencyTest для receipt после revoke — 2/2. Pint, ESLint, TypeScript и npm build пройдены при исходной сдаче. Общий Product suite не запускался по правилу адресных тестов.
Скриншоты: `.local/screenshots/e1-08c/logout-retry-1440.png`, `.local/screenshots/e1-08c/brand-retry-1440.png`.
Ограничения: лог browser (3) CI 41548394464 GitHub API не выдаёт без авторизации (403). Три теста двух процессов из общего SessionIdempotencyTest локально упали из-за запрета записи во временный каталог Windows; адресные тесты receipt зелёные.

## Техдолг
- После потери ответа выхода и перехода на страницу входа старый маркер остаётся до повторного входа; приватные страницы закрыты.

## Принято по умолчанию
- После reload повтор запускается нажатием пользователя. Новая сессия с изменившимся XSRF очищает ключ незавершённого выхода.

## Нужно от интегратора
- Если browser (3) останется красным после слияния main, проверить CI-артефакт и выделить конкретный тест; публичный API отдаёт только этап browser smoke.
