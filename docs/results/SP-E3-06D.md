# SP-E3-06D — защищённая симуляция Seller

- Job по умолчанию выполняет RuntimeSimulation через внутренний fake runtime; явный выключенный флаг сохраняет прежний режим.
- Open создаёт изолированный по бренду диалог с приветствием из настроек; turn использует защищённые claim и finalizer Seller, сохраняет ответ в trace.
- Для open/turn применены ключи идемпотентности, проверка job-контекста, бренда и метки симуляции.
- Тесты: 8 точечных PHPUnit, 50 проверок; Pint. Внешние HTTP-вызовы запрещены тестом.
- Скриншоты: нет новых экранов, изменён только фоновый сценарий.

## Ограничения
- Первый ответ берётся из настроек приветствия. Сессионные extractor/guard/responder первого входящего сообщения не используются в job-контексте.

## Остаток
- Для полного прохождения первого сообщения через защищённые стадии Seller нужен job-вход в FirstTurnCoordinator и его зависимости. Это предлагается отдельной задачей со scope общего ProtectedOperations.

## Техдолг
- Диалоги симуляции сохраняются в общей таблице и различаются меткой в сообщениях; отдельного фильтра в экране диалогов пока нет.

## Принято по умолчанию
- Новый runtime включён по умолчанию; явный выключенный флаг сохраняет старую запись готовых ходов.

## Нужно от интегратора
- Завести продолжение для первого защищённого хода с расширенным scope, если требуется полный первый extractor/guard/responder в фоне.
