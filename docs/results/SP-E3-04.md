# SP-E3-04 — результат

Подготовлены tenant-scoped модели контактов, каналов, настроек, диалогов, сообщений, задач, отзывов и turn; PostgreSQL FK, enum/check, per-channel inbound dedupe, безопасное хранение credentials, repository с атомарными claim/version/commit и транзакционным outbox. Контракт, поля, семантика и интеграционные ограничения описаны в `docs/modules/E3-04.md`. У каждого входа возможна одна обработка, для повторной попытки runtime должен явно разрешить отдельную операцию, не генерируя незаметно новый ключ.

Проверки: отдельная PostgreSQL test БД; миграции up/down в `ConcurrentClaimTest` с DatabaseMigrations; тесты isolation, nullable FK, входных событий и различия payload, повторов и конфликтов claim, отката state/messages/outbox, секретов и назначений. Два отдельных PHP-процесса одновременно запрашивают один turn: один получает `claimed`, второй — `in_progress`, создаётся ровно одна запись. Исходящие сообщения и LLM в тестах не вызываются. Полный PHP-набор: 116 тестов, 840 проверок; Pint выполнен по scope задачи.

Ограничения: data layer не предоставляет UI или API и не исполняет runtime/доставку; screenshot не применим. Для зависшего processing нет автоматического восстановления, для секретов нужен корректный менеджмент APP_KEY и сроков хранения. Не реализованы интеграции каналов и настройки UI. Синтетические тесты не доказывают эквивалентность реальному LLM-run. Перед использованием E3-03B должен применить runtime defaults LeadState и трактовать `externalEventId` как внутренний ULID, см. контракт модуля.
