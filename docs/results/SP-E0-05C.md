# SP-E0-05C — результат

Подготовлена самостоятельная неизменяющая запрос fail-closed граница для применения после существующего ContactMasker и до резервирования ai_calls/драйвера. Проверяются quoted local-part и domain literal через отказ при остаточном @, Unicode NFKC, fullwidth, Unicode-пробелы/тире, HTML/percent/Unicode/hex/octal escapes, вложенные массивы/JSON/tool arguments, часть распространённых разрывов; короткие номера с явной подписью и составные фрагменты проверяются отдельно.

На изолированной тестовой PostgreSQL профиль: 75 тестов / 159 проверок; есть сквозной тест последовательности ContactMasker → ContactBoundary → настоящий Gateway с Http::fake, нулём ai_calls и нулём отправок при отказе, а также позитивный вызов с замаскированными email/телефоном. Все реальные внешние запросы запрещены test fake. Расширенный прогон с тестами AI Gateway перед последним уточнением валидации структуры: 80 тестов / 246 проверок, включая конкурентные сценарии. В отдельном процессе с zend.exception_ignore_args=0 проверены полный текст исключения, getTrace и отсутствие предыдущего исключения.

Интегратор должен подключить границу к Gateway после ContactMasker и до reserve, скрыть чувствительные параметры и заново проверить реальные Gateway/Extractor пути. До merge и до фактического подключения live не разрешать. Ограничения, ложные срабатывания, необходимость consent и невозможность доказать распознавание любых семантически закодированных данных указаны в docs/modules/E0-05C.md.

Повторная проверка: закрыты варианты user at example.test, user AT example.test, user собака example.ru и телефоны с разделителями | и запятая. Исправлен тест: исключения Gateway не считаются отказом защитной проверки.

При повторной проверке добавлены защиты от разделителей [dot], (dot), [.] в доменной части и ; или : в телефонах. Обычные тексты с временем и короткими числовыми списками остаются допустимыми. Длинные числовые списки могут считаться неоднозначными и отклоняться.

Повторная проверка скорректировала обработку ; и : так, чтобы расписания и цены не принимались за телефоны; телефоны заданной структуры и явно обозначенные номера по-прежнему отклоняются. Добавлено обнаружение адресов с пробелами вокруг точки домена. Произвольные номера неизвестной структуры с ; или : не гарантированно распознаются; это общая граница синтаксического подхода.

Исправлена обработка числовых групп: списки цен и размеров вида 1000, 2000, 3000 и 1 000, 2 000, 3 000 сохраняются; блокируются проверенные телефоны +7;999;1234567, +7:999:1234567 и +7;999;123;4567. Старые регрессии сохранены. Списки с группировкой, неотличимой от телефонной, могут отклоняться.
