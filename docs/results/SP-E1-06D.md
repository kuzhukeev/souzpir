# SP-E1-06D — достоверное время последнего входа

## Реализовано

Событие `SessionRegistered` сохраняет только идентификатор пользователя и UTC-время завершённого интерактивного входа, включая MFA. Неуспешный вход и последующая активность сессии время не меняют. Интерактивный вход с установленным «запомнить меня» учитывается; восстановление сессии только по remember-cookie — нет. Старая история не восстанавливается. Ошибка записи или отсутствие миграции не прерывает вход: необязательная операция выполняется в отдельной транзакции/savepoint.

Текущая реализация Auth различает эти случаи по `auth_session_registry.remember_fingerprint`: `issue()` создаёт запись без fingerprint, а `issueRemembered()` — с ним. Это зависимость от текущего поведения Auth, а не гарантия на случай будущей замены механизма; при его изменении необходимо сохранить эту семантику и соответствующий HTTP-тест.

Чтение `GET /team/member-last-logins?ids[]=<membership ULID>` принимает до 25 различных идентификаторов участников и требует `X-Brand-Revision` (клиент также передаёт `X-Brand-Id`). Активная сессия, текущие организация и бренд, права `team.read` и `view` проверяются внутри защищённой транзакции. Чужие и неизвестные участники дают одинаковый 404; устаревший контекст — 409. Ответ содержит только `revision`, `available` и `members: [{id, lastLoginAt}]`, где дата — UTC ISO 8601 либо `null`. Ошибка запроса к таблице возвращает `available: false`, а не выдуманное отсутствие истории; ответ запрещено кэшировать.

Для подключения интегратором `useMemberLastLogins(ids, brandId, teamBrandRevision)` возвращает `status`, `values` по membership ID и `retry`. `<LastLogin status={status} value={values[id]} />` показывает загрузку, недоступность, «Нет данных» или дату в московском времени. Клиент проверяет контекст и состав ответа, скрывает данные при смене контекста/уходе со страницы и повторно проверяет их; значения не помещаются в persistent storage. Подключение общего Team/Index и проверка конечной компоновки — задача интегратора.

Тестовое окружение использует отдельные storage, cookies и очередь, `MAIL_MAILER=array`; внешние HTTP-запросы запрещены/подменены.
- `artisan test tests/Feature/Shell/MemberActivity` — **8 тестов, 136 утверждений**: реальный login/MFA, неверный пароль и MFA, повторный вход, remember-cookie через независимые HTTP-процессы, отсутствие истории, tenant/role/session/brand, ошибки и отсутствие таблицы.

Это визуальная проверка отдельного компонента, не интеграция общего экрана и не тест настоящего API. Просмотрен `.local/screenshots/e1-06d/last-login-neutral-390.png`.
- TypeScript `npm run typecheck`, scoped ESLint и Pint — успешно. Живые письма, AI и иные внешние отправки не выполнялись.

## Ограничения

Исторических значений до миграции нет. При отказе хранилища чтение показывает «Недоступно»; при восстановлении нужно повторить запрос. Запись при ошибке намеренно пропускается, чтобы не блокировать вход. Полная браузерная проверка встроенного в Team/Index компонента возможна только после подключения интегратором. Для свежести и сокрытия данных при длительных сетевых запросах клиент периодически перепроверяет доступ и очищает показанные значения при потере актуальности.
