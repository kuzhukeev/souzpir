# SP-E1-02: результат

Сделаны защищённый organization-only контекст для владельца, четыре адаптивных шага, серверный черновик, валидация и атомарное завершение с единственным первым брендом и audit. Повтор с теми же данными не создаёт дубликат и не переключает выбранный бренд; другие данные отклоняются. Две вкладки с незавершённым черновиком пока сохраняют данные по правилу последней записи. Если настройка завершена в другой вкладке, страница запрашивает актуальное состояние сервера по событию и при возвращении на вкладку.

После завершения или при наличии ранее созданного бренда доступен переход в `/auth/ready`; ссылки модулей появляются только для зарегистрированных GET и `modules.<модуль> === true`. Выбор модулей при онбординге — предпочтение, не подтверждение подключения. Реализована приватная загрузка/замена PNG, JPEG и WebP с проверкой содержимого, размера и разрешения и нормализацией в PNG; SVG отклоняется. Сетевая проверка сайта не выполняется до защищённого пути E8-01B. Контракты, блокировки и ограничения описаны в `docs/modules/E1-02.md`.

Проверки на отдельной PostgreSQL test-БД: 17 тестов онбординга / 162 assertions, включая двухпроцессную конкуренцию одинакового и разного payload. Оба worker подтверждённо ждут блокировку организации в PostgreSQL; результаты create/replay или create/conflict, один бренд и одна audit-запись. Ранее совместный профиль onboarding + tenancy + auth: 53/411. `npm run typecheck`, `npm run lint`, `npm test -- --run` 83/83, `npm run build`, Pint. Статический UI Playwright 14/14 (1440/1024/390, axe WCAG 2 A/AA, состояния и ошибки); живой Laravel/PostgreSQL Playwright 1/1: вход, черновик, reload, два сохранения логотипа, завершение, синхронизация второй вкладки и reload. Без `RUN_ONBOARDING_E2E=1` живой сценарий корректно пропускается. Внешние HTTP/LLM/mail не вызывались. В этой ветке тесты проведены на исходной конфигурации PostgreSQL; интегратор повторит совмещённый прогон с UTC-конфигурацией main.

Команды для CI после `npm run build` (используются уже собранные CSS и шрифты, Vite dev не запускается):

```bash
npx vite build --config vite.layout.config.ts
npx vite build --config tests/Browser/E1-02/vite.config.ts
php -S 127.0.0.1:5183 -t .local/runtime/layout-fixture &
E102_FIXTURE_ENABLED=1 E102_FIXTURE_ORG=01J00000000000000000000002 \
  CABINET_ORGANIZATION_ID=01J00000000000000000000002 \
  php tests/Browser/E1-02/prepare-fixture.php
CABINET_ORGANIZATION_ID=01J00000000000000000000002 APP_URL=http://127.0.0.1:8102 \
  APP_INSTANCE=ci-e102 SESSION_COOKIE=ci_e102_session \
  php artisan serve --env=testing --no-reload --host=127.0.0.1 --port=8102 &
# Дождаться HTTP-готовности обоих серверов.
RUN_ONBOARDING_E2E=1 npm run test:browser
```

Все команды используют `APP_ENV=testing`, `DB_DATABASE=DB_TEST_DATABASE` с `_test_` в имени и БД, отличную от `APP_PREVIEW_DATABASE`. Fixture выполняет обычную миграцию, проверяет уникальные маркер организации и синтетический email, атомарно очищает только собственные записи и отказывается продолжать при конфликте; `migrate:fresh` отсутствует. Условия для сторонних browser suites не меняются. URL можно задать `ONBOARDING_FIXTURE_URL` и `ONBOARDING_BASE_URL`; 5183/8102 — CI defaults. В рабочей среде локальный статический сервер занимал 5185, так как 5183 был занят другим worktree.
