# SP-C-02 — рабочая часть

- Внутренний fake-координатор направляет отказ Guard и остановленный результат на ручную проверку вместо оставления хода в processing.
- Проверка действующей сессии и бренда, карантин и audit выполняются существующим механизмом; повтор не запускает ИИ и не дублирует запрос.
- Тесты: адресные сценарии FirstTurnStateTest на отдельной PostgreSQL с fake; реальных вызовов нет. UI и скриншоты неприменимы.
- Остаток: production runtime, защищённые действия create_promise, последующие ходы и потребитель сессии; предложить отдельные задачи после интеграции.

## Техдолг
- При недоступности audit или утрате полномочий постановка на проверку откатывается; требуется повтор оператора.
- Одновременные изменения остаются предметом отдельной проверки интегратора.

## Принято по умолчанию
- Отказ Guard передаётся оператору как неопределённый ход, без утверждения об отсутствии внешнего эффекта.

## Нужно от интегратора
- Разбить оставшуюся защищённую запись и подключение потребителей на отдельные задачи.
