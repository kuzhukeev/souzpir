# SP-E0-05: ИИ-шлюз

Реализованы контракт AiGateway и DTO, учёт в ai_calls/ai_budgets/object_costs, ai_providers и prompt_sets; tenant/object isolation, маскирование, active/planned provider catalog, fake/record/OpenRouter, идемпотентность, безопасные резервы и сверка неопределённых исходов. Шесть промптов прототипа скопированы без изменений и проверены по SHA-256. Пороговые уведомления подключаются через транзакционный outbox E0-04, когда явно задан порог.

Проверки: изолированный PostgreSQL `souzpir_test_sp_e0_05`; feature-набор 24 теста / 121 проверка, в том числе два отдельных процесса для конкурирующих бюджетов и для одинакового ключа; timeout не повторяется, 429 повторяется только как явный отказ, overspend учитывается, uncertain удерживает резерв. Тесты OpenRouter используют только Http fake. Полный PHP-suite в базовом worktree: 92 теста / 480 проверок до двух последних локальных тестов. Интеграция с временно подключённым уже объединённым E0-04 при включённых config/route cache: 23 теста / 121 проверка до последней проверки маскирования схем; outbox-копии после теста удалены из рабочей ветки.

Живые вызовы по умолчанию выключены и не проверялись; нет утверждённых коэффициентов, цен или порогов. Для live бюджета требуется обоснованная оператором верхняя оценка для ограниченных размеров запроса. Операторская UI-процедура сверки/снятия breach находится вне задачи. Скриншот не применим: отдельного экрана эта задача не создаёт.
