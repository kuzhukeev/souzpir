# SP-E0-05: ИИ-шлюз

Реализованы контракт AiGateway и DTO, учёт в ai_calls/ai_budgets/object_costs, ai_providers и prompt_sets; tenant/object isolation, маскирование, active/planned provider catalog, fake/record/OpenRouter, идемпотентность и удержание неопределённых резервов. Шесть промптов прототипа скопированы без изменений и проверены по SHA-256. Пороговые уведомления подключаются через транзакционный outbox E0-04, когда явно задан порог.

Проверки: изолированный PostgreSQL `souzpir_test_sp_e0_05`; feature-набор 24 теста / 121 проверка, в том числе два отдельных процесса для конкурирующих бюджетов и для одинакового ключа; timeout не повторяется, 429 повторяется только как явный отказ, overspend учитывается, uncertain удерживает резерв. Тесты OpenRouter используют только Http fake. Полный PHP-suite в базовом worktree: 92 теста / 480 проверок до двух последних локальных тестов. Интеграция с временно подключённым уже объединённым E0-04 при включённых config/route cache: 23 теста / 121 проверка до последней проверки маскирования схем; outbox-копии после теста удалены из рабочей ветки.

После review закрыты риски внешней транзакции, сверки работающего запроса, повторного использования ключа между драйверами, контактов в ключах вложенных структур и JSON-аргументов, размера фактического тела HTTP и конкурирующих retry одного parent. Внешняя транзакция блокируется до записи и сети; для retry добавлен уникальный индекс. `reserved` и `uncertain` не освобождаются по непроверенному тексту или результату: авторизованная процедура с проверяемым подтверждением провайдера ещё требуется. Вызывающие должны запускать `complete` после commit.

Повторные проверки после исправлений: изолированный PostgreSQL `souzpir_test_sp_e0_05`, `tests/Feature/Ai` — **31 тест / 149 проверок**, включая три двухпроцессных сценария, имитацию сверки во время HTTP и границу фактических байтов Anthropic. Pint для изменённых PHP-файлов — PASS. Live HTTP в тестах подменён. Интеграцию порога с E0-04 следует повторить после объединения с текущим main.

Дополнительная проверка приватности закрыла произвольные ключи сообщений, некорректный тип `tool_calls`, JSON Unicode-экранированные контакты и объекты в данных: небезопасные значения отклоняются до резерва и отправки. Повторно весь AI-набор: **33 теста / 160 проверок**, live HTTP подменён.

Живые вызовы по умолчанию выключены и не проверялись; нет утверждённых коэффициентов, цен или порогов. Для live бюджета требуется обоснованная оператором верхняя оценка для ограниченных размеров запроса. Операторская UI-процедура сверки/снятия breach находится вне задачи. Скриншот не применим: отдельного экрана эта задача не создаёт.
