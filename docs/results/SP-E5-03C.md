# SP-E5-03C — частичная реализация API-канала

- Сохранены прежние коммиты и ссылка настроек на журнал ошибок; при включении main объединён список входящих с ссылкой.
- POST /api/v1/turn принимает conversation_id, text и Idempotency-Key: проверенный brand-токен, права и активный модуль; сервер сохраняет вход, вызывает существующий защищённый follow-up finalizer и fake-доставку. Повтор возвращает прежний ответ.
- Проверен маршрут: карточка через API → менеджер начинает и возвращает диалог боту → fake-ход; также повтор и конфликт, чужой бренд, отсутствие права, отзыв токена, ошибки и отказ не-fake runtime. Журнал не сохраняет токен и текст.
- Проверки: API PHPUnit 6 тестов / 99 проверок; SellerRuntime/Turns 4 / 62; TypeScript, ESLint, Vite build, Pint. Изолированная PostgreSQL `souzpir_test_e503c`; живых вызовов не было.
- Скриншот light 1440: `.local/screenshots/SP-E5-03C/api-1440.png` (UI-фикстура).

## Остаток
- action=open остаётся 503: защищённый runtime пока не имеет token-входа для первого исходящего хода без клиентского сообщения. Нужны сохранение, Policy/Guard и проверка без подставной сессии; не выдавать обычную запись приветствия за запуск продавца.
- API-ходы доступны только для начатого диалога в режиме bot при автономном расписании; режимы suggest/manager и выключенное расписание пока возвращают 503.
- FollowupFinalizer выдаёт существующий фиксированный fake-ответ; полноценная генерация через защищённые AI-стадии и живые вызовы не подключены.
