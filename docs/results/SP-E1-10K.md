# SP-E1-10K — автоматические вебхуки и общие уведомления

- S-5.2/S-5.3: базовая приёмка (снимок подписок, outbox+очередь, fake-транспорт с подписью и повторами, матрица общих уведомлений, код Telegram) закрыта ранее SP-E1-10H/I/J (`docs/release/2026-11-09-remaining.md`); подтверждено прогоном их тестов (WebhookSnapshotE110JTest, CompanyNotificationQueueE110JTest, CompanyTelegramE110JTest, FakeWebhookQueueE110JTest, FakeTimingErrorsE110JTest — все зелёные), новых изменений по этим пунктам не потребовалось.
- Дополнение 07.11.2026 (реестр S-7.1, D-10.3): `config/runtime.php` — `notification_driver` получил default `fake` (как `ai_driver`/`delivery_driver`); проверено: в окружениях без `NOTIFICATION_DRIVER` тихие часы/сводка (S-7.1, `NotificationTimingDraftTest`, `ProfileSettingsTest`) и переключатель напоминаний (D-10.3, `PlannedTest`) теперь доступны по умолчанию, `DrainNotifications` обрабатывает fake-очередь без лишних флагов. Сверено с макетами S-7.1 (`31/94e5477d`) и D-10.3 (`158/5c6b22a0`) — тумблер напоминаний и блок «Тихие часы»/«Сводка» должны быть активны, текущий UI уже реактивен на `reminders.available`/`timingAvailable`, правок вёрстки не потребовалось.
- Побочный эффект: с новым default'ом общий вебхук-обработчик (`OutboxDispatcher`→`ProcessFakeWebhookEvent`) начал автоматически отправлять «сырую» (немаппленную) копию тестового CRM-события параллельно с собственной CRM-доставкой с полями. Исправлено в `app/Seller/Channels/Crm/CrmFakeDelivery.php`: синтетическое тестовое событие сразу помечается consumed для консьюмера `integrations.webhooks.v1`, маппинг остаётся единственной доставкой (проверено: `CrmMappingsE609DTest`).
- Поправлены тесты, которые полагались на старый default (не-fake) как на «отключённое» состояние: `PlannedTest`, `NotificationTimingDraftTest`, `ProfileSettingsTest`, `NotificationRoutingTest`, `NotificationCoreTest`, а также смежный модуль `Seller/Settings/Limits` (`NotificationsTest`, `DigestTest`, `PersonalDigestTimeTest`) — тесты «боевого» драйвера (digest/внешняя доставка) явно включают `runtime.notification_driver => null`, чтобы не терять покрытие этого пути.
- Тесты: проверено — `php artisan test` по scope задачи + смежным файлам, затронутым сменой default: 84 теста зелёных (`PlannedTest`, `ContactReminderTest`, `NotificationTimingDraftTest`, `ProfileSettingsTest`, `CrmMappingsE609DTest`, `CrmFakeDeliveryTest`, `NotificationRoutingTest`, `NotificationCoreTest`, `NotificationsTest`, `DigestTest`, `PersonalDigestTimeTest`). Отдельно прогнаны широкие наборы `tests/Feature/Shell/Notifications`, `tests/Feature/Shell/Integrations`, `tests/Feature/Shell/Profile`, `tests/Feature/Seller/Channels/*`, `tests/Feature/Seller/Settings/Limits` — без новых падений. `composer lint` (Pint) зелёный.
- Не менял .tsx/фронтенд — экраны уже управляются серверными флагами `available`/`timingAvailable`.

## Техдолг
- На слоте exec-2 тесты с `IsolatedDatabaseMigrations` (в т.ч. `ProfileFeatureGateTest`, `OutboxDeferralTest`, race-группа) падают с «A dedicated, nonprivileged test database owner is required» — проблема окружения слота, не связана с этой задачей; воспроизводится и без моих правок.
- Старые outbox-события без снимка подписок по-прежнему не доставляются автоматическим вебхукам (известно по SP-E1-10J).

## Принято по умолчанию
- `notification_driver` по умолчанию `fake` везде, где явно не задан `NOTIFICATION_DRIVER` — включая `.env.example`; боевой драйвер по-прежнему включается только явной переменной окружения.
