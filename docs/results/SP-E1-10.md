# SP-E1-10 — промежуточный результат

Статус: реализация не прошла полную приёмку. Не считать задачу готовой к интеграции до устранения блокирующих контрактов ниже.

## Что выполнено

- Страница подключений читает `channel_accounts` в текущей организации и бренде; незавершённые каналы отмечены «Скоро».
- Ключи бренда: создание, SHA-256 хеш, маска, выбранные abilities, отзыв, проверка прав и аудит. Ключ создаётся, но ещё не обслуживает запросы `/api/v1/*`; интерфейс прямо предупреждает об этом.
- Вебхуки: HTTPS, словарь пяти событий из registry, зашифрованный секрет, HMAC, изоляция по бренду, аудит, не более десяти строк истории. Для доставки проверяется публичный DNS, IP фиксируется на время запроса, redirects запрещены. Отправка по умолчанию выключена; зарегистрирована независимая команда `integrations:webhooks-drain` без запуска по расписанию.
- Одноразовые секреты не передаются в Inertia props: POST `integrations/api/secrets` под блокировкой сессии выдаёт секрет один раз для исходного actor/organization/brand и только при `integrations.write`; ответы no-store.
- Экран корпоративных уведомлений честно отключён, поскольку действующий runtime не обслуживает этот сценарий.

## Проверки

- Изолированный PostgreSQL 16 в `.local/runtime/postgres`, loopback 127.0.0.1:56410, отдельная база `souzpir_test_sp_e1_10`; основная рабочая база и чужие worktree не использовались. Отдельный `.env.testing`, AI/delivery fake, mail log, scheduler отключён.
- `phpunit tests/Feature/Shell/Integrations --display-phpunit-notices`: 18 тестов, 160 assertions; включая тест настоящего commit/rollback, `Http::fake`, подпись, 5 попыток, отказ внутренних IP, audit, права, разделение брендов и однократную выдачу секретов.
- `npm run typecheck`, `npx eslint resources/js/pages/Shell/Integrations`, `npm run build`, `pint` для PHP этой задачи, `artisan route:list --env=testing --path=integrations`: успешно. Vite предупреждает, что шрифты будут разрешены по публичному пути во время исполнения; файлы шрифтов присутствуют в `public/fonts`.
- Реальных писем, LLM, Telegram или вебхуков не отправлялось; HTTP в тестах подменён и посторонние запросы запрещены.

## Запрос интегратору — блокеры полной приёмки

1. Владельцу bootstrap/tenancy/API: предоставить установленный и совместимый Sanctum (общие composer manifest/lock принадлежат другому владельцу), guard `auth:sanctum`, `tenant.token`, проверку abilities и согласованную поддержку tokenable=Brand. Сейчас `FeatureRegistry` ссылается на отсутствующие guard/alias, E5-03 ещё не реализован. Нужно проверить настоящий endpoint `/api/v1/leads`: отсутствие `leads` → 403; отозванный ключ → 401. В scope SP-E1-10 менять общий bootstrap/модели/lock нельзя.
2. Владельцам E0-04/E3-04/E5-01: согласовать брендовый storage для Telegram-чата и почтовых адресатов, company-recipient delivery/outbox и проверяемый challenge/inbound Telegram flow. `channel_accounts` запрещает тип `telegram_notify`; личные `notification_settings`/`notification_deliveries` требуют user_id, а их runtime доставляет только личным адресатам. Контракт `notifications.router` уже занят E6-07. Нужен реальный тест `seller.conversation.handed_off` → чат компании и передача докладов, а не искусственная отправка или неиспользуемые настройки.
3. Выделить операторский механизм запуска `integrations:webhooks-drain` или согласованный subscriber для committed outbox. Только включения флага доставки недостаточно. При аварии после установки статуса `sending` исход неопределён; автоматическое восстановление не реализовано. Для внешних вызовов нужно отдельное операторское разрешение.
