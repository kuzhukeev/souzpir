# SP-E1-10 — результат

- Зашифрованный секрет API-ключа сохраняется в сессии до показа, истечения квитанции или смены бренда; в базе ключа остаётся только SHA-256.
- Пока секрет доступен, повторное создание блокируется с подсказкой; после показа или отзыва можно создать новый ключ.
- Секрет привязан также к ревизии выбора бренда; POST выдаёт его однократно.
- Проверки: PHPUnit Keys/ApiKeysTest и SecretSecurityTest — 28 тестов, 197 проверок; Pint и git diff --check.
- Расширенная группа: 59 тестов, 4 пропуска, один тест требовал обновления фикстуры ревизии; исправленный тест прошёл в адресном прогоне.
- Скриншот не получен; визуальное изменение — текст подсказки и блокировка кнопки создания.

## Техдолг
- При потере сессии или истечении квитанции непоказанный ключ остаётся активным; его можно отозвать и создать новый.

## Принято по умолчанию
- Перевыпуск выполняется отзывом старого ключа и созданием нового, без автоматического отзыва.

## Нужно от интегратора
- Карточка целиком не завершена: API диалогов и лидов, внешние вебхуки, корпоративные Telegram и почта остаются недоступны; потребуются владельцы соответствующих runtime и контрактов.
- Учесть, что ранее созданный до этого изменения непоказанный секрет после обновления требуется перевыпустить.
