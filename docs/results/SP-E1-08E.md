# SP-E1-08E — тихие часы и сводка в доставке (остаток 08.11)

Макет: `/opt/contour/data/mockups/31/94e5477d-S-7.1-notifications.webp` (S-7.1); скриншот `.local/screenshots/SP-E1-08E/notifications.png` (1440, светлая).

## Сделано
- `ExternalDelivery` (боевой путь email/Telegram, не fake): перед отправкой учитывает личные тихие часы и сводку пользователя для бренда (`profile_notification_timing_drafts`, пояс — из профиля, иначе бренда). Событие в тихие часы получает статус `deferred` («Отложено») и уходит после их окончания; при включённой сводке события копятся и уходят одним сообщением «Сводка уведомлений: N» со списком — отдельно по бренду, пользователю и каналу. Проверки прав/настроек выполняются для каждого события сводки. — проверено: QuietHoursDigestE108ETest (4 теста).
- `notifications:drain` в боевом режиме вызывает `ExternalDelivery::drain()` (отложенные + pending); `NotificationMail` умеет список пунктов сводки. Миграция `E1-08E` добавляет статус `deferred`.
- Экран: `timingAvailable=true` при готовой схеме (не только fake), без бейджа «Тестовая доставка»; форма `TimingDraftForm` — переключатель «Сводка вместо каждого события: раз в день в 09:00» с пояснением как на макете, «Сохранить настройки» неактивна без изменений. — проверено: Playwright `tests/Browser/E1-08E` (2), E1-08D/G/H/I/J (4), vitest Profile (9).
- Доставка только через fake: Http::fake для Telegram, боевые каналы не включались.
