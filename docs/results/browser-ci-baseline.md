# Браузерные фикстуры CI: E1-01, E1-05, E8-02, E8-03

Интеграционная ветка подготовлена от `fd7b844`. Общий workflow поднимает отдельные локальные серверы и пять тестовых PostgreSQL-баз с отдельными непривилегированными ролями. Режимы обычного и локального HTTP E8-02 используют разные базы и порты, поэтому их можно проверять одновременно. Тесты не исключены, существующие проверки не ослаблены. Chromium берётся из установки Playwright; для локальной проверки разрешено явно указать исполняемый файл.

Перед миграциями и стартом сервиса `scripts/ci/assert-browser-database.php` сверяет фактическую базу, пользователя, адрес, порт и привилегии, checkout и preview-настройку. Фикстуры, выполняющие запись, дополнительно проверяют своё окружение. Тестовый router E8-02 перед переключением режима синхронизирует проверенную конфигурацию во все источники окружения и повторно сверяет фактическое подключение Laravel. Непустой `DB_URL`, несоответствия и кеш конфигурации закрывают сценарий. Адрес `SERVER_ADDR`, отсутствующий у встроенного PHP-сервера, восполняется только в CI test router при явном opt-in; скрипт запускает такой сервер строго на `127.0.0.1`. Это тестовое допущение и не проверка безопасности production-прокси или TLS.

На отдельном PostgreSQL 16, Windows 11/Git Bash и установленном Chrome прошли **107 браузерных тестов** в четырёх воркерах (тесты E1-01 invitation, E1-05, E8-02 и E8-03), включая настоящий локальный HTTP и два отдельных сценария анкеты. Проверены запуск всех восьми процессов, предварительная сверка баз, отрицательные случаи с несовпадением роли и preview, непустой `DB_URL`, PHP lint, Pint, ESLint, TypeScript, production build и `bash -n`. Живые внешние отправки не выполнялись. Пример успешной проверки: `.local/screenshots/e8-02/local-http.png` (синтетические данные; файл вне Git).

Во время первичной диагностики ранняя версия локального test router после проверки фиктивных параметров подставила значения из `.env.testing` и предприняла попытку подключения к `souzpir_dev`; сервер ответил `no password supplied`, запись не выполнялась. Router немедленно остановлен и после исправления повторно проверен на отдельном тестовом кластере. Этот случай не скрыт и требует внимания при интеграционном ревью.

На этой машине WSL/Linux не установлен: реальный Linux/GitHub Actions прогон не выполнен. Успешный Windows/Git Bash прогон не доказывает работу Docker service и скачанного Playwright Chromium в Linux. Общий браузерный workflow включает и другие существующие сценарии и opt-in ограничения; полный набор в данной работе не выполнялся. После ревью требуется настоящий CI-run без исключения тестов и анализ его полного результата.
