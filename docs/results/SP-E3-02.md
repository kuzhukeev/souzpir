# SP-E3-02 — результат

Перенесены Policy, LeadState, Goal и Extractor из Laravel-прототипа с адаптацией к KnowledgeSnapshot, prompt_sets и AiGateway. Выполнение неизвестного Blade из базы запрещено, пустое/неверное значение JSON проходит проверку схемы и исходный fallback. Контракт для E3-03B и ограничения указаны в docs/modules/E3-02.md.

Проверки на физически отдельном vendor и PostgreSQL `souzpir_test_sp_e3_02`: оригинальные 11 PolicyTest (28 проверок), сохранённые синтетические сценарии донора (83 сравнения), пять неизменённых эталонных снимков промпта, нормализация/валидатор/fallback, tenant и forged-template проверки. Настоящий AiGateway с fake driver проверен по пути prompt → запрос → ai_calls/object_costs → идемпотентный повтор; HTTP ничего не отправил. После исправлений review полный набор: 206 тестов, 1473 проверки; после последней корректировки CI worker и формы fallback профильный набор: 25 тестов, 229 проверок. Pint выполнен. Отдельная рабочая и тестовая БД используют ограниченную роль, без доступа к базам main.

Фактические LLM и доставки не запускались. Это инфраструктура без UI; screenshots не применимы. Пользовательские шаблоны, выбор фактической конфигурации и привязка опубликованного релиза к turn требуют последующей интеграции; синтетические трассы не доказывают равенство реального LLM-run. Shared dependency Opis 2.6 добавлена интегратором в main коммитом df89d72; в ветке задачи manifest и lock не менялись.

После независимого review: Factory и Extractor получают проверенный published release из tenant-scoped KnowledgeRepository, опубликованный prompt повторно загружается по tenant/version. Введены обязательные классы данных, состояние ожидания/неопределённости без fallback, устойчивая типизация ответа, проверка intents и локальное восстановление email. Проверены запрет внешней передачи политикой, маскирование через настоящий Gateway и конкурентный запрос с одним fake provider вызовом. Номер телефона не является слотом донора и требует отдельной локальной обработки в E3-03B.
Дополнительно после полного прогона: сквозные проверки настоящего Gateway/fake driver для нескольких вариантов email и телефонной маски, а также конкурентной гонки — 2 теста / 33 проверки.
