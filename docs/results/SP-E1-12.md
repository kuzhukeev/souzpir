# SP-E1-12 — помощь и обращения

Ветка `codex/sp-e1-12`, base claim `e332dabf4d2444be6cdc63cd332080fab67c1c2b`, отдельный worktree и изолированная тестовая база. Результат передаётся на review; интеграцию выполняет основной чат.

## Результат

Реализованы страницы `/help`, `/help/support`, `/help/status`: разделы помощи и поиск по настроенной базе; собственные обращения с валидацией, приватными вложениями, уведомлением, аудитом и согласиями на 72 часа; статус приложения/БД и честные unknown-состояния для неподключённого мониторинга. Согласие отзывается и истекает по серверному времени, однако не предоставляет вход сотруднику поддержки: механизма идентификации сотрудника в проекте нет.

SMTP по умолчанию отключён и включается только явной настройкой транспорта и адреса. Письмо формируется после commit, успешным считается только подтверждённый receipt; неопределённая доставка отображается как uncertain. Путь к вложениям не публикуется: доступ проверяет собственника обращения и сессию, ответ attachment/no-store/nosniff. Реальных отправок не было.

## Ограничения и интеграция

1. Приёмка «все роли могут написать» пока не выполнена для viewer: общий `ResolveTenant` блокирует POST. Нужны исключения для двух own-support routes и соответствующее разрешение module policy с тестами на чужие данные и другие viewer mutations. Исключение из guard не обходилось внутри модуля.
2. Доступ сотрудника поддержки в чужой кабинет отсутствует по существующему контракту. Согласие реально сохраняется и истекает, но `entry_available=false`. Future access mechanism должен проверять staff identity, scope давшего согласие и актуальный TTL/отзыв на каждом запросе.
3. AI Gateway не публикует read projection cooldowns, а источников мониторинга компонентов и истории инцидентов нет. Fake cooldown adapter проверяет только отображение и истечение в проекции. Требуется adapter владельца AI и реальные read sources; отсутствие cooldown не выдаётся за работоспособность провайдера.
4. Вложения приватны и в почтовое уведомление не включены; механизм просмотра сотрудником, ответы и закрытие обращения требуют будущего support adapter. При выключенном или не настроенном SMTP обращение сохраняется локально, а UI честно сообщает, что письмо не отправлено.
5. Интегратору нужно выполнить `php scripts/generate-types/generate.php` и включить изменённые shared types после объединения.
