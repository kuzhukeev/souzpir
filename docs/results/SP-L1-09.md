# SP-L1-09 · Виджет: живой режим черновиков

Сделано:
- `WidgetInboundRuntime::turn()` больше не отвечает `unavailable` при `ai_driver` ≠ `fake` (проверка снята, остался только требуемый Postgres-драйвер).
- В живом режиме ход посетителя всегда идёт по ветке подавления (без вызова `FollowupCoordinator`/бот-пайплайна): сообщение всё равно уходит в диалог через `InboundRecorder::ingest`, турн помечается `suppressed`, автономного ответа ИИ нет ни при `mode=manager`, ни при `mode=suggest`/`bot`. `suppress()` обобщён на список разрешённых режимов вместо жёсткого `manager`.
- Режим нового диалога в живом режиме берётся из `channel_accounts.default_mode` канала (а не всегда `bot`, как в fake); в рабочие часы off → `manager`, как и раньше. Fake-режим не менялся (поведение и миграция веток идентичны прежним).
- Черновик для суджест-режима ставится в очередь существующим глобальным листенером `LV-01` (`QueueLiveDraft` на `eloquent.created: Message`) — отдельного вызова из раннера не требуется; отправка менеджером — существующая кнопка SP-L1-05.
- `resources/widget/widget.js`: при ответе без `reply` показывается «Менеджер скоро ответит.» один раз на ожидание (не повторяется, пока ждём); сбрасывается, когда приходит реальный ответ.

Тесты (проверено):
- `tests/Feature/Launch/L1-09/WidgetLiveDraftTest.php` (3, `Http::fake`/`Queue::fake`): live+suggest → `LiveDraftJob` поставлен, посетитель без `reply`, турн `suppressed`; live+manager → турн `suppressed`, без `reply`, запуск `LiveDraftJob::handle()` подтверждает no-op (режим не `suggest`); fake-режим — бот-ответ как раньше.
- `php artisan test tests/Feature/Launch/L1-09/`: 3 passed. `check lint`, `check frontend` — зелёные.
