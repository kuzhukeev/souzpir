# SP-E5-03 — входящие формы и API
- POST /api/v1/leads принимает bearer-ключ бренда и Idempotency-Key, создаёт контакт и диалог, применяет сохранённое соответствие полей и пишет аудит.
- Повтор того же тела возвращает сохранённый результат; другой body с тем же ключом получает 409. Чужой бренд отклоняется.
- Экран показывает настройки соответствия, пример запроса и последние 20 созданных карточек.
- Проверено: PostgreSQL, 2 теста / 30 проверок, 2 предупреждения Pest; bearer/cookie, права, бренд, повторы и ошибки ввода; TypeScript, ESLint, Pint и типы маршрутов.
- Скриншот: `.local/screenshots/sp-e5-03/api-1440.png` в основном checkout, компоненты с демонстрационными данными, светлая тема, 1440.
- Ограничения: действие open и POST /api/v1/turn возвращают 503; журнал содержит успешные создания, не ошибки.
## Техдолг
- Журнал ошибок API требует отдельного способа записи вне откатываемой транзакции token middleware.
## Принято по умолчанию
- Действие по умолчанию — только карточка; требуется хотя бы имя, телефон или почта. Неизвестные поля игнорируются.
## Нужно от интегратора
- Подключить token-scoped защищённые Orchestrator::open и turn после реализации общего runtime; добавить журнал ошибок отдельным продолжением.
