# SP-E8-02 — старт, анкета и профиль «Видения»

Ветка `codex/sp-e8-02`, исходная база claim `0717518626e518859c99bbe117a3cd1f5488033f`; в ветку обычным merge включён проверенный main с SP-E8-01F. Исполнитель не объединяет результат в main и не ставит задачу done.

## Реализовано

- Старт модуля и восемь шагов: семь сохраняемых разделов и обзор перед отправкой. Сохранение использует настоящий `Questionnaire::saveStep` с optimistic revision; конфликт не перезаписывает чужие данные. Отправка создаёт immutable версию профиля и audit, правка — новую версию. История показывает предыдущую и текущую версии.
- Правила и лимиты конкурентов/фактов/вопросов 10/10/15, с конфигурацией для уменьшения пределов. Пустые факты разрешены. Обязательные данные и синтаксис URL проверяются на сервере без DNS или обращения к сайту.
- Доступ и изоляция опираются на действующие tenant, session lease и `vision.quiz.write` из SP-E8-01F. Приватные страницы не кешируются; одноразовая проверка Web Crypto предшествует выдаче данных, Inertia history шифруется в защищённом контексте; контроллер не передаёт приватные ответы и исходные исключения в логи.
- Для владельца/администратора показывается подсказка из заголовка уже сохранённой audit-подтверждённой страницы сайта, при наличии права `vision.settings.write`. Сетевое сканирование из анкеты не запускается; редактору и при локальной ошибке подсказка недоступна.
- Профиль попадает в version-bound snapshot fake замера через принятый runtime SP-E8-01F; данные анкеты не становятся подтверждёнными фактами и не передаются ИИ без отдельного согласованного разрешения.

## Проверки

- Отдельные PostgreSQL cluster на 127.0.0.1:55490, тестовая база `souzpir_test_sp_e8_02`, роль без административных прав; отдельные storage/cache/cookies и порты. AI/delivery fake, mail log; живые внешние отправки и сетевое сканирование не выполнялись.
- После интеграционного замечания добавлен доступ для `http://souzpir.local` исключительно при `APP_ENV=local` и фактическом loopback-подключении. На локальном HTTP история Inertia не шифруется; стартовая страница предупреждает об этом. Для HTTPS и loopback без исключения по-прежнему выполняется проверка Web Crypto и шифрование истории; поддельный Host с внешнего IP не открывает HTTP-исключение. Проверено на отдельной БД: **16 тестов / 289 проверок**, включая CSRF, spoofed Host, production-отказ и HTTPS. Chrome E2E на `http://souzpir.local:8248` без `crypto.subtle`: вход, начало, сохранение и повторное чтение прошли; скриншот `.local/screenshots/e8-02/local-http.png` просмотрен. TypeScript, ESLint, Vite build и Pint прошли.

## Ограничения и запросы интегратору

- Генерация вопросов и UI наборов принадлежат SP-E8-03; публикации/отчёты — последующим задачам. Полный E2E №2 за пределами доступных сервисов пока не завершён. Интерфейс не показывает фиктивную генерацию и не отправляет данные ИИ.
- Для редакторов и иных подсказок требуется отдельный согласованный read-only контракт с проверкой доступа; сейчас используется только имеющийся приватный site-draft API для ролей с `vision.settings.write`.
- Общая навигация вне scope: в текущем меню отдельного пункта «Анкета» нет, вход осуществляется через `/vision` («Обзор видимости»). Интегратору требуется согласовать и добавить меню с учётом `vision.quiz.write` и ограничений состава меню.
- Одновременное открытие приватных страниц в двух вкладках одной сессии может потребовать повторить открытие: одноразовая проверка работает fail-closed.
- История ограничена последними 100 версиями; для большего числа потребуется пагинация. На рабочем сервере приватная анкета требует HTTPS и Web Crypto. Только на указанном локальном адресе при `APP_ENV=local` история браузера не шифруется; это не предназначено для реальных конфиденциальных данных.
