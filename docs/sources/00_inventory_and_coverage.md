## 3. Что не удалось изучить / ограничения

- Структурные карты «01/02/03 png», на которые ссылается ТЗ §0.2, и референс `image-6.png` (§1.1) в приложенных материалах отсутствуют. Эталон общих элементов взят из папки 13 (`S-1.2-attention`) по указанию пользователя.
- Файл `storage/app/sim/final.json` прототипа (результаты симуляций) открыт частично (структура и первые записи), не весь массив.
- eyon-pilot: не выполнялся запуск приложения и тестов; выводы — по чтению кода. Код `Sales/Seller/*` (собственный упрощённый продавец M3) изучен на уровне состава классов и публичных методов, так как ТЗ §0.3 предписывает заменить его движком прототипа.
- Прототип: тесты не запускались (нет PHP-окружения с зависимостями в песочнице); количество тестов и их содержание — по чтению файлов.
- Шрифт Manrope (`public/brand/manrope-*.woff2` по ТЗ) в eyon-pilot не проверялся побайтно; наличие директории подтверждено.

## 4. Проверка согласованности пакета

После составления документов выполнена программная сверка: все 160 ID экранов ТЗ имеют ответственную задачу в `10_backlog.md` (индекс в конце backlog), номера папок макетов в каждой задаче совпадают с индексом архива, все 70 расхождений `02c` закреплены за задачами, все ID зависимостей определены. Найденные при сверке ошибки (пропуск 5 экранов, смещённые номера папок, ошибочная привязка заметок публичной страницы V-5.P к секциям V-5.1–V-5.9, неверная трактовка ролей А.12) исправлены во всех документах.

## 5. Как была организована проверка

1. Архив макетов распакован, из 308 изображений собраны 154 контактных листа (`sheets/sheet_NNN.jpg`, индекс `sheets/index.json`), каждый лист — 2 изображения в оригинальном масштабе по ширине; широкие изображения (1942 px, например `39/D-2.1-dialogs`) просматривались отдельно.
2. Каждый лист открыт, содержимое записано в журнал партиями (5 партий: S-0; S-0.7–S-8; D-1–D-3; D-4–D-11; V-0–V-11 + хвост D-5/D-7/D-8/D-10), с уровнем проверки (full / layout).
3. Для каждого расхождения с ТЗ выполнялся поиск по `tz.md` (чтобы не фиксировать мнимые расхождения) и проверка в коде (`grep` по классам/YAML прототипа и eyon-pilot).
4. Код прототипа прочитан целиком (классы `app/Agent`, YAML, промпты); eyon-pilot — по разделам, указанным в таблице выше.
