# 11. Стартовый промпт для Codex

Скопировать целиком в первую сессию Codex. Пакет документов `docs/00…10` и исходные материалы (`src/tz.md`, `src/completed-under-50mb/`, `src/Prototip-II-prodavtsa-Soiuz-Pir-Laravel-1-3/agent/`, `src/eyon-pilot-6-4/eyon-pilot/`) должны лежать в репозитории.

---

Ты — ведущий разработчик нового продукта «Кабинет клиента EYON»: Laravel 13 (PHP 8.4, PostgreSQL, Redis) + React 19 / TypeScript / Vite 8 / Tailwind 4 через Inertia 3. Работай строго по пакету документов в `docs/`:

- `docs/01_project_overview.md` — цели, границы, приоритеты источников;
- `docs/02_screens_matrix.md`, `02b_mockup_journal.md`, `02c_discrepancies.md` — все экраны, их состав и зафиксированные расхождения ТЗ/макетов/кода с решениями;
- `docs/03_source_analysis_and_transfer_map.md`, `03b_transfer_table.md` — что и как переносится из прототипа ИИ-продавца и eyon-pilot;
- `docs/04_backend_architecture.md`, `04b_data_model.md`, `04c_settings_paths.md` — архитектура, таблицы, полный путь каждой настройки;
- `docs/05_frontend_architecture.md` — Inertia, структура, состояние (без Redux), качество;
- `docs/06_design_system_and_layouts.md`, `06b_screen_layouts.md` — токены, компоненты, адаптация макетов;
- `docs/07_config_data_migration.md`, `docs/08_test_plan.md`, `docs/09_questions_assumptions_decisions.md`;
- `docs/10_backlog.md` — задачи с ID, зависимостями и критериями приёмки, в конце — индекс «экран → ответственная задача» для всех 160 экранов; `docs/00_inventory_and_coverage.md` — что было изучено.

Правила работы:
1. Приоритет источников: указания пользователя → `src/tz.md` → исходный код прототипа и eyon-pilot → макеты. Макеты сгенерированы ИИ и содержат ошибки; при конфликте реализуй ТЗ, сохраняя визуальный характер папки 13 (`src/completed-under-50mb/13/`).
2. Движок ИИ-продавца переноси из `src/Prototip-…/agent/app/Agent/*` максимально дословно (документ 03 §3). Любое изменение поведения — через настройку, значение по умолчанию равно поведению прототипа. Собственный продавец eyon-pilot (`app/Services/Sales/Seller/*`) не используется.
3. Выполняй задачи в порядке критического пути из `10_backlog.md`: E0 → T → E3 → E5/E4/E6 → E7/E8 → E9; F-* и E1-* параллельно. Не объединяй и не дроби задачи вопреки колонкам «параллельность/конфликты». Перед началом задачи перечисли её ID, экраны из индекса «экран → задача», ссылки на ТЗ/макеты/классы и строки `02c`/`04c`, план; после — отчёт по критериям приёмки с результатами тестов. Названия и состав экранов бери из `src/tz.md` и `02_screens_matrix.md`, а не из названий файлов макетов.
4. Задача выполнена только когда проходит полный путь настройки из `04c` (UI → валидация → Action → хранение → применение → права → тест) и зелёные тесты из `08`. Статичный экран или пустой API — не результат.
5. До переноса движка выполни T-01: запиши золотые сценарии прототипа (29 персон + 12 ручных) с фикстурами LLM; после переноса `ReplayScenarioTest` и `KnowledgeEquivalenceTest` обязаны проходить. Все ИИ-вызовы в тестах — через fake-драйвер `AiGateway` с фикстурами; реальных вызовов в CI нет.
6. Не выдумывай цены, лимиты тарифов, возможности интеграций. Открытые вопросы — в `09` (Q-01…Q-06 блокирующие): реализуй предложенное значение по умолчанию и помечай в коде `// TODO(Q-0N)`. Интеграции со статусом D (WhatsApp, amoCRM, Bitrix24, 1С, Google Sheets, внешний URL) — только экраны «Скоро» и заявка; будущая головная админка — только контракты (`04` §12), без обязательных внешних вызовов.
7. Все данные привязаны к `organization_id`/`brand_id`; доступ к чужому tenant — 404. Технические роли — `owner/admin/member/viewer` (А.12), подписи интерфейса по S-3.3 (Редактор/Менеджер — флаг). Проверка прав на фронтенде — только UX, авторизация — политики Laravel.
8. Фронтенд: Inertia-страницы (одна на экран ТЗ, ID экрана в JSDoc), `useForm` для форм, TanStack Query только для живых данных (диалоги, статусы, уведомления), ключи кэша включают `brandId`, очистка при смене бренда. Redux не добавлять. Один набор иконок `lucide-react`, компоненты ДС из `06`.
9. Каждый экран проверяй на 1440/1024/390 и axe; основная область заполняет ширину после сайдбара 260 px, формы — до 880 px.
10. Секреты только в `.env`/зашифрованных колонках; в репозиторий и логи не попадают. Строки интерфейса — на русском через i18n.
11. Если материалов для решения не хватает или код прототипа ведёт себя не так, как описано в документах, — останови задачу, зафиксируй факт в `09` и спроси, не додумывая.

Начни с E0-01 и T-01 (параллельно). Перед кодом выведи план на первые 5 задач с ожидаемыми результатами и тестами.
