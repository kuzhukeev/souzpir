## 2. Эквивалентность поведения ИИ-продавца

### 2.1. Фиксация до переноса (в репозитории прототипа, задача T-01)
1. Добавить в прототип «записывающий» LLM-клиент (`RecordingOpenRouterClient`): при реальных вызовах пишет пары «нормализованный запрос → ответ» в `tests/fixtures/llm/<scenario>/<n>.json`. Нормализация: удаление timestamp’ов, сортировка ключей.
2. Прогнать `agent:simulate` для всех 29 персон `tools/personas.yaml` с `--max-turns` из персоны и зафиксировать: для каждого хода — вход клиента, `extraction`, `goal` (тип, слот, trigger.id, теги), `tool_calls`, `guard` (issues, rejected, fallback), `stage/outcome/client_type` после хода, текст ответа. Сохранить как `tests/fixtures/scenarios/<persona>.json` («золотые сценарии»).
3. Дополнительно зафиксировать 12 ручных сценариев по сценариям ТЗ D-4.11 и правилам из `02c`: opt-out, prompt injection, off-topic ×3, негатив ×2, большая заявка (`escalation_amount_rub`), просьба отсрочки ×2 (deferred_insist), «хочу человека», вопрос о закрытой теме, повтор вопроса о заполненном слоте, 14 ходов до force close, напоминания (20 ч / 40 ч при старом поведении).
4. Снапшоты промптов на 5 состояниях.

### 2.2. Проверка после переноса
- `ReplayScenarioTest`: для каждого золотого сценария новый движок с эталонным релизом знаний и `FakeAiGateway`, отдающим записанные ответы, должен воспроизвести те же `goal`, `tool_calls`, `guard`, `stage/outcome`, текст ответа (текст — при одинаковых записанных ответах LLM совпадает детерминированно). Любое расхождение — падение теста с diff.
- `KnowledgeEquivalenceTest`: `KnowledgeSnapshot::fromRelease(v1)->toArray()` == `Knowledge::all()` прототипа (JSON нормализован).
- Перенесённые тесты прототипа: `GuardTest` (13), `PolicyTest` (11), `TurnTest` (4), `SupervisorTest` (3) — без изменения ожиданий.
- `DefaultsEqualPrototypeTest`: `brand_seller_settings` по умолчанию (пустые) дают те же значения, что константы прототипа (nudge 20, max_auto 2, off_topic 3, negative 2, budget_asks 2, zones доставки, текст реквизитов).
- Для каждого намеренного изменения поведения (R-D-08 warn, R-D-18 два интервала, R-D-19 действие off-topic, R-D-36 цены) — тест, что при выключенной настройке поведение = старое, при включённой — новое.

### 2.3. Воспроизводимость ИИ в тестах
`AiGateway` имеет драйвер `fake` (фикстуры по хэшу нормализованного запроса) и `record`. В CI — только `fake`; отсутствие фикстуры = падение теста с инструкцией записать. Тесты симулятора/судьи используют тот же механизм.

## 3. Тесты по модулям (минимальный состав)
- Оболочка: регистрация/вход/MFA/выбор компании/приглашения/роли (матрица S-3.3: 4 технические роли + флаг «менеджер продаж»)/бренды/домены/аудит/уведомления и история доставок (S-6.2, «Повторить»)/темы; API-ключи бренда с abilities и вебхуки компании (S-5.2, HMAC, тест-доставка); чат компании (S-5.3); согласия, экспорт с SHA-256 и отложенное удаление (S-7.4); реквизиты (S-4.5); тикеты и доступ поддержки 72 ч (S-8.2); статус сервиса (S-8.3); изоляция tenant (попытка доступа к чужому brand_id → 404; чужие ID в формах → 422).
- Видение: лимиты анкеты (10/10/15), набор переменного размера, запуск замера с `fake`-ответами моделей, расчёт метрик отчёта (снапшот JSON), публикация/TTL, расписание, `planned`-модель → 422, лимит слотов.
- Продавец: знания (CRUD в draft, publish, rollback, импорт/экспорт YAML, конфликт 409; входящие D-4.2 из `unknown_question`/пометок/докладов; образцы речи D-4.8 с порогом confidence; закрытые темы D-4.9), диалоги (перехват, режимы диалога и канала, экстренный стоп D-9.1, пометки А.6), клиенты (список, карточка с историей заполнения слотов, объединение дублей D-3.4 с переназначением диалогов/задач, импорт/экспорт D-3.5), задачи, каналы (Telegram webhook с дедупликацией `update_id`, виджет, API leads idempotency + маппинг полей D-9.9), напоминания (time travel), почта прайса (D-9.8 mail fake), аналитика (воронка на фикстурных диалогах), экспорт CSV/PDF, CRM-вебхук (HMAC, повторы), каталог (парсер CSV/XLSX/YML на фикстурах, порог «мало»).

## 4. E2E-сценарии
1. Регистрация → организация → бренд (тема) → приглашение коллеги → принятие.
2. Анкета Видения 8 шагов → профиль → набор вопросов → запуск замера (fake) → отчёт → публикация → публичная страница.
3. Подключение Telegram (fake API) → входящее сообщение → ответ бота → перехват менеджером → возврат боту.
4. Редактирование фактов → песочница на черновике → публикация релиза → песочница на новой версии → откат.
5. Настройка причин передачи → диалог с триггером «хочу человека» → задача → уведомление.
6. Напоминания: диалог без ответа → time travel → два напоминания → стоп.
7. Виджет на тестовой странице → диалог → карточка клиента.
8. Смена бренда в шапке → данные списка диалогов сменились, кэш очищен (проверка отсутствия чужих ID).

## 5. Definition of Done для задачи с ИИ-логикой
Код + тесты всех уровней, затронутые золотые сценарии зелёные, снапшоты промптов не изменились (или изменение задокументировано в 09), настройка проходит полный путь `04c`, аудит пишется, экран проверен на 3 ширинах.
