# HTTPS и доверенные прокси

При прямом запросе без forwarding-заголовков приложение принимает серверный `HTTPS=on`. Если присутствует `Forwarded`, любой `X-Forwarded-*`, `X-Real-IP` или `CF-Connecting-IP`, одного `HTTPS=on` недостаточно: для защищённых операций нужен явно настроенный доверенный IP/CIDR непосредственного прокси и один однозначный `X-Forwarded-Proto: https`. Заголовок `Forwarded` пока не поддерживается и приводит к отказу даже при доверенном прокси. Универсальные сети и wildcard не принимаются. Прямой HTTP для `souzpir.local` остаётся допустимым только в локальном окружении при проверенном loopback.

При переносе на Nginx нужно определить реальную схему подключения. Если Nginx напрямую передаёт запрос PHP-FPM, настройка FastCGI должна получать признак HTTPS из фактического TLS-соединения и не принимать протокольные заголовки клиента как доказательство TLS. Если Nginx работает как reverse proxy, на границе он должен перезаписывать forwarding-заголовки на основании своего соединения, а приложению необходимо явно задать `trustedproxy.proxies` конкретными адресами/сетями доверенных непосредственных прокси. Доступ к backend следует ограничить только этими прокси. Проверить обе схемы реальными запросами и поддельными заголовками до включения чувствительных операций.

Ссылка восстановления пароля пока отклоняет **все** forwarding-заголовки, даже от доверенного прокси. Её отдельное безопасное подключение к Nginx через прокси, error log и всю цепочку ingress нужно проверить до включения реальной доставки писем. Конфигурация OSPanel этим изменением не устанавливается.
