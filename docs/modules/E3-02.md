# SP-E3-02 — детерминированный движок продавца

`App\Seller\Engine\LeadState`, `Policy` и `Goal` перенесены из Laravel-прототипа. Policy принимает `App\Seller\Knowledge\KnowledgeSnapshot`, сохраняющий десять исходных пространств знаний и порядок списков. При создании движка runtime обязан получить snapshot из `KnowledgeRepository` для проверенного tenant и закрепить его на весь ход: E3-02 не выбирает или не меняет релиз посреди обработки.

`ExtractorPromptLoader::load(TenantContext $tenant, string $version = 'v1'): ExtractorPrompt` выбирает опубликованный prompt_sets для бренда или общий платформенный при отсутствии брендовой версии. В обоих случаях считывание не переходит к другому бренду. Объект prompt содержит tenant, точный body, version и checksum; рендер проверяет их снова перед передачей Blade. Чтобы исключить выполнение произвольного PHP из базы, сейчас допускается только шаблон, в точности совпадающий с доверенным `resources/views/prompts/extractor.blade.php`; незнакомая или повреждённая версия отклоняется. Произвольное редактирование текста промпта требует отдельного безопасного механизма шаблонов. Сидер prompt_sets E0-05 вызывается явно, при отсутствии опубликованного шаблона loader выдаёт ошибку.

Конструктор `Extractor(AiGateway $gateway, KnowledgeSnapshot $knowledge, ExtractorPrompt $prompt, string $model, float $temperature, string $agentName)` принимает закреплённые на ход зависимости. `extract(LeadState $state, array $history, string $clientMessage, AiContext $context): array` требует family `seller`, purpose `extractor` и tenant prompt; вызывает `AiGateway::complete` вне SQL-транзакции, передаёт исходную JSON schema, последние шесть сообщений, версию/checksum промпта, лимит 900 токенов, model и temperature. Неизвестные намерения и возражения нормализуются по правилам прототипа, JSON проверяется `opis/json-schema` 2.6.0. При ошибочном ответе шлюза возвращается исходный fallback прототипа, ошибки конфигурации/авторизации и исключения шлюза не скрываются. `_meta` содержит модель, latency, cost_usd и usage в формате донора; учёт и идемпотентность принадлежат AiGateway.

Интегратор E3-03B отвечает за получение snapshot правильного бренда, выбор model/name/settings, сохранение state и вызов этих классов в установленном порядке. Новый класс BrandRuntime здесь не создаётся: его владелец — E3-03B. Engine не реализует orchestration, Guard, инструменты или доставку. Результаты тестов основаны на синтетических данных и не подтверждают эквивалентность реального ответа модели.
