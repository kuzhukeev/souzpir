# SP-E3-02 — детерминированный движок продавца

`App\Seller\Engine\LeadState`, `Policy` и `Goal` перенесены из Laravel-прототипа. Policy принимает `App\Seller\Knowledge\KnowledgeSnapshot`, сохраняющий десять исходных пространств знаний и порядок списков. Для production runtime используйте `EngineFactory::forRelease(tenant, releaseId, gateway, model, temperature, agentName, promptVersion)`: factory получает именно опубликованный релиз через `KnowledgeRepository::forRelease(tenant, releaseId, false)` и создаёт Policy и Extractor из него. При каждом вызове на LLM-границе Extractor повторно загружает этот release для активного tenant и использует только возвращённое содержимое; переданный вызывающим кодом Snapshot/checksum не считается доказательством происхождения. Публикованный release зафиксирован на весь ход.

`ExtractorPromptLoader::load(TenantContext $tenant, string $version = 'v1'): ExtractorPrompt` выбирает опубликованный prompt_sets для бренда или общий платформенный при отсутствии брендовой версии. В обоих случаях считывание не переходит к другому бренду. Объект prompt содержит tenant, точный body, version и checksum; перед вызовом LLM published prompt заново загружается доверенным loader для активного tenant и указанной версии. Содержимое DTO не считается доказательством публикации или tenant. Чтобы исключить выполнение произвольного PHP из базы, сейчас допускается только шаблон, в точности совпадающий с доверенным `resources/views/prompts/extractor.blade.php`; незнакомая или повреждённая версия отклоняется. Произвольное редактирование текста промпта требует отдельного безопасного механизма шаблонов. Сидер prompt_sets E0-05 вызывается явно, при отсутствии опубликованного шаблона loader выдаёт ошибку.

Конструктор `Extractor(AiGateway $gateway, KnowledgeSnapshot $knowledge, ExtractorPrompt $prompt, string $model, float $temperature, string $agentName)` принимает закреплённые на ход зависимости. `extract(LeadState $state, array $history, string $clientMessage, AiContext $context): array` требует family `seller`, purpose `extractor` и tenant prompt; вызывает `AiGateway::complete` вне SQL-транзакции, передаёт исходную JSON schema, последние шесть сообщений, версию/checksum промпта, лимит 900 токенов, model и temperature. Неизвестные намерения и возражения нормализуются по правилам прототипа, JSON проверяется `opis/json-schema` 2.6.0. Для завершённого empty_response или невалидного JSON используется fallback прототипа. `ExtractionPending` означает уже выполняющийся запрос: E3-03B обязан ждать без Policy, commit, доставки и нового платного вызова. `ExtractionUncertain` (включая provider_uncertain/cost_unknown и неизвестный статус) закрывает обработку до подтверждённой сверки, без fallback и автоматического повторения. Исключения конфигурации и авторизации не скрываются. `_meta` содержит модель, latency, cost_usd и usage в формате донора; учёт и идемпотентность принадлежат AiGateway.

Интегратор E3-03B обязан вызывать EngineFactory в активном tenant, подавать только данные принадлежащего tenant диалога и фиксировать один release на ход; он отвечает за выбор model/name/settings, сохранение state и порядок вызовов. Новый класс BrandRuntime здесь не создаётся: его владелец — E3-03B. Engine не реализует orchestration, Guard, инструменты или доставку. Результаты тестов основаны на синтетических данных и не подтверждают эквивалентность реального ответа модели.

Для Extractor обязательны все три dataClasses: `conversation_content` (последнее сообщение и история), `client_profile` (карточка и слоты лида), `knowledge_internal` (внутренние intents и закрытые темы); до появления общего словаря E3-03B обязан передавать их в AiContext, а E1-11 — учитывать при согласиях. Дополнительно проверяются active tenant, family=seller, purpose=extractor, objectType=conversation и принадлежность диалога. До реальной передачи Gateway проверяет разрешения бренда на каждый класс.

Email из текущей реплики извлекается локально: при единственном валидном адресе он сохраняется после проверки ответа модели, при нескольких разных адресах не выбирается произвольно; уже известный адрес повторно не записывается. Значения `[EMAIL]`, `[PHONE]`, `[ТЕЛЕФОН]` не становятся контактами. Схема донора не содержит phone-слота: безопасное локальное сохранение телефона в Contact и авторизованная связка с входным сообщением — отдельная обязанность E3-03B/канального адаптера, здесь номер не сохраняется и не отправляется в открытом виде.
