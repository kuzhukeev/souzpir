# E1-01F — восстановление пароля через очередь

Форма для существующего и неизвестного адреса возвращает одинаковый текст и локальный redirect. Валидация и IP-throttle маршрута сохранены; на один аккаунт действует интервал из auth.passwords.users.throttle. Доступ требуется по активной организации и участию либо непросроченному приглашению.

При включении модуля и настроенного транспорта запрос сохраняет намерение с непрозрачным ID, user ID, версией авторизации и HMAC адреса. Задание очереди содержит только ID. Открытый токен генерируется непосредственно перед передачей транспорту и существует только в памяти процесса; в стандартной таблице восстановления хранятся его хеш и версия авторизации на момент выдачи. При смене версии (например, настройке MFA) ссылка отклоняется. Старые токены без версии намеренно недействительны; нужно запросить новую ссылку. При использовании ссылки права повторно проверяются в транзакции с блокировками user → organization → invitations → membership → token. Срок действия задаётся auth.passwords.users.expire; запрос, ожидавший этот срок, отменяется. Повторная выдача заменяет предыдущий токен; успешный сброс атомарно удаляет токен и сессии, меняет remember token, повышает auth_version и пишет audit.

Состояния pending → sending → transmitting → sent, failed или uncertain. Scanner auth:password-dispatch-pending обрабатывает только pending; задача очереди использует одну попытку. При обрыве sending/transmitting оператор может вызвать markUncertain только после подтверждения остановки worker; uncertain автоматически не повторяется. После паузы пользователь может создать новый запрос: это новая выдача, а не автоматический повтор. После перехода в transmitting, но до фактического ответа провайдера неизбежна неопределённость: письмо могло быть принято, а рабочий процесс не узнал результата. Действующий запрос следует считать неопределённым и не перезапускать.

Почта и SMTP выключены по умолчанию; в контейнере по умолчанию DisabledTransport. Для разработки допускается fake. Сам по себе legacy AUTH_EMAIL_DELIVERY_ENABLED отправку восстановления не включает. Sync queue не выполняет отправку в HTTP-запросе: намерение остаётся pending для оператора/scanner.

**Блокер live:** текущий URL содержит токен в пути, адрес в query. Access logs веб-сервера, обратного прокси и систем наблюдения способны записать их до Laravel. Перед включением необходимо отдельное проверенное решение по маршрутизации/исключению или редактированию таких записей, включая ретеншн/копии и запрет передачи в сторонние системы. Не включать live до этого решения и отдельного разрешения пользователя. Ошибки внутри обработчика и транспорта санитизируются без сохранения исходного исключения; это не защищает журналы внешней инфраструктуры.
