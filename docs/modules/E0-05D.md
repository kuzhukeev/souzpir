# Защита секретов перед ИИ

SecretBoundary — дополнительная проверка известных форм. Gateway проверяет исходный запрос и контекст до резервирования, затем проверяет запрос повторно после маскирования контактов. Это позволяет обнаружить дубли ключей в исходных JSON-аргументах инструментов. Для live-передачи отдельно требуется доверенная политика разрешённых источников и классов данных. Доверие к одной клиентской классификации или регулярным выражениям недопустимо.

Проверяются вложенные структуры, текст и исходные JSON-аргументы инструментов, включая дубликаты ключей и ошибки синтаксиса; известные названия полей в snake_case и camelCase, \u escapes, HTML/URL encoding, NFKC, известные формы API-токенов, AWS access key ID, Basic и URL user:password. Валидные аргументы и исходный payload не изменяются. Проверка ограничена глубиной и общим размером, консервативна и может отклонять безопасный текст. Строковые tool arguments должны быть корректным JSON-объектом или массивом; некорректные и дубликаты отклоняются.

**Граница исходных данных.** Если внешний JSON уже разобран в PHP array, дубликаты ключей к моменту вызова могут быть потеряны. API/Gateway должен проверять исходный JSON до первого декодирования либо получать структуру от доверенного сериализатора без дублей. Сервис не проверяет неизвестные форматы, семантически скрытые секреты и все возможные разбиения на блоки; он не доказывает отсутствие секретов.

Исключение сервиса не содержит исходные данные и previous. При zend.exception_ignore_args=0 вызвавшие методы способны раскрыть аргументы в getTrace(): Gateway использует SensitiveParameter и выдаёт обобщённую ошибку без previous; сквозной тест проверяет отсутствие исходной строки в исключении до резервирования и транспорта. Любые новые вызывающие методы обязаны так же защищать свои аргументы и логи. Реальный транспорт остаётся выключенным до проверки интеграции и отдельного разрешения пользователя.

При локальном режиме записи запросы и ответы модели сохраняются в закрытых локальных файлах. До применения этого режима с реальными данными отдельно нужны проверка прав доступа, политика хранения и удаления. Защита трасс ошибок не заменяет контроль журналов, внешних прокси и вызывающего кода.
