# Защита секретов перед ИИ

SecretBoundary — дополнительная проверка известных форм, не подключённая автоматически. До любого внешнего вызова интегратор обязан применить доверенную политику разрешённых источников и классов данных, затем вызвать этот сервис до резервирования и транспорта. Доверие к одной клиентской классификации или регулярным выражениям недопустимо.

Проверяются вложенные структуры, текст и исходные JSON-аргументы инструментов, включая дубликаты ключей и ошибки синтаксиса; известные названия полей в snake_case и camelCase, \u escapes, HTML/URL encoding, NFKC, известные формы API-токенов, AWS access key ID, Basic и URL user:password. Валидные аргументы и исходный payload не изменяются. Проверка ограничена глубиной и общим размером, консервативна и может отклонять безопасный текст. Строковые tool arguments должны быть корректным JSON-объектом или массивом; некорректные и дубликаты отклоняются.

**Граница исходных данных.** Если внешний JSON уже разобран в PHP array, дубликаты ключей к моменту вызова могут быть потеряны. API/Gateway должен проверять исходный JSON до первого декодирования либо получать структуру от доверенного сериализатора без дублей. Сервис не проверяет неизвестные форматы, семантически скрытые секреты и все возможные разбиения на блоки; он не доказывает отсутствие секретов.

Исключение сервиса не содержит исходные данные и previous. При zend.exception_ignore_args=0 вызвавшие методы способны раскрыть аргументы в getTrace(): при интеграции обязательны SensitiveParameter для всей цепочки, generic исключения без previous и сквозной тест Gateway → boundary → fake transport с проверкой trace и логов. Реальный транспорт остаётся выключенным до проверки интеграции и отдельного разрешения пользователя.
