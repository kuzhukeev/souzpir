# ИИ-шлюз E0-05

`App\Contracts\Ai\AiGateway::complete(AiRequest, AiContext): AiResult` вызывается внутри действующего `TenantContext`. Контекст хранит organization/brand, семейство seller или vision, исходный purpose, тип и ID объекта расходов, idempotency key, объявленные data classes, номер попытки и parent. Таблица объекта должна существовать и принадлежать текущему бренду; известные типы: brand/onboarding, conversation, measurement, audit_run, release_eval, quiz, evaluation. Будущие домены добавляют новые типы только через согласованное изменение контракта.

Провайдеры и их состояние active/planned задаются в config/features/E0-05.php; строка `ai_providers` может дополнительно выключить провайдера, но не включает planned-адаптер. `ProviderSeeder` и `PromptSetsSeeder` вызываются явно, не при загрузке приложения. Шесть шаблонов исходного Laravel-продавца перенесены байт-в-байт; сидер сохраняет SHA-256 и не перезаписывает отличающийся `v1`. Дефолты моделей и температуры продавца перенесены из прототипа, не из M3.

До передачи запросов маскируются телефоны и email внутри сообщений, включая JSON-аргументы tool calls. Сырой запрос и контакты не сохраняются в ai_calls: для идемпотентности используется HMAC исходного запроса и ключа. Нормализованный ответ хранится шифрованным в ai_calls; `record` сохраняет пару маскированный запрос / нормализованный ответ только в приватное local/testing storage. Перед переносом записей в тестовые фикстуры оператор должен проверить их содержимое. `fake` читает fixture `<sha256 нормализованного запроса>.json` и выбрасывает ошибку при отсутствии. Набор реальных пользовательских записей и эталон поведения LLM эта задача не создаёт.

Контакты в ключах, экранированные контакты в произвольных строках, объекты и некорректный тип `tool_calls` отклоняются до передачи. Для вложенных данных используются массивы и скалярные значения. Это ограничение не заменяет проверку разрешения на передачу объявленных классов данных.

Live OpenRouter по умолчанию выключен: необходимы явное `AI_LIVE_ENABLED`, ключ провайдера и разрешение внешней передачи для каждой data class в `brands.settings.ai_data_policy`. Тесты используют только `Http::fake`, сетевой запрос не выполняется. Нормализация сохраняет ID, имена и аргументы tool calls, поддерживает null content и разбор JSON как прототип. OpenRouter-драйвер выполняет не более одного POST и запрещает автоматическое следование redirect. HTTP-статусы, кроме 200, timeout, disconnect и неразбираемые или неполные ответы считаются неопределёнными; по одному статусу или тексту отказа освобождать резерв нельзя. Ошибки, достоверно возникшие до отправки, сохраняют прежнюю классификацию. Возможности streaming и не-OpenRouter адаптеры не заявлены.

Денежный учёт — целые микродоллары: текстовое значение из JSON переводится без float с округлением вверх. Значения лимитов и курсов/коэффициентов не выдумываются. При месячном `limit_micros` оператор должен явно определить верхний `reservation_micros` по модели; для live дополнительно задать `reservation_request_limits` с `max_input_bytes` и `max_output_tokens`, соответствующие обоснованной максимальной цене модели. Без них вызов блокируется до сети. При превышении резерва фактическая стоимость сохраняется полностью, включается `reservation_breached`, последующие вызовы останавливаются. Доступные тарифные `limit_units`/`used_units` хранятся nullable; заданный лимит единиц до согласования пересчёта закрывает вызовы, а не превращается в ноль или бесконечный лимит.

Резерв, счётчик и запись ключа выполняются в короткой транзакции под PostgreSQL lock; HTTP проходит вне SQL-транзакции. Сам `complete` запрещён внутри внешней транзакции: вызывающая операция должна завершить commit и лишь затем запускать шлюз. Один ключ, тело и драйвер возвращают тот же результат / состояние in_progress / uncertain; другое тело или драйвер с тем же ключом отклоняются, даже если разные контакты маскируются одинаково. Допускается только один потомок неуспешной попытки; это обеспечено блокировкой parent и уникальным индексом. При timeout, неизвестной стоимости или сбое учёта резерв удерживается. До списания нормализованный ответ сохраняется в зашифрованном виде.

Сверка `reserved` запрещена: старый запрос может ещё выполняться. При падении процесса оставшийся `reserved` не освобождается автоматически; безопасный операторский механизм определения завершения процесса и сверки с провайдером ещё требуется реализовать. `reconcileUnbilled` и `reconcileSuccess` закрыты и для `uncertain`: произвольный текст и результат не являются проверкой провайдера и могут ложно подтвердить нулевые или меньшие расходы. Для разблокировки требуется отдельная авторизованная операторская процедура с проверяемым подтверждением провайдера; HTTP для неё не открыт. При breach отдельный администрируемый процесс проверки/снятия блокировки ещё не реализован.

Событие `ai.budget.threshold_reached` помещается в транзакционный outbox E0-04 при явно настроенном `budget_threshold_basis_points` и первом пересечении денежного лимита. Без E0-04 настройка порога закрывает вызов заранее. При доставке используется after-commit механизм E0-04. Значение порога по умолчанию отсутствует.


Независимый кандидат fail-closed обработки OpenRouter не подтверждает окончательную стоимость провайдера даже при синтаксически валидном HTTP 200. Он не исправляет исторические `failed/provider_rejected`, в которых прежний драйвер мог освободить резерв после HTTP-ответа; до live требуется отдельная read-only сверка и согласованная обработка. В текущем main сохранённый `uncertain` блокирует иной ключ только при заданном лимите и в текущем месячном бюджете: family-wide guard — отдельный кандидат и должен интегрироваться/проверяться отдельно. Fake HTTP доказывает параметры клиента и число вызовов в тесте, но не поведение реального proxy/провайдера или невозможность поздней внешней отправки.
