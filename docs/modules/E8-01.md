# E8-01 — ядро Видения, работа продолжается

Этот модуль пока нельзя считать завершённым: безопасный источник профиля/knowledge bridge, парсер с проверкой фактов и их сквозное подключение находятся в отдельных задачах. Live вызовы запрещены на уровне MeasurementRunner независимо от настроек шлюза; публикация и пользовательские экраны отсутствуют.

## Текущий контракт

- question_sets хранит tenant, версию, неизменяемый список {id,text,intent}, размер и checksum. Новый набор — новая версия. Число вопросов определяется сохранёнными данными; проверены 12, 20, 30. Уникальность назначается при блокировке соответствующего бренда.
- measurements хранит tenant, ссылку на набор и неизменяемую configuration: frozen вопросы и checksum, providers (ключ провайдера → модель), runs, temperature, max_output_tokens и parser. Сейчас parser явно null; парсер обязан отказывать при null и не принимать модель или настройки из клиентского запроса. Значения температуры 0,7 и 1200 токенов взяты из VisibilityPlan исходного проекта и замораживаются при запуске; это не тариф. Выбираются только active модели.
- measurements.profile_snapshot и profile_checksum пока равны null. Будущий доверенный bridge должен передать их при создании замера; текущий API этого ещё не делает. Значения после создания менять нельзя. Evidence обязан требовать оба поля, сверять checksum, tenant, статус ответа и исходный AI call и заново проверять, что знания не отозваны. Объявленный формат профиля: name, aliases, normalized_aliases, ambiguous_aliases, alias_entries, brand_domain, domains, verified_domains, legal_name, facts, knowledge (release_id, fingerprint, restrictions_version, atoms). Контракт донора — VisibilityKnowledge::freeze; доверять профилю из клиентского запроса нельзя.
- measurement_answers хранит tenant, measurement_id, question_n (1-based), provider, run_no, requested_model, model, status, answer_text, ai_call_id, protocol_valid; fact/mentions/sources не считаются подтверждёнными. Композитные внешние ключи не позволяют привязать ответ к чужому бренду. При in_progress/uncertain повтор не запускается. В базе фиксируются код ошибки, а не исходное исключение.
- MeasurementRunner получает сырой результат через существующий AiGateway с purpose vis.measure, family vision, object_type measurement, data_class vision_question и детерминированным ключом слота. Текущий Gateway используется только в режиме fake. Отдельного ручного или автоматического повторного запуска списанного либо неопределённого вызова нет.
- vision_reports сохраняет неизменяемые версии снимка и canonical checksum. Пока Evidence не подключён, все факты null, успешный сырой ответ остаётся неизвестным, сырой текст не включается в snapshot. Подготовка review использует источник ReportPreparation: сомнительные факты, подтверждённые действия и перепроверка типов/отсутствия на площадках. Публичных ссылок здесь нет.
- monitoring_schedules создана один раз, по умолчанию отключена; расписатель и реальные отправки не запускаются.

## Метрики и границы

VisibilityMetrics и Audit Metrics перенесены из eyon без изменения формул. Отсутствующие, ошибочные и protocol_invalid результаты не превращаются в отрицательные. Сравнение использует общую выборку, а смена comparability key разрывает серию. Тесты исходника сохранены.

Не реализованы совместимые с донором Evidence/AnswerParser/MentionConfirmer, проверка буквальных цитат, сущностей, атомов, валидности и отзывов knowledge, provenance/сохранение фактов и связывание с расчётом. Не реализован live, source search protocol и полнофункциональный pipeline/recovery, реальные семантические запросы или публикация. Нынешний snapshot без фактов показывает только неизвестность и не является равнозначной заменой полноценного отчёта. Требуется интеграция будущих Evidence/knowledge bridge с независимыми tenant- и fake-LLM тестами и контрольными примерами до передачи E8-01 на review.

Internal API не регистрирует маршрутов и не выполняет пользовательскую авторизацию действий: будущие UI/API/worker consumers обязаны проверять permission/brand grants и передавать только tenant, восстановленный из доверенного контекста. ReportPreparation::items/report — чистые внутренние преобразования сохранённых и проверенных данных, они не являются границей доверия.

Контракт будущего configuration.parser задаёт проверенный provider/model, параметры модели и контрольные суммы установленных prompt/schema/confirmation artifacts, а также версии normalizer и confirmation. Эти значения должны поступать из доверенной конфигурации и замораживаться при создании нового измерения вместе с проверенным profile_snapshot; существующий пустой план не обновляется. До интеграции никакие такие значения не предполагаются автоматически.

Текущее start предназначено только для локальных fake-запусков и не проверяет утверждение набора вопросов. До пользовательского запуска E8-03 должен добавить явную tenant-bound проверку утверждения, а исполнитель — требовать её до любого вызова; утверждение не должно менять неизменяемую версию набора.
