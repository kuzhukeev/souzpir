# E3-01: версии базы знаний

KnowledgeRepository предоставляет опубликованный неизменяемый срез и черновик. Формат runtime-среза совместим с десятью YAML-набором прототипа. В runtime попадают только активные факты. Публикация атомарно создаёт отдельную версию, не меняя черновик; откат только переключает активную версию. Контрольная сумма описывает runtime-срез с активными фактами; неизменяемость остальных полей опубликованной версии защищается ограничениями базы.

Редактор получает идентификаторы, источники, статусы и версию через draftEditor. Изменение текста/статуса/источника, добавление, перенос и удаление фактов выполняются через setFact/addFact/moveFact/deleteFact с ожидаемой версией. saveDraft редактирует остальные разделы и пустые группы и отклоняет неоднозначные изменения фактов. Это защищает одинаковые тексты с разными метаданными. Логический ID факта сохраняется в публикациях, физический ID редактора стабилен в черновике.

Все редакторские действия повторно проверяют права и активность организации, бренда и участника в транзакции, а также записывают аудит. Порядок блокировок: организация, бренд, участник, версия, группы и факты. Модули команды и редактора должны придерживаться этого порядка. Прямые SQL-изменения дочерних таблиц могут конфликтовать с редактором и вызывать отмену одной транзакции из-за deadlock; используйте API репозитория.

published/forRelease предназначены для доверенного кода движка. HTTP-контроллер обязан проверять seller.knowledge.read до вызова. Нельзя передавать черновик в движок. Очередь работ и интерфейсы E4 должны использовать editor API, не менять таблицы напрямую.
