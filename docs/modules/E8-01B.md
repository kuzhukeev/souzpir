# E8-01B — ядро аудита сайта и приватные черновики источников

## API и границы

`App\Vision\SiteAudit\SiteInspector::inspect(string $url, ?int $pageLimit = null): array` — синхронная проверка публичного HTML без JavaScript и без ИИ. Результат содержит исходный/final URL, `criteria`, интервальную `readiness`, извлечённые страницы с provenance, отдельный `ai_access`, issues и описание охвата. Сервис не публикует отчёт, не создаёт расписание и не предоставляет HTTP endpoint. Пользовательский запуск/хранение отчётов и UI принадлежат задачам-потребителям E8-02/E8-06.

`Knowledge\SiteKnowledgeImporter::import(TenantContext $tenant, ?string $url = null, int $maxPages = 20): array` извлекает страницы только с origin публичного сайта текущего бренда и сохраняет приватные неизменяемые черновики. Контекст обязан совпадать с текущим scoped TenantContext; активные организация, бренд, membership и permission `vision.settings.write` проверяются до обхода и повторно при записи. `Knowledge\SiteDraftStore::read(TenantContext, string $url): ?array` читает последнюю подтверждённую аудитом версию в том же scope. Прямого URL для скачивания файлов нет.

Конфигурация/DI зарегистрированы в `config/features/E8-01B.php`, общий bootstrap не менялся. `PublicAddressResolver` — заменяемая граница DNS для offline fixtures. `SITE_AUDIT_FETCH_ENABLED` по умолчанию false: live загрузки включаются оператором отдельно. Тесты включают её только с HTTP/DNS fake и `Http::preventStrayRequests()`.

## Политика адресов и конфиденциальность

Входные адреса сайта, загружаемые страницы, Location и ссылки на источники с query-строкой отклоняются до DNS/перехода либо исключаются из результатов и обхода; fragment не отправляется и не входит в provenance. Это намеренное ограничение: страницы, доступные только по query-ссылке, и контактные ссылки, смысл которых содержится только в query (например, WhatsApp send), не подтверждаются — для них результат остаётся unknown. Путь без query сохраняется целиком, чтобы можно было проверить источник; его не следует воспринимать как обезличенный. Ошибки в публичных методах санитизируются, исходное исключение не прикрепляется.

Извлечённый текст, JSON-LD и указанные пути являются недоверенными потенциально чувствительными данными: текст страницы сам может содержать адрес с query или иной секрет. Результат и приватные drafts доступны только авторизованному потребителю нужного tenant и не пригодны для логов, мониторинга, публичных отчётов или сериализации в очереди без отдельной политики защиты и редактирования; результаты не являются общей гарантией отсутствия контактов или секретов. Доступность сайта в интернете сама по себе не является разрешением на публикацию его содержимого. Будущие API/jobs обязаны защитить входные URL и собственные трассировки, так как эта библиотека не контролирует их кадры стека и access logs.

## Семантика 16 + 4

Каждый из 20 критериев имеет вес 5. Первые 16 оцениваются по HTML/robots/sitemap; последние четыре всегда `pending=true`, `in_scope=false`, `score=null`. Отсутствующее подтверждение — unknown, не ноль. Оценка не нормализуется к 16 критериям: lower = сумма 5 × известный score; upper = lower + 5 × неизвестная доля; coverage = 100 × (1 − неизвестная доля / 20). Идентификаторы уникальны в 1…20, границы должны быть конечными числами и помещаться в [0,1].

| ID | Исходная группа | Критерий / допустимые положительные свидетельства |
|---|---|---|
| 1 | Техническая доступность | 2xx и не менее 120 символов извлечённого текста |
| 2 | Техническая доступность | Внутренние ссылки и корректный sitemap: оба 1, один 0.5 |
| 3 | Техническая доступность | Robots, meta robots/eyon-audit, X-Robots-Tag; доказанный запрет 0 |
| 4 | Техническая доступность | Текст и JSON-LD: 1; один достаточный текст: 0.5 |
| 5 | Структура предложения | Product/Service/SoftwareApplication или содержательная страница предложения |
| 6 | Структура предложения | Параметры и единицы измерения |
| 7 | Структура предложения | Категория/варианты либо несколько подтверждённых предложений |
| 8 | Структура предложения | SKU/MPN и URL: 1; подтверждённые адреса предложений: 0.5 |
| 9 | Коммерческие условия | Цена с валютой или описанный порядок расчёта |
| 10 | Коммерческие условия | Наличие, минимальный заказ или срок начала |
| 11 | Коммерческие условия | Условия получения товара/доступа к услуге в собственном блоке |
| 12 | Коммерческие условия | Проверяемый контакт/путь покупки; share-ссылка не является контактом |
| 13 | Доверие | Реквизиты/юридическая идентичность |
| 14 | Доверие | Ссылка на подтверждающий документ; его подлинность не утверждается |
| 15 | Доверие | Одинаковый факт цены одного товара на разных успешно загруженных страницах |
| 16 | Доверие | Явная календарно корректная dateModified; copyright не доказывает актуальность |
| 17–20 | Понимание ИИ | Продукт, параметры, ограничения, следующий шаг: pending |

Слабое положительное свидетельство для критериев 5–16 обычно даёт 0.5, исключение — идентификаторы критерия 8. Демонстрационные цены и примеры исключены из коммерческих свидетельств; кейсы и чек-листы не доказывают условия доставки. Исходный текст примеров остаётся в извлечённой странице. Явно скрытые поддеревья по атрибутам `hidden`, `aria-hidden=true` и inline `display:none`/`visibility:hidden` исключаются до извлечения свидетельств и ссылок; внешние таблицы стилей, CSS-экранирование и JavaScript не вычисляются. Свидетельства сохраняют URL, время и ограниченную цитату. Failed HTTP страницы не подтверждают JSON-LD. XXE/DOCTYPE/ENTITY в sitemap запрещены; пустой sitemap считается некорректным.

Группы намеренно сохранены до согласования Q-03/R-V-11; ссылка R-V-05 в карточке относится к размеру набора вопросов, а не к группам аудита. `ai_access` отдельно показывает robots/llms/sitemap и 12 bot tokens с ролями search/training/user_fetch; он не добавляет баллы и не доказывает индексацию/упоминания. Каталог ботов перенесён как снимок донора с его датой проверки, не как новая live-проверка документации.

## Ограничения обхода

Инспектор: 1…5 страниц (default5), максимум10 HTTP hops вместе с robots, redirects, sitemap и llms; на цепочку не более5 переходов. Перед HTML каждого origin проверяется robots. Импорт: BFS, default20/max100 страниц, queryless ссылки того же origin, только 200 HTML/XHTML; 10s на HTTP hop и deadline120s между операциями. Сетевые вызовы проходят вне коротких SQL-транзакций; importer и draft store отклоняют вызов внутри внешней транзакции. Исторические источники после смены сайта остаются доступны только текущему авторизованному администратору своего бренда; запись сверяет текущий origin заново.

`CrawlerClient` делает ровно один HTTP GET. Допустимы HTTP(S), порты80/443, публичный DNS hostname без credentials/control characters и query. Все A/AAAA ответы, включая CNAME (до8 DNS lookup), проверяются; private/reserved/multicast, localhost, metadata, mapped IPv6 и специальные диапазоны запрещены. Выбранный IP закреплён через CURLOPT_RESOLVE при сохранении hostname/SNI/TLS-проверки. Proxy и автоматические redirects отключены через поддерживаемые опции Guzzle; reuse соединений отключён. Совместимость параметров с реальным CurlFactory проверяется без выполнения запроса. DNS проверяется заново для каждого hop.

HTTP timeout ограничен0.1…48s, connect≤3s, тело≤600000 байт; ограничение проверяется по заголовкам, прогрессу и окончательному телу. Сжатие отвергается; HTML/XHTML/XML/plain text приводится к UTF-8 из явно указанной поддерживаемой charset (включая Windows-1251), либо проверяется как UTF-8 при отсутствии charset. Лимит размера действует и после перекодировки. Это намеренно более узкая граница, чем generic crawler донора: произвольный JSON/binary, неизвестная charset и повреждённые последовательности отвергаются вместо незаметной замены символов. Нативный DNS использует таймауты resolver ОС; HTTP timeout/deadline не обещают принудительное прерывание зависшего системного DNS вызова. Live transport в этой задаче не запускался.

## Источники импорта

Сохранены HTML extraction, таблицы/заголовки/списки, caveats цен с корневой страницы, исключение script/nav/hidden/form content, canonical identity `/index.htm[l]` → `/` без изменения запрашиваемого пути, идемпотентный fingerprint и новые версии при изменении текста. Сырой HTML не исполняется; извлечённые данные остаются недоверенными и не отправляются в ИИ.

Файлы находятся только в `storage/app/private/vision/site-audit/<organization>/<brand>/<sha256 canonical URL>/`. Блокировка источника исключает одновременную запись; версии имеют ULID, provenance и статус draft. Аудит не содержит текст страницы. При обычном сбое аудита запись откатывается; при аварии до commit orphan-файл не читается и не переиспользуется без соответствующей записи audit_logs. Файловая система и PostgreSQL не объявляются одной атомарной транзакцией.

В принятом registry нет таблиц M0 KnowledgeDocument/KnowledgeVersion/KnowledgeProposal донора, поэтому они не перенесены и не созданы самовольно. `proposal_id=null`, `confirmed=0`; публикация, approve, применение к Seller release отсутствуют. Интегратору нужен отдельный согласованный адаптер приватного source draft → общий review/proposal/import API знаний с approved ownership/schema; до него источники не входят в опубликованные знания. Audit commit-marker должен сохраняться вместе с черновиком; очистка/retention аудита требует согласованного независимого commit-marker. Автоматического удаления файлов/организации нет.
