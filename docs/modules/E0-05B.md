# Восстановление учёта ИИ: просмотр незавершённых вызовов

В ветке SP-E0-05B подготовлен только защищённый read-only список вызовов. Регистрацию маршрута в `routes/features/E0-05B.php` выполняет интегратор отдельным изменением: эта папка вне scope исполнителя. До регистрации маршрута HTTP-список недоступен в приложении.

Контракт интеграции: `GET /ai/recovery/calls`, имя `ai.recovery.calls.index`, invokable `App\Ai\Http\UnresolvedCallsController`; web-группа фундамента `web`, `auth`, `verified`, `tenant`, дополнительно `auth.version`, `auth.nostore`. Контроллер повторно проверяет действующую сессию, актуальную выбранную организацию и бренд под блокировками через `ProfileAccess`, право `billing.manage` и то, что актор — действующий назначенный владелец. Переданный `X-Brand-Revision`, если есть, проверяется; устаревшая ревизия даёт 409. `X-Brand-Id` проверяет middleware tenant и не выбирает бренд. Непроверенный пользователь, другие роли и не назначенный владелец доступа не имеют.

Запрос читает только `reserved` и `uncertain` текущего доступного бренда. Ответ содержит `calls` с `id`, `status`, `family`, `reservedMicros` (десятичная строка), `createdAt`, `updatedAt` и `nextCursor`. Страницы ограничены 50 строками; `after` — ULID последней записи предыдущей страницы. Клиент должен заново прочитать список при изменении контекста; список не является снимком нескольких страниц при параллельных изменениях. Ответ содержит `Cache-Control: private, no-store`. Текст, ответы, модели, имена провайдеров, сообщения об ошибках, идентификаторы объектов и ключи в проекцию не входят. Запросы к поставщикам и изменения расходов/резервов отсутствуют; стандартное обслуживание lease сессии остаётся частью существующего middleware.

`reserved` может обозначать ещё выполняющийся вызов; наличие записи в списке не доказывает его завершения или итоговой стоимости. Действие восстановления, проверка провайдера, UI, audit восстановления и снятие блокировок не реализованы. Произвольные ручные суммы, сохранённые ответы и свободный текст не являются доказательством. Два существующих метода сверки остаются закрытыми, резерв при неопределённости сохраняется. Исторические ошибочно освобождённые `failed` этим списком не выявляются. Live shadow этот результат не разрешает.
