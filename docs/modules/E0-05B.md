# E0-05B — операторская сверка расходов ИИ

Существующий `GET /ai/recovery/calls` возвращает по 50 `reserved`/`uncertain` вызовов выбранного бренда. Контракт списка и его минимальная проекция сохранены.

Добавлен `App\Ai\Http\RecoverCallController`, но маршрут POST вне scope задачи. Интегратору требуется зарегистрировать `POST /ai/recovery/calls/{callId}/reconcile` (имя `ai.recovery.calls.reconcile`) в `routes/features/E0-05B.php` с теми же middleware `auth.version`, `auth.nostore` внутри группы `web/auth/verified/tenant`, что и список. Успех: JSON `{status: completed|failed, costMicros: number}`, `Cache-Control: private, no-store`. Ошибки оставляют резерв неизменным. Действие доступно только действующему назначенному владельцу организации с `billing.manage` и выбранным брендом.

Новый столбец `ai_calls.provider_generation_id` сохраняет ID из ответа OpenRouter, включая неполный ответ с неопределённым исходом. Если ответ не содержит валидный ID, восстановление закрыто. Старые вызовы без сохранённого ID остаются заблокированными. Прежний ID не заменяется при повторном неполном ответе.

Действие читает `GET https://openrouter.ai/api/v1/generation?id=<сохранённый ID>` с настроенным ключом. Требуются HTTP 200, точное совпадение ID, `cancelled=false`, конечная причина завершения и проверяемый `total_cost`. 404, таймаут, неверные поля и ошибка разбора не доказывают отсутствие расхода. Ответ провайдера не возвращается клиенту; хранится SHA-256 тела доказательства. Резерв `reserved` моложе 10 минут не сверяется.

При подтверждённой нулевой стоимости резерв освобождается; без пригодного ответа вызов помечается `failed`. При положительной стоимости сумма переносится в `spent_micros`, учитывается в `object_costs`, включая подтверждённое превышение резерва. Сохранённый нормализованный ответ с той же стоимостью делает вызов `completed`; без пригодного ответа вызов `failed` с кодом `reconciled_billed_without_result`. Повтор платного вызова автоматически не выполняется. Все изменения и аудит `ai.call.reconciled` находятся в одной транзакции.

Свободные ручные суммы и строки «доказательства» не принимаются. Старые публичные `Gateway::reconcileSuccess/Unbilled` остаются закрытыми. Без регистрации POST и операторского экрана сценарий недоступен из кабинета; live shadow пока не разрешён.
