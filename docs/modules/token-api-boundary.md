# Граница API-ключей бренда

`GET /api/v1/brand` возвращает идентификатор и название бренда, которому принадлежит ключ. Требуется явный bearer-ключ `id|secret` с разрешением `read`; браузерная cookie-сессия не аутентифицирует API. `turn` и `leads` зарезервированы для будущего E5-03 и не означают, что соответствующие endpoint уже существуют. `X-Brand-Id`, если передан, может только подтвердить текущий бренд; не совпадающее значение даёт 404.

Sanctum использует `BrandAccessToken`, принимающий только преобразованный ранней границей запроса SHA-256. Сам bearer удаляется из заголовка и серверного объекта до framework guard и журналирования; полученный digest проверяется с постоянным временем против хеша существующего ключа. Поиск tokenable производится только для сверенного типа `Brand`, связанных id/organization и после проверки хеша. На каждом запросе `tenant.token` повторно блокирует организацию, бренд и токен именно в этом порядке, проверяет активность, отзыв и истечение, затем устанавливает изолированный `TenantContext`. `token.ability` требует явно перечисленного scope; wildcard не действует. Последнее использование записывается в той же транзакции.

API принимает ключи только по HTTPS либо в local/testing при обоих реальных адресах клиента и сервера loopback и без прокси-заголовков. HTTPS за reverse proxy допустим только при явно настроенном списке IP/CIDR доверенных прокси и корректной настройке backend, исключающей прямой доступ; автоматическое доверие Laravel по имени Host и записи `*`, `**`, `REMOTE_ADDR`, `PRIVATE_SUBNETS` не принимаются. При сетевом HTTP ответ 403. Защита описывает приложение: access-логи веб-сервера, обратного прокси и внешних средств наблюдения должны отдельно исключать Authorization. Не включать логи заголовков с секретами.

До проверки bearer добавлен отдельный предел: 60 запросов за 60 секунд по фактическому `REMOTE_ADDR` без доверия Host и forwarded-заголовкам. IPv6-формы нормализуются, IPv4-mapped IPv6 и соответствующий IPv4 используют одну корзину; отсутствующий или невалидный адрес закрывает запрос с 403. Один общий cache lock сериализует проверку и увеличение счётчика между процессами. При недоступности блокировки/cache или неподходящем драйвере API отвечает 503, а не пропускает запрос без ограничения; предыдущий `throttle:api` после аутентификации сохранён.

Для нескольких серверов требуется корректно настроенное общее хранилище блокировок и счётчиков (database, Redis или Memcached). Файловый cache допускается лишь для односерверной локальной установки и тестов, array — только внутри PHPUnit. Адрес балансировщика/прокси считается единственным физическим клиентом: лимит будет общим для всех пользователей за ним; перед эксплуатацией нужно оценить топологию и ёмкость. Сбой или задержка cache могут временно закрыть API. Блокировка имеет ограниченный срок; поведение при остановке процесса дольше этого срока, отказах cache и при распределённой сетевой перегородке отдельно не доказано. Ограничение не заменяет сетевой rate limit и защиту веб-сервера.

Транзакция `tenant.token` охватывает downstream API action, чтобы изменение состояния не обгоняло отзыв ключа. API actions не должны выполнять в ней внешние сетевые запросы; внешнюю работу нужно передавать в job/outbox после commit. Неиспользуемые ключи и `created_at` не изменяются при проверке. На случай долгоживущих worker режимов требуется отдельная проверка изоляции request-scoped контейнера до их включения.

Таблица `personal_access_tokens` принадлежит E1-10. Этот helper должен интегрироваться вместе с проверенной миграцией и реальным UI создания/отзыва ключей; без таблицы endpoint не готов. Текущие проверки используют синтетические ключи, отдельную БД, реальную HTTP-цепочку Laravel и временную копию фактической миграции E1-10; внешних сетевых вызовов нет. Успешно проверены read/401/403/404, отсутствие допуска по cookie, истечение/отзыв, изоляция брендов, гонка отзыва между guard и действием, отказ подменённому Host и raw bearer в ответе/журналируемой ошибке при `zend.exception_ignore_args=0`. E5-03 обязан дополнительно протестировать каждый свой endpoint, межпроцессный отзыв и реальные mutation/idempotency пути.
