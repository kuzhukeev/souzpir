# SP-E8-03 — наборы вопросов

## Граница и хранилище

Операции кандидатов и утверждение проходят `ProfileAccess::run`: действующая lease, серверный tenant, активные организация/бренд/membership, модуль и `vision.quiz.write` повторно проверяются под транзакционными блокировками. Чтение утверждённых наборов для viewer/manager использует lease, tenant, module и `reports.read`; им не возвращаются кандидаты или приватная анкета. Приватные тексты не входят в Inertia props/history: страницы получают их отдельным JSON no-store в памяти браузера. Ошибки HTTP перехватываются до exception reporter, audit содержит ID и счётчики, но не тексты.

Ручные и явно импортированные из собственной анкеты вопросы сохраняются в существующих `question_candidates` E8-01F, в отдельных для actor/profile/origin batch со статусом **blocked**. Собственная `vision_question_manual_batches` содержит provenance `manual`/`questionnaire`, composite tenant/profile/quiz/batch FK и автора; она не меняет общую схему. Импорт только по явному действию и выбранному намерению, повторное действие идемпотентно; некорректные вопросы пропускаются с явным счётчиком. Удалить можно только собственный вопрос с origin=manual; импортированный из анкеты или перенесённый из набора можно отключить. Извлечение, сохранение и проверка текста не вызывает AI или сеть.

Утверждение принимает доступные candidates текущей версии профиля, не включая скрытые blocked batches без собственного sidecar. Под блокировками проверяются лимиты `vision.questions` / `vision.models`, ProviderCatalog (только active), идентификаторы и содержимое. Отсутствующий тарифный лимит не превращается в ноль или выдуманную величину. Core `QuestionSets::create` создаёт настоящий immutable набор `{id,text,intent}` с версией и checksum; в той же транзакции аудируется действие и переключается `vision_question_approvals` с composite FK на набор, автором и provider/model panel. Предыдущие наборы остаются неизменными. Текущая выбранная комбинация моделей сохранена как metadata; частота не настроена (принимается только null).

## Интеграционные запросы

- Будущий владелец очереди генерации обязан исключить batches с sidecar `vision_question_manual_batches` (`origin=manual`, `questionnaire` или `active_set`) из генерации, rebuild и любых автоматических consumer. Их статус остаётся blocked; эта ветка не выдаёт их за AI generation. Для настоящей AI-генерации приватной анкеты нужны отдельные data class/grant/data policy/ContactBoundary и разрешённый live этап. Генератор в этой задаче отсутствует.
- `MeasurementRunner::start` принимает произвольный set ID и сам не проверяет active pointer. SP-E8-04 должна tenant-qualified выбирать `vision_question_approvals.active=true`, проверять актуальную session/permission/grant и использовать сохранённый provider panel либо согласованный операторский выбор. Тест передаёт фактический active set ID в `MeasurementRunner::start` с синтетическим published grant и fake AI: создаются pending measurement/answer, сетевых запросов и ai_calls нет. Продуктовый UI не запускает замер и не создаёт расписание; эти действия отмечены «Скоро».
- Интегратору как владельцу `docs/contracts/registry.json` зарегистрировать собственные sidecar таблицы `vision_question_manual_batches` (brand tenant, parent `question_generation_batches`) и `vision_question_approvals` (brand tenant, parent `question_sets`) и `vision_question_copy_entries` (brand tenant, parents `question_candidates`, `question_sets`).
- После изменения профиля действие «Изменить набор» копирует проверенные вопросы из активного immutable set в новые candidates текущего профиля с `origin=active_set`, source set/question provenance и повторной проверкой имени бренда; повтор идемпотентен, неподходящие вопросы пропускаются со счётчиком. Уже существующие кандидаты в текущем профиле переиспользуются без дублирования и без изменения сделанного пользователем выбора или статуса. Старый набор не меняется.
- Список истории ограничен последними 100 версиями; при росте нужна пагинация. Коммерческие значения и оценки не заданы и не выдумываются.
- API с приватными вопросами разрешает только HTTPS и точный localhost/127.0.0.1/[::1]; static shell не содержит приватных данных. Обычный HTTP .local API отклоняет.
