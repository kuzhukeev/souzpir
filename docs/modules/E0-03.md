# Права и политики E0-03

`config/permissions.php` содержит фиксированные подписи пяти ролей и словарь действий. Реальные технические роли остаются owner/admin/member/viewer; member с `settings.sales_manager=true` получает роль manager, без флага — editor. Неизвестная роль, настройка или способность закрывают доступ. Удаление организации и пользовательские роли отсутствуют.

`PermissionEvaluator` реализует общий `App\Providers\Features\PermissionEvaluator`. `config/features/E0-03.php` регистрирует каждую способность через FeatureRegistry в Laravel Gate и регистрирует `BrandPolicy`/`MembershipPolicy`. Каждое решение проверяет совпадение пользователя, организации, активной membership, активного выбранного бренда и его grant; архив или отзыв действует сразу. Переданные модели должны иметь загруженный tenant и не могут пересекать организацию или выбранный бренд. Модельные политики не заменяют scoped lookup, который возвращает 404 для чужого объекта.

Матрица соответствует S-3.3: owner — полный доступ, admin — кроме платежных изменений и передачи владельца, editor — работа со знаниями и вопросами без изменения настроек модулей, команды и интеграций, manager — диалоги/клиенты/подсказки и чтение отчёта Видения, viewer — чтение. Для таблицы тарифов макет S-3.3 запрещает редактору/менеджеру доступ, хотя другая строка 04c описывает чтение тарифов для всех; выбран более ограничительный вариант до отдельного решения. Настройки только своей учётной записи требуют дополнительной проверки субъекта будущим Action; `profile.own` не является правом на чужой аккаунт.

`PermissionSharedProps` возвращает ленивую карту `can` из одной проверки membership и бренда; без пользователя — пустой набор. `usePermissions` в feature-папке показывает только UX и никогда не заменяет проверку на сервере. Публичный путь `resources/js/hooks/usePermissions.ts` и типогенерация принадлежат E0-08; интегратор должен согласовать с ним реэкспорт или эквивалент.

Сейчас evaluator намеренно требует активный бренд. Отдельный organization-only onboarding для организации без бренда должен быть добавлен перед E1-02 согласно `docs/contracts/integration-followups.md`, без ослабления брендовых маршрутов. Передача владельца и редактирование состава команды реализуются отдельными Actions с транзакционными проверками; policies самостоятельно их не выполняют.

При интеграционной сверке добавлен словарь способностей из `docs/contracts/core.md`: управление организацией, командой и оплатой, работа с диалогами, анкета и отчёты. Изменение настроек модулей ограничено owner/admin; на все пять ролей добавлены проверки Gate.
