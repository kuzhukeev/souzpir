# Одноразовый обмен приглашения

- `invitations.exchanged_at` — необратимый признак первого успешного обмена. Его устанавливает Auth в транзакции под блокировкой приглашения; владелец схемы `invitations` — Tenancy (SP-E0-02). API прямого приёма и просмотра токена Tenancy обязан отвергать уже обменянные ссылки. Принятие по серверному grant повторно проверяет организацию, срок, отзыв, адрес и принятие.
- `invitation_exchange_sessions` принадлежит Auth (SP-E1-01). Ключ — HMAC идентификатора сессии; секрет ссылки и сам ID сессии в таблице не хранятся. `document_epoch` и `sequence` отсеивают запоздавшие запросы, `invitation_id` и срок grant — единственный серверный источник полномочий. Сериализованные данные обычной сессии не являются доказательством доступа.
- Вход, регистрация и MFA переносят grant при смене session ID и меняют epoch, предыдущий ID больше не получает доступ. Logout удаляет grant. `show`, `register`, `accept` не принимают ID приглашения от браузера. При конфликте документ, последним зарегистрированный сервером, имеет приоритет; недоставленный запрос о новом документе сервер не может предугадать.
- Exchange делает bearer одноразовым до принятия; потерянный ответ может потребовать повторной отправки приглашения. Предварительное открытие ссылки email-сканером без выполнения JS не расходует её; выполнение JS сканером может расходовать. Первоначальный URL до обмена и истории браузеров без Navigation API могут содержать ещё действительный fragment.
- Истёкшие записи удаляет ограниченная пакетами команда `auth:prune-invitation-exchanges`; она планируется ежечасно при включённом штатном scheduler. Без работающего scheduler записи накапливаются, но просроченный grant не действует. Откат миграции отзывает уже обменянные приглашения, чтобы не оживить старые ссылки.
