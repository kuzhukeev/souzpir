# Каркас кабинета

`CabinetLayout` принимает содержимое, необязательные `breadcrumbs` (`{label, href?}[]`) и необязательный флаг `brandSwitchReady`, по умолчанию `false`. Авторизованные Inertia-страницы оборачивают содержимое в layout. SharedPropsV1 — единственный источник текущего пользователя, организации, бренда, доступов, темы и счётчика уведомлений. Неизвестные значения не превращаются в нули или демоданные.

Канонические разделы и адреса находятся в `resources/js/components/navigation/navigation.json`; PHP-конфигурация и русские переводы читают тот же файл. Ссылкой считается только зарегистрированный в Ziggy GET-маршрут с точным URI. Незарегистрированные пункты не кликабельны и помечены «Скоро»; permissions скрывают пункты без явно выданного права. Разделы с отрицательным состоянием модуля показывают «Не подключён», `null` не считается отключением. Добавляя реальные экраны, проверяйте соответствие URI и способность/политику на сервере; Ziggy и UI не заменяют авторизацию. Навигация знает 11 разделов продавца. Для Видения отражены пока два пункта принятого превью, состав остальных экранов интегрируется их владельцами.

Выбор бренда полностью заблокирован до появления стабильной авторизованной главной: текущий `POST /brand/switch` перенаправляет на `/`, который в production не является страницей кабинета. E1-03 должен реализовать `/dashboard`, изменить серверный redirect на него, гарантировать очистку/отмену запросов предыдущего бренда и лишь после проверки передать `brandSwitchReady`. При включении компонент отправляет реальный ID в `POST /brand/switch`, оставляет текущий бренд из серверных props, блокирует повтор во время запроса и показывает ошибку; нельзя включать только по наличию маршрута. При смене бренда данные обрабатываются серверной политикой, интерфейс не является границей доступа.

Ширина панели 280px, свёрнутая 72px; при 768–1279px используется узкий вариант, на мобильном — диалог слева с возвратом фокуса. Пользовательское состояние хранится только локально; отсутствие localStorage допустимо. Пункты вложенного меню имеют иконки, заметное выделение активного пункта и клавиатурный фокус. Никакая тестовая страница не входит в production routes.

Автономный браузерный стенд собирается командой `npx vite build --config vite.layout.config.ts` после `npm run build` и использует те же собранные CSS и шрифты. CI запускает его как статические файлы на отдельном порту, без повторного сканирования Tailwind.
