# Живые данные кабинета

createQueryClient создаёт TanStack Query v5 клиент: staleTime 0, gcTime 5 минут, обновление при фокусе. Экземпляр создаётся один раз для браузерного приложения и отдельно для каждого SSR-запроса. Данные кэша не сохраняются в localStorage; секреты, токены и полные credentials в Query не помещаются.

brandQueryKey({ organizationId, brandId }, ...parts) обязателен для всех данных бренда; пустой контекст отвергается. usePolling не делает запрос без бренда; отключённый observer отсоединяется от старого ключа и таймера. Запрос отменяется, когда у него не осталось других наблюдателей и queryFn использует AbortSignal. При наличии других наблюдателей их запрос продолжает выполняться. При глобальной смене бренда clearBrandQueries намеренно отменяет все запросы старого бренда. Базовые интервалы: диалог 5 с, список 20 с, уведомления 60 с. Ошибки остаются в состоянии Query и показываются экраном; автоматическая имитация успешного ответа не допускается.

useBrandHttp использует Inertia useHttp для JSON-мутаций и после успешного POST/PUT/PATCH/DELETE инвалидирует только запросы текущего бренда. Ошибки и отмена не считаются успехом. Отдельный submit и fluent-методы dontRemember, optimistic, withAllErrors, withPrecognition не экспортируются: они возвращают исходную форму и обходят инвалидацию; запросы на изменение запускают указанными методами. Форма создаётся без rememberKey. Секретные формы нельзя сохранять в remember или Query. HTTP-ответ и авторизация на сервере остаются источником истины.

При смене бренда интерфейс сначала блокирует старые операции и останавливает текущие useHttp запросы через cancel(), затем await clearBrandQueries(client, previousScope): функция отменяет и удаляет только запросы старых организации и бренда. После подтверждённого сервером переключения страница размонтируется/переходит на безопасный маршрут и получает новые props; Query ключи гарантируют отсутствие данных прежнего бренда. При выходе вызывается client.clear(). Новый QueryClientProvider в корне и вызовы этих действий при смене бренда/выходе — интеграционные изменения вне области F-04; они выполняются интегратором и SP-E1-03. Сам F-04 не делает сетевых обращений автоматически и не включает переключатель до готовности маршрута.
