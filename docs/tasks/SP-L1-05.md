# SP-L1-05 · Отправка черновика ИИ в один клик

**Зачем:** в режиме черновиков менеджер не может отправить готовый черновик. ReadySuggestions::read() (app/Seller/Dialogs/ReadySuggestions.php:12–47) отдаёт черновик, DialogsController.php:66–67 передаёт только текст readySuggestion без id хода; кнопка «Использовать в ответе» (resources/js/pages/Seller/Dialogs/Index.tsx:120) лишь подставляет текст, далее «Чтобы отправить ответ, заберите диалог себе.»; DialogMessageController.php:30 требует mode manager и назначение. CHECK статусов seller_turns (database/migrations/C-02/2026_11_01_040000_c02_uncertain_turn_on_inbound.php:97) не содержит sent/edited.
**Часть чего:** волна «Запуск-1» (planning/QUEUE.md): прод с живыми Продавцом (Telegram, режим черновиков) и Видением; экраны после запуска.
**Зависимость:** нет; граница с SP-L1-04 — существующий job DeliverManagerMessage (его не менять). Статусы доставки live появятся после SP-L1-04.

## Приёмка
- В режиме suggest у готового черновика кнопки «Отправить» и «Изменить и отправить» (правка в поле ответа, затем отправка); перевод диалога в режим manager не требуется; права — как у ответа в диалоге (существующая политика).
- Новый маршрут POST /seller/dialogs/{dialog}/suggestions/{turn}/send в routes/features/L1-05.php (routes/features/E5-04.php не трогать): ход проверяется по условиям ReadySuggestions (актуальная ревизия, хеш outcome), создаётся сообщение менеджера с исходным или изменённым текстом и ставится существующий DeliverManagerMessage.
- Статус хода sent или edited (миграция database/migrations/L1-05/ расширяет CHECK), кто и когда отправил; исходный текст черновика остаётся в outcome; двойной клик или повтор — одно сообщение (409 или идемпотентно).
- Устаревший черновик (после него пришло сообщение клиента) — отказ «Черновик устарел»; следующее сообщение клиента создаёт новый черновик (QueueLiveDraft.php:11–14), блок показывает новый.
- Под сообщением менеджера виден статус доставки (fake / отправлено / ошибка — после SP-L1-04).
- Тесты tests/Feature/Launch/L1-05/: отправка, правка и отправка, права, изоляция, устаревший черновик, повтор, новый черновик после сообщения клиента; Queue::fake для DeliverManagerMessage.
- Feature-тесты только с Http::fake/Queue::fake, без живых и платных вызовов; ключи и токены только из env/config, не в коде и не в логах. Рефакторинг сверх нужного запрещён; чужие модули не менять; итоговый отчёт docs/results/SP-L1-05.md до 30 строк (тесты, долг, решения).
