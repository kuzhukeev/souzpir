# SP-E1-01G · Защита ссылок восстановления в журналах

Прочитать AGENTS.md и docs/preparation/decisions.md. Атомарный claim и отдельный Git worktree.

Цель: Исключить запись токена восстановления и адреса из URL во все журналы доступов и ошибок веб-сервера, прокси и приложения; проверить заголовки Referrer-Policy и Cache-Control, корректность маршрута и процесс настройки OSPanel без отключения остальных журналов.

Зависимости: SP-E1-01F.
Область записи: infra/osp/, docs/runbooks/, tests/Feature/Shell/Auth/PasswordLogSafety/, docs/modules/E1-01G.md, docs/results/SP-E1-01G.md.
Приёмка:
- Проверить реальные поддерживаемые конфигурации локального веб-сервера и прокси на синтетической ссылке: токен и email отсутствуют в access/error/application logs, прочие события продолжают логироваться; проверить заголовки, редиректы и кэш. Только тестовые данные, реальную почту не отправлять.
- Документировать и автоматизировать воспроизводимую настройку без разрушительных правок; для неизвестных production-прокси — fail-closed и чёткое условие готовности.

До фактической проверки всех точек логирования включать реальную доставку восстановления нельзя. Обновление конфигурации OSPanel с перезапуском планируется отдельно и выполняется без влияния на другие проекты по возможности.
Не менять общие контракты за пределами scope; после работы commit и submit, done ставит интегратор после независимой проверки.

## Решение пользователя 01.11.2026: новая ссылка восстановления

Секрет и email не передаются веб-серверу в адресе: новая ссылка использует фрагмент, клиент очищает его из адресной строки и передаёт данные POST-запросом; для рабочего сервера требуется HTTPS, для одобренного локального `souzpir.local` допустим HTTP. Старые ссылки и выпущенные ими токены не принимаются; не удалять рабочие данные и не включать реальную доставку при реализации. Сохранить существующие проверки одноразовости, срока действия, смены сессий и прав. Включение SMTP и переход работающей базы — отдельная проверенная интеграция.

Для этого решения scope дополнен: `app/Shell/Auth/Http/PasswordController.php`, `app/Shell/Auth/PasswordDelivery/`, `resources/js/pages/Shell/Auth/ResetPassword.tsx`, `resources/js/features/Shell/Auth/`, `routes/features/E1-01.php`, `tests/Feature/Shell/Auth/PasswordDelivery/`, `tests/Feature/Shell/Auth/AuthFlowTest.php`, `tests/Browser/E1-01/`. Не менять общую конфигурацию OSPanel и другие сайты. Применять узкие проверки на отдельной базе и fake-почте; сверить журналы и браузерную историю на синтетических данных.
