# SP-L1-06 · Уведомления менеджеров о сообщениях и черновиках

**Зачем:** менеджер не узнаёт о новом сообщении клиента и готовом черновике. В EventCatalog (app/Shell/Notifications/EventCatalog.php) нет событий входящего сообщения и готового черновика; RecipientPolicy.php:23 даёт участникам только handed_off/contact.reminder; DrainNotifications зарегистрирован (config/features/E0-04.php:10), но не в расписании (routes/console.php:9–13); TelegramSender::managers() (TelegramSender.php:29) не используется. Расписание через секцию schedules и ScheduleContributor (app/Providers/Features/FeatureRegistry.php:175–185, флаг runtime.features_scheduling_enabled, :121).
**Часть чего:** волна «Запуск-1» (planning/QUEUE.md): прод с живыми Продавцом (Telegram, режим черновиков) и Видением; экраны после запуска.
**Зависимость:** SP-L1-01 (LiveDraftJob). app/Shell/Notifications/ занят SP-E1-10K — брать после его слияния (блокирует пересечение scope).

## Приёмка
- События seller.conversation.inbound (сообщение клиента) и seller.draft.ready (LiveDraftJob перевёл ход в suggested) в EventCatalog; получатели — менеджеры бренда (RecipientPolicy).
- Доставка: список в кабинете (cabinet_notifications) и группа менеджеров бренда в Telegram (managers_chat_id канала через TelegramSender::managers или ExternalDelivery); живая отправка только при NOTIFICATIONS_EXTERNAL_ENABLED, иначе fake.
- Дедупликация: не больше одного уведомления на диалог и тип события за N минут (config, по умолчанию 5).
- DrainNotifications в расписании через ScheduleContributor из config/features/L1-06.php (каждую минуту, withoutOverlapping), routes/console.php не трогать.
- Текст без персональных данных сверх имени и канала, со ссылкой на диалог.
- Тесты tests/Feature/Launch/L1-06/ с Http::fake на Telegram: входящее → кабинет и группа, черновик → уведомление, дедупликация, расписание зарегистрировано, изоляция бренда, выключенный режим.
- Feature-тесты только с Http::fake/Queue::fake, без живых и платных вызовов; ключи и токены только из env/config, не в коде и не в логах. Рефакторинг сверх нужного запрещён; чужие модули не менять; итоговый отчёт docs/results/SP-L1-06.md до 30 строк (тесты, долг, решения).

Scope: `app/Seller/Notifications/`, `config/features/L1-06.php`, `app/Shell/Notifications/EventCatalog.php`, `app/Shell/Notifications/RecipientPolicy.php`, `app/Seller/Live/LiveDraftJob.php`, `tests/Feature/Launch/L1-06/`, `docs/results/SP-L1-06.md`.
