# SP-E1-10K · Автоматические вебхуки и общие уведомления

**Зачем:** конкретные незакрытые сценарии S-5.2 и S-5.3 по журналу макетов [27], [28].
**Часть чего:** частичная сдача SP-E1-10J, docs/results/SP-E1-10J.md.
**Зависимость:** SP-E1-10J.

## Приёмка
- S-5.2: при создании события сохранять согласованный снимок подписанных вебхуков текущего бренда и формировать доставки через outbox и очередь; fake-транспорт подписывает тело, повторяет ошибки и показывает статус. Реальную отправку оставить выключенной.
- S-5.3: события из матрицы общих уведомлений ставить в очередь для сохранённых адресов почты и подтверждённого Telegram с fake-транспортом; показать результат и ошибки, сохранить изоляцию бренда и права.
- Проверить полный путь событие → снимок/маршрутизация → хранение → очередь → fake-доставка → видимый результат, повтор и ошибки на отдельной тестовой БД; без живых и платных вызовов.
