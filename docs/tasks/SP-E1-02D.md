# SP-E1-02D · Оболочка: экран «Выберите компанию» (S-0.7) для одной организации

**Зачем:** решение владельца от 03.11.2026: задач должно хватать на 100 % закрытие экранов по функционалу; S-0.7 был единственным экраном макета без карточки. Владелец согласовал: экран верстается по макету с данными текущей (единственной) организации, без выбора между организациями.
**Часть чего:** оболочка кабинета (вход и точка входа, рядом с SP-E1-02C и HomeEntry). Решение «одна организация» из AGENTS.md остаётся в силе: карточка не вводит членство в нескольких организациях и переключение контекста.
**Зависимости:** SP-E1-02C (логотип организации из мастера первого запуска).

- Экран S-0.7 «Выберите компанию» соответствует макету из матрицы по пунктам (журнал docs/sources/02b_mockup_journal.md [11], матрица docs/sources/02_screens_matrix.md строка S-0.7): маршрут `GET /context/organization` (имя `context.organization`), страница `resources/js/pages/Shell/Context/OrganizationSelect.tsx`; заголовок «Выберите компанию», поле поиска по названию (фильтрует список на клиенте), строка «Доступно компаний: N» (N = число организаций, доступных пользователю; сейчас всегда 1), карточки компаний: аватар (логотип организации, если загружен в мастере, иначе инициалы названия), название, роль пользователя, чипы брендов, «Последний вход». Клик по карточке ведёт на точку входа кабинета (HomeEntry), без смены контекста: организация у пользователя одна и выбрана всегда.
- Данные настоящие, не заглушка: организация из текущего контекста; роль из `memberships.role` с подписями по журналу [11] — owner «Владелец», admin «Администратор», member «Редактор» или «Менеджер» при `settings.sales_manager = true`, viewer «Наблюдатель»; чипы брендов — только бренды, доступные участнику (`Membership::brand_ids`, owner/admin с пустым списком видят все); «Последний вход» — `member_last_logins.last_login_at` текущего пользователя в формате «сегодня в 12:40 / вчера / 1 ноя», если входа ещё не было — «впервые». Отключённое членство (`status = disabled`) на экран не попадает: 403 как в остальных экранах оболочки.
- Точка входа на экран: ссылка «Выбор компании» в меню профиля/оболочки и карточка на HomeEntry (S-1.x точка входа) только если у пользователя есть доступ к кабинету; после входа экран не показывается принудительно (решение владельца: не добавлять лишний клик при одной компании). Пустое состояние поиска «Ничего не найдено» со сбросом фильтра; состояния загрузки и ошибки как на макете.
- В AGENTS.md строка про одну организацию дополнена: «S-0.7 верстается как экран с одной компанией (SP-E1-02D), выбор между организациями не вводится». Исполнитель не добавляет таблицы, миграции и middleware для нескольких организаций; если какой-то пункт макета требует второй организации, пункт записывается в docs/decisions-pending.md, а не реализуется.
- Каждый пункт покрыт Feature- или Browser-тестом (роль каждого типа, подпись «Менеджер» для sales_manager, бренды по brand_ids, «впервые» без записи в member_last_logins, поиск с пустым результатом, 403 для disabled); данные только текущей организации; в отчёте скриншот экрана рядом с макетом 11/5513d4ce-S-0.7-company-select-v2.webp.
- Без живых и платных внешних вызовов без разрешения владельца; если пункт макета противоречит ТЗ или требует решения владельца, исполнитель не выдумывает, а записывает вопрос в docs/decisions-pending.md и делает остальное.
- Сдача частями: если что-то из пунктов не сделано, в отчёте раздел «Остаток» перечисляет невыполненные пункты по экранам; интегратор принимает такой отчёт только вместе с заведённой карточкой-продолжением на этот остаток (правило в AGENTS.md).
