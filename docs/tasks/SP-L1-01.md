**Зачем:** запуск на живом OpenRouter без риска перерасхода. Сейчас лимит только в строке ai_budgets на org+brand+family+месяц (app/Ai/Gateway.php:989–1008), исчерпание — нетипизированный LogicException('AI budget exhausted.') (Gateway.php:1032), живой бюджет без reservation_request_limits модели отказывает (Gateway.php:1013–1017), а config/features/E0-05.php:34–36 пуст (reservation_micros [], reservation_request_limits [], budget_threshold_basis_points null). Глобального дневного/месячного потолка нет.
**Часть чего:** волна «Запуск-1» (planning/QUEUE.md): прод с живыми Продавцом (Telegram, режим черновиков) и Видением; экраны после запуска.
**Зависимость:** нет; можно брать параллельно с другими SP-L1 без пересечения scope.

## Приёмка
- Глобальные потолки из env: AI_BUDGET_MONTHLY_USD (по умолчанию 30) и AI_BUDGET_DAILY_USD (по умолчанию 3) в новом config/features/L1-01.php; проверка в Gateway::reserve() до HTTP-запроса. Резерв считается по максимуму запроса; неопределённые вызовы (uncertain/unresolved) учитываются по зарезервированному максимуму до сверки.
- Месячный лимит организации из тарифа (config) с переопределением командой администратора `ai:budget:set-org {organization} {usd}`; лимит агрегирует все бренды и семейства организации (строки ai_budgets сейчас по brand+family).
- Границы запросов (reservation_request_limits: max_input_bytes, max_output_tokens; reservation_micros) из config/features/L1-01.php для моделей seller.live_draft (config/features/LV-01.php), vis.measure (config/features/E8-01.php) и разбора/подтверждения доказательств (VISION_EVIDENCE_PARSER_MODEL, по умолчанию google/gemini-2.5-flash); значения по умолчанию проходят проверку Gateway.php:1013–1017.
- 80 %: одно событие ai.budget.threshold_reached за период (существующий notifyThreshold, Gateway.php:1187), warning в лог и строка на экране оператора OperatorAiRecovery: расход/резерв/лимит сегодня и за месяц, % использования. Повторно в том же периоде не отправляется.
- 100 %: жёсткий стоп до HTTP-запроса типизированным исключением App\Ai\Budget\BudgetExhausted (extends LogicException, чтобы существующие catch не сломались) с уровнем global_daily / global_monthly / organization.
- Продавец под стопом: LiveDraftJob не создаёт черновик, ход завершается failed с error_code budget_exhausted, диалог помечается для ручного ответа существующим механизмом передачи менеджеру (handed_off_at / seller.conversation.handed_off), без повторных попыток и без правки экрана диалогов.
- Видение под стопом: MeasurementRunner не берёт новые слоты (оставшиеся pending → failed, error_code budget_exhausted; сейчас любой Throwable даёт uncertain, MeasurementRunner.php:193), уже идущий слот доводится до конца; замер в списке показывает «Остановлен лимитом» (stateLabel, resources/js/pages/Vision/Measurements/Index.tsx:34). Если нужен отдельный статус — миграция в database/migrations/L1-01/ (CHECK vision_measurement_status_check, database/migrations/E8-01/2026_10_31_080100_create_vision_core_tables.php:84).
- Команда `ai:budget` печатает расход, резерв и лимит за сегодня и за месяц: глобально и по каждой организации; без секретов.
- Тесты tests/Feature/Launch/L1-01/ с Http::fake: 79→80 % событие один раз, 100 % стоп до HTTP (Http::assertNothingSent), дневной и месячный потолок, лимит организации через команду, uncertain по максимуму, стоп Продавца и Видения, вывод ai:budget.
- Feature-тесты только с Http::fake/Queue::fake, без живых и платных вызовов; ключи и токены только из env/config, не в коде и не в логах. Рефакторинг сверх нужного запрещён; чужие модули не менять; итоговый отчёт docs/results/SP-L1-01.md до 30 строк (тесты, долг, решения).
