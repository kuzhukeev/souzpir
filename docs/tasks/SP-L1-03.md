**Зависимость:** нет; можно брать параллельно с другими SP-L1 без пересечения scope.

## Приёмка
- В настройках бренда раздел «Передача данных в ИИ» с четырьмя переключателями: conversation_content (переписка с клиентами), knowledge_internal (внутренние знания), vision_question (вопросы замера Видения), knowledge_public (публичные знания). Менять может только владелец (role owner); остальные видят только чтение; серверная проверка, 403 для не-владельца.
- Сохранение пишет settings.ai_data_policy в формате, который читает Gateway (разрешено → ['any'], запрещено → []); тест через Gateway: разрешено — проходит, запрещено — «Brand data policy does not authorize this external AI transfer.».
- Команда `brand:ai-policy {brand} --allow=conversation_content,knowledge_internal,vision_question,knowledge_public` (и --deny=…; без опций печатает текущую политику); неизвестный класс — ошибка; по умолчанию deny для новых брендов и отсутствующих ключей.
- Смена knowledge_public при активных грантах: ошибка триггера показывается понятным сообщением (не 500), команда завершается ненулевым кодом с текстом.
- Запись в аудит: кто, что, когда, через существующий аудит.
- Тесты tests/Feature/Launch/L1-03/: права owner/admin/manager, props страницы, команда, deny по умолчанию, триггер, изоляция (бренд другой организации недоступен).
- Feature-тесты только с Http::fake/Queue::fake, без живых и платных вызовов; ключи и токены только из env/config, не в коде и не в логах. Рефакторинг сверх нужного запрещён; чужие модули не менять; итоговый отчёт docs/results/SP-L1-03.md до 30 строк (тесты, долг, решения).
