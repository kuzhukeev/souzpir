# SP-E7-06 · Продавец: дефекты меток качества и списка клиентов

**Зачем:** решение владельца от 03.11.2026 по повторному аудиту 160 экранов закрыть оставшиеся расхождения с макетами; экраны D-7.1, D-3.1.
**Часть чего:** дефекты из повторного аудита 160 экранов.
**Зависимости:** нет.

- Качество D-7.1: словарь меток в Quality/Index.tsx:7 знает только 6 типов ошибок, а Quality/Day.tsx:9 знает полный список. Остальные выводятся сырыми кодами с пробелами вместо «_». Нужен один общий словарь для обеих страниц; тест: ни один тип ошибки из БД не выводится кодом.
- Клиенты D-3.1: колонка каналов выводит сырой код канала вместо названия и иконки (Customers/Index.tsx:16). Список строится запросом на каждую строку (CustomersController.php:53-82): N+1 убрать, перейти на paginate(); тест проверяет число запросов на 50 клиентов.
- Каждый пункт покрыт Feature- или Browser-тестом; данные только текущего бренда, проверены права ролей; состояния пусто / загрузка / ошибка как на макете; в отчёте скриншоты каждого экрана рядом с макетом.
- Без живых и платных внешних вызовов без разрешения владельца; если пункт макета противоречит ТЗ или требует решения владельца, исполнитель не выдумывает, а записывает вопрос в docs/decisions-pending.md и делает остальное.
