# SP-E3-07F — диагностика записанных сценариев

## Что проверено

Новый диагностический тест перебирает все 41 записи из `recorded-v2`, проверяет хеш каждого файла и для 39 диалоговых сценариев передаёт в изолированный `FirstInboundRuntime` первое непустое записанное сообщение клиента. Для каждого выбирается первая запись компонента `extractor`; оригинальный `RecordedGateway` проверяет её целостность и полное совпадение запроса. Сеть, почта и очередь подменены fake. Для 29 persona исходное вступление без сообщения клиента не воспроизводится: это проверка доступной первой реплики клиента, не replay исходного начала. Для `manual.no_repeat_filled_slot` передано исходное начальное состояние из сценария.

- 38 случаев: runtime вызвал записанный адаптер один раз, запрос отклонён как `Recorded request does not match`, результат runtime `unavailable`. Это все 29 `persona.*` и 9 случаев `manual.*` с клиентским ходом, кроме указанного ниже.
- `manual.no_repeat_filled_slot`: runtime вернул `unavailable` до вызова адаптера; причина пока не локализована. Проверка не устанавливает причину отказа и не подтверждает нарушение поведения исходного сценария.
- `manual.followup_20h`, `manual.followup_40h`: входящих клиентских ходов нет; это сценарии таймера, тест их классифицирует, но не воспроизводит планировщик.
- Runtime проверен отдельно на отказ viewer и попытку использовать диалог другой организации/бренда до вызова AI.

## Подтверждённые препятствия полному replay

1. Записанный запрос имеет `messages` и `options`, в которых находятся `component`, модель и параметры; runtime передаёт `AiRequest::toArray()` с моделью и параметрами на верхнем уровне и собственными данными prompt. Послабление хеша без сверки этапа, истории и входа не доказывает соответствия запроса. У persona предыдущая записанная реплика продавца отсутствует во входе runtime, поэтому даже перенос полей сам по себе недостаточен.
2. `app/Seller/Runtime/FirstInboundRuntime.php` начинает с клиентского сообщения; исторические persona содержат начальную реплику продавца без клиента. Для полного сравнения нужен согласованный путь начала диалога и воспроизведение истории.
3. `app/ProtectedOperations/SellerFollowup/FollowupCoordinator.php` и `FollowupFinalizer.php` возвращают фиксированную fake-реплику для последующих входящих сообщений, не вызывая записанный extractor/responder. Эти файлы вне scope SP-E3-07F. Сценарии таймера дополнительно проходят через `app/Seller/Followups/PrepareFollowups.php` и `FollowupSender.php`, тоже вне scope.
4. В `app/Ai/Gateway.php` получение сырых аргументов требует экземпляр `FakeDriver`, тогда как записанный драйвер реализует `Driver`; снятие проверки без согласованного безопасного адаптера ослабило бы существующую границу.

Ни один исходный полный сценарий не завершён, фактические различия итогового состояния не измерены. Успех теста означает только корректное обнаружение и классификацию текущих остановок, а не эквивалентность. Golden fixtures не менялись.
