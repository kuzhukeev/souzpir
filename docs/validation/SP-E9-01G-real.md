# SP-E9-01G — реальные экраны, промежуточная проверка

В изолированной PostgreSQL БД создана синтетическая организация, через UI включён продавец. На реальных маршрутах получены HTTP 200 и заголовки 15 экранов: D-4.1, D-4.3, D-4.5, D-4.6, D-4.8, D-4.9, D-4.10, D-4.11, D-3.1, D-3.3, D-3.5, D-2.3, D-10.1, D-10.4, D-5.1. Результат ещё не означает проверку заполненных состояний: новый бренд без черновика и данных. Скриншоты и подробный axe — `.local/screenshots/SP-E9-01G/`.

Axe WCAG 2 A/AA и 2.1 AA: на D-4.11 серьёзное `link-in-text-block` для ссылки «Создать черновик» на всех трёх ширинах; на остальных 14 пустых состояниях critical/serious не найдено. Ручной тест теперь завершится ошибкой при этом нарушении. Сравнение снимков с макетами и заполненные состояния ещё не завершены.

Через UI созданы черновик, группа «Доставка» и факт «Доставляем по России». Повторно открыты те же 15 маршрутов и карточка созданного факта D-4.4: все вернули 200, axe 0 critical/serious на 1440/1024/390, браузерный сценарий прошёл. Наполнение относится к базе знаний; клиенты, задачи, каталог и диалоги остаются пустыми. Снимки `populated-<экран>-<ширина>.png`, детали `populated-status.json`. Песочница без черновика и с черновиком — разные состояния: находка для пустой страницы выше сохраняется.
